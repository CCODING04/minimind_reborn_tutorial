全链路地图：一次请求的一生

M02 你已经和模型说上话了；这一课产出一张七站地图——从你输入一句话到 token 回来， 经过哪七站、每站对应 reborn 哪个文件。这张图贴在后续模块开头： M05–M09 解剖⑤站，M06 专攻 KV cache，M20 深潜整条推理栈。

前置：M02 时长：约 50 分钟 新概念：自回归解码 · 全链路分层 对照：inference/ 全目录 + models/ 总览

学完你能

  • 默画七站地图：每站的名字、职责与对应源码文件；
  • 解释自回归解码循环——为什么每步只喂一个新 token、为什么 decode 只解码生成段；
  • 说出推理栈四层（sampling → generator → chat → engine）的边界与"内核只认 token"的含义；
  • 跑一次七站巡游拿到七行证据，并预测 + 验证 temperature=0 的行为变化。

开篇地图：七站巡游

先全景后细节。一次请求依次经过七站，右边标了 reborn 里真正干活的文件：

你输入「你好」
↓
① tokenizer 编码assets/tokenizer + HF tokenizers 「你好，世界」→ [1968, 294, 1950]
↓
② chat 模板渲染inference/chat.py · render_chat 消息 → <|im_start|>user 你好<|im_end|>…
↓
③ engine 门面inference/engine.py · build / generate_tokens 权重加载 · dtype 回退 · 设备搬运
↓
④ generator 内核inference/generator.py · generate 预分配 KV cache · 增量喂入 · 停止三重
↓
⑤ model 前向models/model.py + attention / layers RoPE · GQA · SwiGLU 逐层（8 × Block）
↓
⑥ sampling 采样inference/sampling.py · 纯函数链 logits → 下一个 token id
↓
⑦ decode + 后处理tokenizer.decode + split_reasoning token → 文本（拆 <think> 块）
↓
模型输出「你好！有什么…」

实线框 = 处理站；④⑤⑥（左侧蓝条）组成自回归循环——每生成一个 token 转一圈；①②③只在请求开始跑一次，⑦收尾。

注意方向性：①②③只在请求开始时跑一次；④⑤⑥组成的循环每生成一个 token 转一圈，⑦收尾。 tokenizer 往返可以放心依赖——「你好，世界」→ [1968, 294, 1950]，decode 完全还原，词表 6400 [作者实测 · 2026-09-29 · 2×RTX 4090 · torch 2.14.0+cu130]。

地图⑤站里那一排缩写是模型内部构件的名字，第二篇会逐个拆解——RoPE（旋转位置编码，让模型知道词的先后）/ GQA（分组查询注意力，多头注意力的省显存版）/ SwiGLU（门控前馈网络）/ RMSNorm（归一化层），分别对应 M05–M08。本课不需要打开它们，只需知道"这些零件都住在⑤站的前向里"。

💡 概念卡：自回归解码（autoregressive decoding）

一句话：用自己已经生成的输出，当作下一步的输入。模型每次只预测下一个 token， 拼回序列尾部再预测下一个，直到触发停止。自回归严格串行：第 N 个 token 依赖前 N−1 个—— 这正是 KV cache（M06）存在的原因：历史算过的，不必每步重算。

逐站讲解

每站三样：职责一句话、精选代码、一个"停一下"观察点。

① tokenizer：把字变成 id

职责：文本 ↔ id 的双向翻译。模型眼里没有字，只有 0~6399 的整数。词表在 assets/tokenizer/， 特殊 token 常量在 constants.py:9-11：

constants.py:9-11 · 特殊 token（与官方 minimind 一致）python
PAD_TEXT = "<|endoftext|>"   # pad：凑批用的填充位
BOS_TEXT = "<|im_start|>"  # bos：序列开始
EOS_TEXT = "<|im_end|>"    # eos：对话结束——④站停止三重的靶子

停一下：「你好，世界」5 个字符变成 3 个 token（你好 / ， / 世界）—— token ≠ 字符也不等于词，是 BPE 学的片段（M10 专讲）。记住 294，⑥站它作为 top1 再次登场。

② chat 模板：把对话变成模型认识的格式

职责：把 messages 渲染成带特殊标记的文本，让模型知道"谁在说话、该谁说了"。 inference/chat.py 的 render_chat（chat.py:10）只调 tokenizer 自带模板：

chat.py:10-25 · 模板进 tokenizer_config.json（单一事实源）python
def render_chat(tokenizer, messages, *, tools=None, open_thinking=False,
                add_generation_prompt=True) -> str:
    """消息列表 → chat template 文本。"""
    return tokenizer.apply_chat_template(
        messages, tokenize=False,
        add_generation_prompt=add_generation_prompt,
        tools=tools, open_thinking=open_thinking,
    )

对 [{"role": "user", "content": "你好"}] 的真实渲染结果（§tour ②行同款）： '<|im_start|>user\n你好<|im_end|>\n<|im_start|>assistant\n<think>\n\n</think>\n\n' [作者实测 · 2026-09-29 · 2×RTX 4090 · torch 2.14.0+cu130]

停一下：结尾停在 <|im_start|>assistant\n 加空的 <think> 块—— 模型接手"该 assistant 说话了"的语境（模板 M10 拆）。本课只需确认：②站输出文本，下一步才编码成 id。

职责：读 checkpoint → 建模型 → 加载权重 → 精度回退 → 设备搬运，一次收拢。 inference/engine.py 的静态工厂 build（engine.py:43）一行拿到能用的引擎：

停一下：_resolve_dtype 是回退链——首选 bf16，CPU 不支持回退 fp32 并只警告一次 （engine.py:213-219）。无 CUDA 的机器上跑巡游，③行打出 dtype=torch.float32——不是 bug，是链在退。

④ generator 内核：自回归主循环

职责：只认 token id 的生成循环——预分配 KV cache、增量喂入、三重停止。 inference/generator.py 的 generate（generator.py:30）是全栈心脏：

generator.py:47-99 · 主循环精选（shape 注释）python
cache = KVCache(num_layers=model.config.num_hidden_layers,       # 8 层 → 第 0 维
                max_batch_size=batch,                            # 1
                max_seq_len=prompt_len + steps,                  # 4+6=10：容量=prompt+上限
                num_kv_heads=model.config.num_key_value_heads,   # 4（GQA 共享 KV 组）
                head_dim=model.config.head_dim,                  # 96
                dtype=next(model.parameters()).dtype, device=device)

for _ in range(steps):
    past_len = cache.cur_len
    feed = input_ids if past_len == 0 else input_ids[:, past_len:]
    # 增量喂入：第 1 步喂整段 prompt (1,4)（prefill，预填充），之后每步只喂 1 列 (1,1)
    logits = model(feed, attention_mask=attention_mask,
                   past_key_values=cache).logits[:, -1, :]   # (1, 6400)：只要最后一位
    ...
    input_ids = torch.cat([input_ids, next_token], dim=-1)  # (1, T) → (1, T+1)
    finished |= next_token.squeeze(-1).eq(eos_token_id)     # 只认"生成位"的 eos
    if bool(finished.all()):                                # 停止三重之 2：batch 全停才 break
        break

停止三重（generator.py:1-7 文件头，缺一不可）：token 级——eos 掩码要求"生成位 ∧ token ∈ 停止集合"，prompt 自带的 eos 不算；循环级——batch 全部序列结束才 break（支持长短不一）； 后处理级——解码后按 eos 截断残留（⑦站 _decode_truncated，engine.py:205）： 已结束序列在循环里被冻结为 eos 占位（generator.py:89），decode 前再切一刀。

停一下：对照实测 k.shape=(8, 1, 10, 4, 96) 反推五维——8 层、batch 1、 容量 10（prompt 4 + 上限 6）、4 组 KV 头、head_dim 96。容量循环前定死、零再分配， 新 token 只是往空位原地写入一列（kv_cache.py:44 的 copy_）——为何快过 torch.cat，测验 2 见。

⑤ model 前向：8 层 Transformer 的一次计算

职责：id 序列进、每个位置对 6400 词的打分（logits）出。 models/model.py：

model.py:106-119 · MiniMindModel.forward 精选python
cos, sin = (self.freqs_cos[cache_start : cache_start + seq_length],   # RoPE 预计算表只切片
            self.freqs_sin[cache_start : cache_start + seq_length])  #     不重算
hidden_states = self.dropout(self.embed_tokens(input_ids))   # (b, seq) → (b, seq, 768)
for layer in self.layers:                                    # 8 × MiniMindBlock
    hidden_states = layer(hidden_states, (cos, sin),
                          cache=past_key_values, cache_start=cache_start,
                          attention_mask=attention_mask)
if past_key_values is not None:
    past_key_values.advance(seq_length)                      # 前向结束才统一推 KV 游标
hidden_states = self.norm(hidden_states)                     # final RMSNorm → (b, seq, 768)
# ForCausalLM 再过 lm_head（model.py:160）：(b, seq, 768) → (b, seq, 6400)
input_ids (b, seq) ─► embed_tokens(6400→768) ─► 8 × Block ─► norm ─► lm_head(768→6400)
                                                                    └─ generator 只取 [. , -1, :] → (b, 6400)

Block 内部（model.py:40-48，pre-norm 残差 ×2；embed 权重与 lm_head 共享，model.py:144）：
x ──┬──────────────────────────┐
    │                          ▼
    └──► RMSNorm ─► Attention ─►(+)   x₁ = x + attn(norm(x))    # GQA · RoPE
x₁ ──┬──────────────────────────┐
     │                          ▼
     └──► RMSNorm ─► FFN(SwiGLU)─►(+)  x₂ = x₁ + ffn(norm(x₁))

停一下：weight tying——lm_head.weight 与 embed_tokens.weight 是同一块张量 （model.py:144），6400×768 省约 4.9M 参数（总 63.91M 的一部分，M09 记账）。 RoPE 频率表同样"预计算 + 切片视图"（model.py:106-107）——与 KV cache 同宗的模式。

⑥ sampling：从 6400 个候选里挑一个

职责：把一位 logits 变成一个 token id。 inference/sampling.py 是一串纯函数——每个 ≤10 行、张量进张量出、无副作用、可独立单测（sampling.py:1 即契约）：

sampling.py · 五连纯函数（顺序即契约）python
def apply_temperature(logits, temperature):        # ① logits / T：改分布形状
    if temperature <= 0: return logits               #    ≤0 语义是"贪心"，原样返回
    return logits / temperature

# apply_top_k：③ 前 k 大保留，其余 -inf；apply_top_p：④ 核采样，质量 ≤ p 的前缀

def sample_token(logits, gen, generator=None):      # ⑤ 单步采样入口 → (b, 1)
    logits = apply_temperature(logits, gen.temperature)
    logits = apply_top_k(logits, gen.top_k)
    logits = apply_top_p(logits, gen.top_p)
    if gen.temperature <= 0:
        return torch.argmax(logits, dim=-1, keepdim=True)  # 贪心：必选第一名
    probs = torch.softmax(logits, dim=-1)
    return torch.multinomial(probs, num_samples=1, generator=generator)  # 按概率抽签

完整顺序（sampling.py:3 注释即契约）：repetition_penalty（generator 施加）→ temperature → top_k → top_p → 采样。 repetition_penalty 需要"已见序列"这个随步变化的状态，由 generator 在调用前施加 （generator.py:83-84；默认 1.0 = 关闭）——它与 temperature 都是逐元素乘法、可交换先后。为什么顺序是契约：temperature 用除法 z_i / T 改变 logits 相对间距（分布变尖/变平），top_k/top_p 按改完之后的排序截断—— 若先截断再调温，被截的尾巴会以不同比例"回来"，旋钮互相污染。先定型、再截断（测验 3 见）。

停一下（进阶观察，已修复）：课程写作时（2026-09-29）并排读 generator.py 与 sampling.py 会发现 apply_temperature 在 generate 路径上被调两次（实测：max_new_tokens=2 时插桩计数 4 次； 等效缩放 logits/T²，T=0.85 时有效温度 ≈0.72，比旋钮读数更"尖"） [作者实测 · 2026-09-29 · 2×RTX 4090 · torch 2.14.0+cu130 · apply_temperature 换计数包装插桩]。 每个函数单独看都对——"纯函数都对、串起来的契约有缝隙"，M20 立案；2026-10-06 已修复 （commit 714f9c5：删 generator 的外层调用，sampling.py 契约同步改为"温度恰好施加一次"， 回归测试 test_temperature_applied_exactly_once_per_step 锁定）——现在的 generator.py 只施加重复惩罚， 温度归 sample_token 独家。你在当前代码里插桩会数到每步恰 1 次。

⑦ decode 与后处理：把 id 变回字

职责：生成段 id → 文本，顺带拆 <think>。engine 文本层只解码生成段 （engine.py:180-182）再走两道后处理：

engine.py:205-210 + chat.py:28-37 · 后处理两连python
new_tokens = out["sequences"][0, prompt_len:]   # 只取生成段 (n,)
text = self._decode_truncated(new_tokens)       # 停止三重之 3：按 eos 截断后再 decode
reasoning, content = split_reasoning(text)      # 拆 <think>...</think> 前缀

def split_reasoning(text):                      # chat.py:28
    if "<think>" in text and "</think>" in text:
        reasoning = text.split("<think>", 1)[1].split("</think>", 1)[0].strip()
        content = text.split("</think>", 1)[1].lstrip("\n")
        return reasoning, content
    return None, text                            # 无 think 标签：(None, 原文)

停一下：巡游里 pretrain 输出没有 think 标签，split_reasoning 返回 (None, 原文)——对"没有的东西"保持无操作；decode 用 skip_special_tokens=True， 模板标记不漏进答案。

分层思想：内核只认 token，文本层才认字

七站收拢成四层，每层只对上一层负责：

层文件语言边界
samplinginference/sampling.pylogits → 一个 id不知道模型与 tokenizer
generator（内核）inference/generator.pyid 序列 → id 序列只认 token：不 decode、不渲染
chat（文本/会话）inference/chat.pymessages → 文本模板、历史、eos 截断、think 拆分
engine（门面/工厂）inference/engine.py一句话 → 结构化结果权重/精度/设备脏活
📐 概念卡："内核只认 token，文本层才认字"

generator 的签名里只有 id 张量和结构化的 GenerationOutput（generator.py:21-26）—— 它完全不知道 tokenizer 的存在。收益双向：内核可用假 id 序列独立单测（不用加载权重）、 可被任何 tokenizer 复用；所有"字的语义"上浮到 chat/engine，改模板不用碰内核。 这是 llm-inference 规范的核心分层：数与字分离。 反例是把 decode 写进生成循环——每生成一个 token 碰一次字符串，流式、批处理、内核单测全被绑架。

🏭 工业对照：vLLM / SGLang 的内核-服务分层

工业推理引擎同款分层：vLLM 的 engine core（调度 + paged KV cache）与前端 API server 分离， SGLang 的 scheduler 与 tokenizer/frontend 分离——服务层管文本，内核层管 token。 reborn 把同一思想缩微到四个文件；RL 训练还给 rollout 留了可切换的 SGLang 后端 （training/rollout.py:120 的 SGLangRolloutEngine， create_rollout_engine 在 rollout.py:223 按配置切换）——内核只认 token， 换执行引擎对训练循环透明。M19 见。

⚠️ 坑卡：拿 pretrain 权重套 chat 模板对话

  • base 权重没在 chat 模板格式上训练过，<|im_start|>user 对它只是普通 token；它只会文本续写。
  • 两种都合法，但要配套：pretrain 权重用 pretrain_mode=True（bos + 裸文本，engine.py:166-167、chat.py:68）；要真对话换 full_sft_768.pth。实测（temperature=0 固定，排除采样随机性）：

pretrain_mode  → '，我有一个问题想问。你好，欢迎来到这里。请问有什么问题需要我的帮助吗？我最近'

动手巡游：七行证据

把脚本存到仓库外（如 /tmp/tour.py，临时文件不进 reborn 仓库），在 Reproduce/minimind_reborn/ 下运行。权重用 out/pretrain_768.pth （base 模型走 bos + 裸文本，见上面坑卡），七站各打印一行证据：

/tmp/tour.py · M03 巡游：一次请求的一生python
# M03 巡游：一次请求的一生——七站各打印一行证据（权重 out/pretrain_768.pth）
import torch
from torch.nn.functional import softmax
from minimind_reborn.configuration.schemas import GenerateConfig
from minimind_reborn.inference.chat import render_chat, split_reasoning
from minimind_reborn.inference.engine import MiniMindLLM
from minimind_reborn.inference.sampling import apply_temperature, apply_top_k, apply_top_p
from minimind_reborn.models.kv_cache import KVCache

llm = MiniMindLLM.build("pretrain")  # ③ engine 门面：权重→模型→dtype 回退→设备
ids = llm.tokenizer("你好，世界")["input_ids"]  # ①
print(f"① encode 「你好，世界」→ {ids} → decode 还原「{llm.tokenizer.decode(ids)}」 vocab={len(llm.tokenizer)}")
print(f"② render {render_chat(llm.tokenizer, [{'role': 'user', 'content': '你好'}])!r}")
print(f"③ engine device={llm.device} dtype={llm.dtype} 参数={sum(p.numel() for p in llm.model.parameters()) / 1e6:.2f}M")
inputs = llm.tokenizer(llm.tokenizer.bos_token + "大语言模型", return_tensors="pt").to(llm.device)  # (1, 4)
gen = GenerateConfig(temperature=0.85, top_k=50, top_p=0.95, max_new_tokens=6)
with torch.inference_mode():
    out = llm.generate_tokens(inputs["input_ids"], gen)  # ④ generator 内核
    c = llm.model.config
    cache = KVCache(num_layers=c.num_hidden_layers, max_batch_size=1,  # 复刻 generator.py 的分配参数
                    max_seq_len=4 + gen.max_new_tokens, num_kv_heads=c.num_key_value_heads,
                    head_dim=c.head_dim, dtype=llm.dtype, device=llm.device)
    print(f"④ generator·KV 预分配 k.shape={tuple(cache.k.shape)} 生成 {out['generated_ids'].shape[1]} tokens finish={out['finish_reasons'][0]}")
    logits = llm.model(**inputs).logits[:, -1, :]  # ⑤ 一次前向 → (1, 6400)
    print(f"⑤ forward logits.shape={tuple(logits.shape)}（hidden=768 × 8 层 → 每步只留最后一位）")
    t0 = softmax(logits[0], -1).topk(5)  # ⑥ 链前
    s = apply_top_p(apply_top_k(apply_temperature(logits, gen.temperature), gen.top_k), gen.top_p)  # 顺序契约
    fmt = lambda t: [f"{i}:{v:.3f}" for i, v in zip(t.indices.tolist(), t.values.tolist())]
    print(f"⑥ sample 链前 top5 {fmt(t0)}\n          链后 top5 {fmt(softmax(s[0], -1).topk(5))}（temperature→top_k→top_p 后重归一化）")
    text = llm.tokenizer.decode(out["sequences"][0, 4:].tolist(), skip_special_tokens=True)  # ⑦ 只解码生成段
    print(f"⑦ decode sequences[0, 4:] → {text!r} → split_reasoning={split_reasoning(text)[0]!r}")

检验一下

测验 1 · 为什么 decode 只解码 sequences[0, prompt_len:]，而不是整个序列？

提示：sequences 怎么拼出来的？回顾 generator.py:90 的 torch.cat。

答案：sequences = prompt + 生成段——generator 每步把新 token torch.cat 回输入（generator.py:90），返回完整序列；不切片就 decode 等于把提问复读一遍再接答案。生成段 eos 后的冻结占位残留由 _decode_truncated（停止三重之 3）解码前截掉。

答错回看：⑦ decode 与后处理 与 ④ generator 内核 的 cat 一行。

测验 2 · KV cache 预分配为什么省时间省显存？对比"每步 torch.cat 重建整段历史"。

本课只要直觉答案，深挖留给 M06（5 个专门测试）。

答案：torch.cat 每步新分配更大张量、拷贝全部历史——到第 N 步累计拷 O(N²/2) 份 KV，频繁分配还让显存碎片化。预分配一次到位后：写入是原地切片 copy_，读取是前缀视图（零拷贝，kv_cache.py:47-49），全程零再分配。直觉版：先买好整面书架，每来一本书插进去，而不是每来一本重抄全部。

答错回看：④ generator 内核 的 KVCache 构造注释与"停一下"。

测验 3 · 采样五连里，temperature 为什么必须放在 top_k / top_p 之前？

提示：top_k / top_p 都是排序后截断——对哪个分布排序？

答案：契约是"先改分布形状，再截断"。temperature 用除法 z_i / T 改变相对间距——分布变尖或变平；top_k/top_p 随后按改完之后的排序决定谁留下。反过来先截断再调温：softmax 重新分配概率，被截的尾巴以不同比例"回来"，候选集随 temperature 漂移——旋钮互相污染。先定型、再截断，旋钮才正交。

答错回看：⑥ sampling 的"为什么顺序是契约"段。

本课词汇

自回归解码 autoregressive decoding
用已生成输出作为下一步输入、一次一个 token 滚动生成：第 N 个依赖前 N−1 个。
token
模型眼里的最小文本单元：0~6399 的整数 id；由 BPE 词表双向翻译（M10 专讲）。
chat 模板 chat template
把 messages 渲染成带特殊标记文本的约定（谁在说话、该谁说），事实源在 tokenizer_config.json。
KV cache
缓存注意力历史 Key/Value 的预分配张量组，让每步只算新增 token（M06 专讲）。
logits
模型对每个词表项的未归一化打分，(b, vocab)；softmax 之后才是概率。
dtype 回退链
精度逐级降级：首选 bf16，不支持时回退并只警告一次（CPU → fp32）。
