DPO：偏好对齐

M16 的模型已经会"以助手身份说话"（🏁 里程碑 B），但它没有品味：同一个问题的两个回答， 在 SFT 的损失眼里一样"像标准答案"。本课给它装上那把尺子——DPO 偏好对齐， 而 M01 冒烟日志里那个 0.6931，将在公式推导的最后一步真相大白。

前置：M16（模型会说话了，本课教它挑更好的说法） 时长：约 80 分钟 新概念：偏好优化（Bradley-Terry→DPO）· 冻结参考模型 对照：training/dpo/{workflow,loss}.py · configs/dpo_64m.yaml · runs/dpo_full/

学完你能

  • 从"两个回答哪个更好"出发走完推导链：Bradley-Terry 偏好模型 → RLHF 目标 → DPO 闭式损失，说出每一步替换掉了什么；
  • 逐行读 dpo_loss 与 logits_to_log_probs，解释 β 的作用，以及"为什么是 log_prob 之差而不是 logit 之差"；
  • 说出参考模型"冻结三件套"（eval / requires_grad_(False) / no_grad）各防什么，以及没有参考模型时目标函数退化成什么；
  • 真跑三档学习率的 smoke_dpo 对照、读 64M 存档的偏好曲线，用数字解释 lr=4e-8 背后的"已经会说话，只调品味"；
  • 亲手触发两个退化案例（β=0、chosen=rejected），先按公式预测行为再实测验证。

会说话 ≠ 说得好：SFT 之后的瓶颈

M16 收官的复盘三问里有一条"还差什么"，答案是：模型不知道什么叫"更好"。SFT 的损失是 模仿——把标准答案的每个 token 概率推高（M12 的 loss mask 只对回答区间记账）。它带来两个后遗症： ① 背答案（sft_full 的 train 1.32 / val 1.96 分叉，M16）；② 无偏好—— 问"用一句话介绍北京"，一个啰嗦跑题的答案和一个精炼切题的答案，只要都"像训练集里的回答"， 损失就无从比较。模型缺的是一把比较两个回答的尺子。

尺子的原料是偏好数据：同一个 prompt 配两个回答——chosen（人更喜欢的）与 rejected（较差的），只标注"谁更好"，不写"好多少"。数据侧 M12 已经造好： DPODataset 每行产出 6 个张量（x/y/mask × chosen/rejected，预移位）， 且 chosen/rejected 共享同一次 think 抽签保证配对公平。本课讲训练侧怎么消费它们。 怎么用？历史上有两条路线：RLHF（reinforcement learning from human feedback， 基于人类反馈的强化学习——InstructGPT 的经典路线）走两步，DPO 一步到位： 

偏好数据 (prompt, chosen, rejected) 的两条消费路线

路线一 RLHF（重）                          路线二 DPO（轻，本课）
┌────────────────────────────┐            ┌────────────────────────────┐
│ ① 训一个奖励模型 r(x,y)                  │  一个损失函数直接训策略：    │
│    拟合"人觉得哪个好"                     │  -log σ(β·[(πc-πr)-(refc-refr)])│
│ ② 用强化学习(PPO)最大化 r               │  参考模型 π_ref 冻结在场     │
│    同时用分布距离 KL 拉住别跑偏           │  没有 reward model、没有 RL │
└────────────────────────────┘            └────────────────────────────┘
   两个模型 + RL 训练循环                       一个损失 + 一份冻结权重
   （reborn 里也有，M19 逛）                   数学上是路线一的闭式解（折叠深读）

本课两个新概念之一登场：偏好优化（preference optimization）——不再模仿标准答案， 而是直接优化"chosen 比 rejected 更受偏爱"这一判断。DPO（direct preference optimization， 直接偏好优化）是其中最轻的一条实现路线。先记住结论：DPO 的训练循环与 pretrain/SFT 共用同一台 Trainer（M13），差异仍然只是一个 compute_loss 闭包——只是这个闭包比前两棒长， 而且流程里多了一份冻结的参考模型（本课第二个新概念）。

🏭 工业对照：RLHF 与 DPO 的分野

InstructGPT（2022）确立了 RLHF 三部曲：SFT → 训奖励模型 → PPO 强化学习 （PPO：proximal policy optimization，一种主流的 RL 优化算法，M19 再见），效果拔群但工程重： 训练时要同时在场四个模型（策略、参考、奖励、价值）。DPO 论文（2023）证明这条弯路可以抄直： 偏好数据能直接写成策略的损失函数，奖励模型被"闭式地"消掉了。此后小模型圈几乎默认 DPO—— Zephyr 用它对齐 7B 模型，HuggingFace 的偏好对齐栈以它为默认。reborn 同样把 DPO 作为 唯一的偏好训练范式实现（PPO/GRPO 留在 training/ 里作 M19 的地图）。

📐 折叠深读：从 Bradley-Terry 到 DPO（可跳过，不影响主线）

主线只需要最终损失。但 M01 测验 2 埋的话("M17 推 DPO 公式时这个数字会再次出现")在这里兑现—— 四小步，每步只换一个变量。

第 1 步：偏好也是概率。"chosen 比 rejected 好"这个人类判断，最经典的刻度是 Bradley-Terry 模型：给每个回答打一个分数 r（奖励，reward），偏好概率定义为

$$ P(c \succ r) = \sigma(r_c - r_r), \qquad \sigma(x) = \frac{1}{1+e^{-x}} $$

σ 是 sigmoid（M08 在 SiLU 里见过：把任意实数压进 (0,1) 的 S 形函数）。分差越大， "更喜欢 chosen"的概率越接近 1；分差为 0 → 0.5，五五开。

第 2 步：RLHF 的目标。有了奖励，RLHF 用强化学习最大化它，但加一条缰绳—— 别离出发时的模型 π_ref 太远（否则语言能力被冲掉，M16 的灾难性遗忘在极端情况下的样子）：

$$ \max_\pi \; \mathbb{E}_{y \sim \pi}\left[ r(x,y) \right] - \lambda\, \mathrm{KL}\!\left(\pi \,\|\, \pi_{\mathrm{ref}}\right) $$

KL 散度（Kullback-Leibler divergence）衡量两个概率分布差多远，在这里是"新模型偏离参考模型的总量"， M19 讲 RL 时它会反复出现。这一步的问题：r 是另一个模型，目标里既有 RL 又有两个模型——重。

第 3 步：闭式解改写奖励。上面这个优化问题有解析最优解，变形后得到 $ \pi^*(y|x) \propto \pi_{\mathrm{ref}}(y|x)\, e^{r(x,y)/\beta} $。 两边取对数、移项，奖励被表示成了两个模型的对数概率比：

$$ r(x,y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\mathrm{ref}}(y|x)} + \text{const} $$

这一步是全部魔法：奖励模型 r 被消掉了——"偏离参考模型多远"本身就是奖励的等价表达。

第 4 步：代回 Bradley-Terry。把第 3 步的 r 代入第 1 步的偏好概率，再做最大似然 （让观测到的偏好判断概率最大），损失就是 DPO：

$$ \mathcal{L}_{\mathrm{DPO}} = -\mathbb{E}\left[ \log \sigma\Big( \beta \big[ (\pi_c - \pi_r) - (\mathrm{ref}_c - \mathrm{ref}_r) \big] \Big) \right] $$

其中 $\pi_c$ 是策略模型给 chosen 的（回答区间求和的）对数概率，$\pi_r$、$\mathrm{ref}_c$、 $\mathrm{ref}_r$ 同理。起点检验：训练开始时策略与参考是同一份权重，$\pi = \mathrm{ref}$， 方括号恒为 0，$\sigma(0) = 0.5$，损失 $= -\log 0.5 = \ln 2 = 0.6931$—— M01 测验 2 的答案在此兑现：那是"对哪个更好毫无偏好、纯猜硬币"的损失，所有偏好训练的零点。

精读 loss.py：31 行纯函数

DPO 的全部数学落在 training/dpo/loss.py——两个纯函数（输入输出只有张量， 不碰模型不碰配置，天然可单测）。全文 31 行：

src/minimind_reborn/training/dpo/loss.py · 全文 31 行python
"""DPO 损失（与官方 train_dpo.py 的实现语义一致，纯函数可单测）。"""

from __future__ import annotations

import torch
import torch.nn.functional as F


def logits_to_log_probs(logits: torch.Tensor, labels: torch.Tensor) -> torch.Tensor:
    """logits (b, seq, vocab), labels (b, seq) → 每 token 的 log prob (b, seq)。"""
    log_probs = F.log_softmax(logits, dim=2)
    return torch.gather(log_probs, dim=2, index=labels.unsqueeze(2)).squeeze(-1)


def dpo_loss(
    ref_log_probs: torch.Tensor,
    policy_log_probs: torch.Tensor,
    mask: torch.Tensor,
    beta: float,
) -> torch.Tensor:
    """sigmoid-DPO：-log σ(β·[(π_c-π_r) - (ref_c-ref_r)])，mask 限定回答区间求和。

    输入 (b, seq)，batch 前半 chosen 后半 rejected。
    """
    ref_log_probs = (ref_log_probs * mask).sum(dim=1)
    policy_log_probs = (policy_log_probs * mask).sum(dim=1)
    half = ref_log_probs.shape[0] // 2
    pi_logratios = policy_log_probs[:half] - policy_log_probs[half:]
    ref_logratios = ref_log_probs[:half] - ref_log_probs[half:]
    return -F.logsigmoid(beta * (pi_logratios - ref_logratios)).mean()

dpo_loss 从上到下四件事。① mask 加权求和（25–26 行）：M12 造的 0/1 mask 在这里被消费——只把回答区间的每 token 对数概率加起来，prompt 与填充位不记账 （这就是 M12 说的"加权求和"消费格式，与 SFT 的 -100 哨兵同源不同形）。 ② 对半切（27–29 行）：batch 的前一半是 chosen、后一半是 rejected（下一节讲怎么拼的）， 两行减法得到 $\pi_c - \pi_r$ 与 $\mathrm{ref}_c - \mathrm{ref}_r$，再相减—— 公式里的三重差分一行不差。③ logsigmoid（30 行）：$-\log\sigma(\cdot)$ 的数值稳定实现， 大负数输入时不会溢出。④ mean：对 batch 内所有对取平均。

一个值得驻留的细节：求和，不是平均。25–26 行把整个回答的 token 概率加总—— 这正是折叠深读里 $\log \pi(y|x)$ 的定义（整个回答序列的对数似然）。于是 $\pi_c - \pi_r$ 的量级随回答长度增长，几百 token 的回答轻松差出几十 nat—— 这也是 β 只有 0.15 的原因之一：把巨大的"长度 × 概率"刻度压回 sigmoid 的工作区间。

💡 直觉：β 是偏好差距的"敏感度旋钮"

β 乘在 margin（策略相对参考对 chosen/rejected 的偏好差）上，再喂给 sigmoid。β 大 → 小的偏好差也被放大成接近 1 的偏好概率，损失很快饱和、梯度趋零，模型被勒令"贴着参考模型微调"； β 小 → 需要很大的偏好差才令损失满意，模型被允许跑得更远。reborn 固定 0.15（官方同值）。 记住一个极端的反例：β=0 会发生什么？——坑卡见下文实测。

logits_to_log_probs：gather 的"对号入座"

模型 forward 吐出的是 logits——每个位置对全词表 6400 个候选的原始打分（M03/M09）。 DPO 需要的是"实际发生的那个 token拿到了多少概率"。三步：

logits_to_log_probs 逐行python
log_probs = F.log_softmax(logits, dim=2)   # (B, T, 6400)：先归一化成分布再取对数
idx = labels.unsqueeze(2)                  # (B, T, 1)：每个位置"正确答案"的词表下标
picked = torch.gather(log_probs, 2, idx)   # (B, T, 1)：去 6400 个数里精准领自己的那份
return picked.squeeze(-1)                  # (B, T)：每 token 的 log P(y_t | y_<t)

gather 是张量的"按索引取数"：在 dim=2（词表维）上，用 labels 里的下标 从 6400 个对数概率里各取一个。等价写法是 one-hot 向量（只有对应位是 1 的 0/1 向量） 与全词表做乘加，但 gather 只搬数不算乘，省算力。 log_softmax（先 softmax 归一化再取对数）保证 6400 个数加起来等于 1 的约束先被兑现—— 这引出一个高频问题：为什么不直接用 logit 之差？因为 logits 没有归一化：每个位置的 6400 个打分整体加一个常数，分布完全不变（softmax 平移不变），但"logit 之和"会任意漂移—— 它不是分布的性质。$\sum_t \log P(y_t)$ 才是模型真正分配给这个回答的概率质量， 折叠深读的推导（概率比 $\pi/\pi_{\mathrm{ref}}$）也只对归一化分布成立。

写稿时顺手踩了一个真实的小坑，值得替你踩一遍：直接拿 B=1（只有一条序列、无配对）调 dpo_loss，返回 nan——27 行 half = 1 // 2 = 0， 切片 [:0] 是空的，空张量取均值即 nan。上游 workflow 的拼批保证 batch 恒为偶数 （下一节），纯函数自己不设防；给它写单测时，batch 必须按"对"喂。

def run(cfg: RunConfig, *, device: str | None = None, local_rank: int = 0) -> Trainer:
    setup_logging(cfg.run_dir)
    tokenizer = load_tokenizer()
    model = build_model(cfg, tokenizer)

    ref_model = build_model(cfg, tokenizer)

    )

    ref_model.eval().requires_grad_(False).to(device or ("cuda" if torch.cuda.is_available() else "cpu"))
    load_inference_weights(model, init, strict=True)  # 策略模型同起点（Trainer 的 resume 在其后仍可接管）

    train_ds = build_preference_dataset(cfg, tokenizer)

策略模型（policy，正在被训练的模型——RL 词汇，M19 常用）与参考模型（reference） 从同一份权重出发：都严格加载 init_from（默认 full_sft，M14 的"严格起点"语义， 键集合必须完全相等）。然后是本课第二个新概念的实体——冻结，一行三件事，各防一种病：

三件套防什么
eval()切到推理行为。本模型 dropout=0 时作用有限，但它是"这个模型不参与训练"的声明位——任何带训练态的层（dropout/归一化更新）都被关掉
requires_grad_(False)参数不登记"需要梯度"。少了它，损失反传时会为参考模型构建整棵计算图（autograd 记录的求导路径，M13）并算出它的梯度——白算一份 63.91M 参数的反向
前向包 torch.no_grad()激活即算即释放。autograd（M13 讲过的自动求导机制）完全不记录中间量，省下参考侧整批激活显存

为什么必须有参考模型？把损失里的 ref 项删掉再看：$-\log\sigma(\beta(\pi_c - \pi_r))$ 仍是个合法的损失——"chosen 的概率比 rejected 高"。但它没有参照系：模型可以整体抬高 一切像"回答"的文本的概率来满足它，甚至把整份分布推向 chosen 的措辞—— 这就是普通的语言模型训练（甚至在训一个更窄的复读机），语言能力（M16 的 7 小时 pretrain 家底） 会在无约束的推高中流失。ref 项把目标改写成"相对你出发的地方，把概率质量从 rejected 挪向 chosen"——挪多远有记录（KL 缰绳，折叠深读第 2 步），语言能力因此被保护。 这也是 M01 测验 2 那句"参考模型（冻结作对照的它自己）"的全部含义。

后半段是 compute_loss 闭包——本范式对 Trainer 的全部接口：

src/minimind_reborn/training/dpo/workflow.py · compute_loss 段（34 行起）python
def compute_loss(batch, m):
    # chosen/rejected 拼成一个 batch 前后两半，一次前向
    x = torch.cat([batch["x_chosen"], batch["x_rejected"]], dim=0)
    y = torch.cat([batch["y_chosen"], batch["y_rejected"]], dim=0)
    mask = torch.cat([batch["mask_chosen"], batch["mask_rejected"]], dim=0)
    with torch.no_grad():
        ref_logp = logits_to_log_probs(ref_model(x).logits, y)
    out = m(x)
    policy_logp = logits_to_log_probs(out.logits, y)
    loss_val = dpo_loss(ref_logp, policy_logp, mask, beta=cfg.dpo.beta)
    loss = loss_val + out.aux_loss
    return loss, {"train/dpo_loss": loss_val.item(), "train/aux_loss": float(out.aux_loss)}

两个工程选择。① 拼批：chosen 与 rejected 序列等长（M12 按 max_length 填充）， 沿 batch 维 cat 成 (2B, T) 一次前向——两次小 kernel（GPU 上的函数调用）启动合并成一次， GPU 利用率更高，更重要的是保证两半走过完全相同的计算路径（对半切的前提，loss.py 27 行）。 ② 参考模型只算一次且全程 no_grad：它对 batch 的每个 epoch 都给出同样的 ref_logp （权重不动），训练中反复计算的只有它——这是"冻结"在性能上的代价与边界。 aux_loss 那行与 M16 相同（MoE 辅助损失，dense 恒 0）。

复测：判对率 50% → 59%

训练 loss 降了，模型真的更"会挑"了吗？直接量：拿存档里的两份 64M 权重—— DPO 前的 full_sft（也是参考）与 DPO 后的 dpo_768——在 64 个抽样对上算每对的 $z = \beta[(\pi_c-\pi_r) - (\mathrm{ref}_c-\mathrm{ref}_r)]$，统计 z>0（比参考更偏爱 chosen）的占比：

/tmp/m17_margin.py · 核心段（完整脚本 60 行，此为循环体）python
ref  = build("out/archive/era2/full_sft_768.pth")   # DPO 的参考 = 起点（存档 md5 fb1dcf…）
pol  = {"DPO 前": build("out/archive/era2/full_sft_768.pth"),
        "DPO 后": build("out/dpo_768.pth")}           # 存档 md5 521a5b…（=era2 快照）

@torch.no_grad()
def one_pass(m, b):
    x = torch.stack([b["x_chosen"], b["x_rejected"]]).cuda()   # (2, T) 拼批
    y = torch.stack([b["y_chosen"], b["y_rejected"]]).cuda()
    mask = torch.stack([b["mask_chosen"], b["mask_rejected"]]).cuda()
    return (logits_to_log_probs(m(x).logits, y) * mask).sum(dim=1)   # (2,)

for i in range(64):
    b = ds[i * 7 % len(ds)]
    ref_lp = one_pass(ref, b)                                    # (2,) 参考的偏好
    for k, m in pol.items():
        lp = one_pass(m, b)
        z = beta * ((lp[0] - lp[1]) - (ref_lp[0] - ref_lp[1]))   # 每对的判据量
        stats[k].append(z.item())

检验一下

测验 1 · 参考模型的"冻结三件套"缺一不可吗？各防什么病？

答案：三件套作用在不同层面，各有独立价值：eval() 关训练态（本实现 dropout=0 时冗余，但它是声明位）；requires_grad_(False) 防止反传时为参考模型构建计算图、白算一份 63.91M 参数的梯度——若漏掉它且优化器误收了这些参数，参考会跟着训练，"锚"漂移，margin 失去意义；前向包 no_grad() 让激活即算即释放，省参考侧整批激活显存（实测峰值因此只比单模型高 8%）。漏掉后两件不会报错——损失照常下降——但要么白算一整份反向（时间显存双亏），要么在优化器误收参考参数时真把"锚"拖着一起走，margin 失去意义。

答错回看：冻结参考模型：workflow 精读。

测验 2 · β 调大会怎样？调成 0 又会怎样？

答案：β 乘在 margin 上再进 sigmoid，是"偏好差距的敏感度"。调大：小的 margin 被放大成高置信偏好，损失很快饱和、梯度趋零（σ(-z)→0），模型被更强地勒令贴着参考模型——偏离更小、学得更保守；调小：允许更大的偏离，但也更容易把 SFT 学到的东西带偏。β=0 则是彻底空转：z 恒 0，损失恒 ln 2，梯度恒 0，权重一步不动（坑卡实测：lr=5e-4 也纹丝不动）。它不等于"退化成纯 LM 训练"——那需要删掉 ref 项而不是归零 β。

答错回看：β 的直觉卡 与 坑卡：β=0。

测验 3 · DPO 的 lr 为什么是 4e-8？用本课实测的数字说明大 lr 的后果

答案：三棒任务不同：pretrain 从零学说话（5e-4），SFT 精修当助手（1e-5），DPO 只在已会说话的权重上微调偏好排序——大步长会震掉语言能力（灾难性遗忘），所以再降 250 倍。实测刻度（smoke_dpo 40 步）：4e-8 时 loss 钉在 0.6931（tiny 上步长太小，但也绝不伤模型）；4e-5（×1000）时 loss 多次爬回 ln 2 之上（0.82/0.76 尖峰）；5e-4（×12500，smoke 默认继承值）时 0.43～3.53 狂震——margin 正负乱跳，偏好被学成噪声。官方注释"≤5e-8 防遗忘"就是这个安全边界的经验表达。

答错回看：实测：三档学习率 与 dpo_64m.yaml。

测验 4 · 为什么 DPO 用 log_prob 之差，而不是直接用 logit 之差？

答案：两个理由。① 分布性质：logits 是未归一化的打分，每个位置的 6400 个打分整体加常数，softmax 分布完全不变，但"logit 之和"会任意漂移——它不是模型分配给回答的概率；$\sum_t \log P(y_t)$（log_softmax 后对实际 token 求和）才是。② 推导要求：DPO 的损失来自"奖励 = β·log(π/π_ref)"的改写（折叠深读第 3 步），概率比只对归一化分布有定义。logits_to_log_probs 里那行 log_softmax 就是把打分兑换成概率的关卡，gather 负责从 6400 个候选里取出实际发生的那个 token 的份额。

答错回看：logits_to_log_probs：gather 的"对号入座"。

观察结果与解释（先动手再看）

loss 精确等于 ln(2)，梯度精确等于 0（不是近似 0——逐 bit 为 0）。机制：DPO 的 输入是"同一个数在两处的差"——$\pi_c - \pi_r$ 对同一条序列恒为 0，ref 侧同理，z 恒 0； 更深一层，chosen 与 rejected 共享同一份计算图，梯度经"正的一路"与"负的一路"完全对消。 这也解释了第 ③ 问：策略=参考（起点）只是让 ref 项也为 0，与本题无冲突—— 两个 0 叠加还是 0。对照实验给出边界：只要 rejected 有一点更差（末 token 低 0.5 nat）， loss 立即跌破 ln 2 且梯度非零。 工程含义：DPO 从"没有差别"的数据里学不到任何东西且不报错——所以 M12 的 "配对公平"（chosen/rejected 共享 think 抽签）才重要：它防的是反面（格式差异凭空制造 假的 margin），而本题是正面（差异为零则学习为零）。偏好数据的全部价值都压缩在 "两边的差"里。

本课词汇

偏好优化 preference optimization
第三棒训练范式：不再模仿标准答案（SFT），而是直接优化"chosen 比 rejected 更受偏爱"的判断。数据形态是同一 prompt 的两个回答（M12 的 DPODataset），损失开口于 ln 2=0.6931——零偏好零点。
DPO direct preference optimization
偏好优化的最轻路线（2023）：把 RLHF 的"奖励模型+强化学习"闭式地消成一个损失 $-\log\sigma(\beta[(\pi_c-\pi_r)-(\mathrm{ref}_c-\mathrm{ref}_r)])$，与 pretrain/SFT 共用同一台 Trainer。工业界小模型对齐的默认选择（Zephyr 等）。
Bradley-Terry 模型 preference model
把"哪个更好"写成概率：$P(c\succ r)=\sigma(r_c-r_r)$。偏好训练的第一块数学地基——分差过 sigmoid 变成偏好概率，分差为零即五五开。
参考模型 reference model
与策略同起点、全程冻结的"锚"（eval + requires_grad_(False) + no_grad 三件套）。它提供"从出发点挪了多远"的坐标；没有它，"推高 chosen"退化成无约束的普通 LM 训练，语言能力流失。
策略模型 policy model
正在被训练的那个模型（RL 词汇，M19 常用）。DPO 里它与参考模型从同一份权重出发，唯一的差别是它吃梯度。
margin（隐式奖励） implicit reward
每对样本的判据量 $z=\beta[(\pi_c-\pi_r)-(\mathrm{ref}_c-\mathrm{ref}_r)]$：策略相对参考"多偏爱了 chosen 多少"。z>0 即方向正确；复测 64M 存档的 z>0 占比 50%→59.4% 是偏好被拨正的直接证据。
β 偏好敏感度
margin 的放大器（reborn 固定 0.15）：大 β 勒令贴参考（sigmoid 早饱和、梯度趋零），小 β 允许大偏离，β=0 彻底空转（梯度恒 0，不报错）。它与"回答区间求和"的量级（几十 nat）共同决定了这个看似很小的值。
拼批 concatenated batch
chosen 与 rejected 沿 batch 维 cat 成 (2B, T) 一次前向的技巧：省一半 kernel 启动，且保证两半走过完全相同的计算路径——dpo_loss 按"前半 chosen 后半 rejected"对半切的前提。
logsigmoid 数值稳定实现
$-\log\sigma(z)$ 的稳定计算（loss.py 用 F.logsigmoid）。margin 大负数时朴素写法会溢出；其梯度 $-\sigma(-z)$ 在 z 极负时≈1、极正时≈0——DPO 的梯度尺度与交叉熵不可直接比较。
