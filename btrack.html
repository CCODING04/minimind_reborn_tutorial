B 轨 · 自写挑战总纲

A 轨教你怎么读，B 轨考你怎么写：走完一个模块后，不看源码，凭讲解把那个组件 自己写出来，再与 reborn 逐张量对拍。八个任务，一条终点 🏁D——用自己的手， 让官方权重在你的代码里说出第一句话。

定位：附录页 · A 轨主线不变 任务数：8 个 · 每个约 20-60 分钟 终点：🏁D 自己的模型说话 加入时机：读到 M05 即可开始（BT1）

B 轨宣言

这门课有两条轨道，不是两个阵营： A 轨（跟读主线）不变——22 个模块、绿灯验收、数字溯源，一门都不改、一课都不少； B 轨（自写挑战）是叠加项——每个挑战对应一个已读模块，规则只有一句话：

📐 B 轨规则：先自己写、再与 reborn 对拍

读完某模块 → 合上源码，只凭页内讲解与自己的笔记，把该组件写出来 → 用统一的对拍脚本把你的实现与 reborn 的实现喂同一输入 → torch.testing.assert_close 全绿，任务完成。 reborn 在 B 轨里从"教材"升格为"对拍答案"——它仍然是你最终要对齐的那份真实工程代码， 这不违背课程宪法（跟读真实代码、绿灯验收、数字溯源）：B 轨只是把"读懂它"升级成"默写出与它逐值等价的它"。

为什么值得：A 轨的验收证明你读懂了，B 轨的对拍证明你写得出—— 两者的差距就是"看会了"与"学会了"的差距。默写会失败在你想不到的地方（dtype、边界、就地改写）， 而每一处失败都是 A 轨读漏的细节。

通用对拍脚本模板

八个任务共用同一个对拍骨架，五步纪律：固定 seed → 同一输入 → 双实现前向 → assert_close → 打印 PASS。以 BT1 的 RMSNorm 为例（把两个 import 换成当次任务的组件即可复用全程）：

对拍模板 · 每个任务把"裁判"与"选手"换成本次的组件python
import torch
from minimind_reborn.models.layers import RMSNorm    # 裁判：reborn 参考实现
from my_model.layers import RMSNorm as MyRMSNorm     # 选手：你自己的实现

torch.manual_seed(42)              # ① 固定 seed：两边吃同一份随机性
x = torch.randn(3, 7, 32)          # ② 同一输入（batch/seq 用质数，学 conftest 防 shape 硬编码）

ref = RMSNorm(32)(x)               # ③ 同输入分别前向
mine = MyRMSNorm(32)(x)

torch.testing.assert_close(mine, ref, rtol=1e-5, atol=1e-6)  # ④ 逐元素对拍
print("PASS")                      # ⑤ 绿灯——唯一的成功输出
💡 三条对拍礼仪

容差写死并保留——rtol/atol 是任务的一部分，改大容差换 PASS 是自欺； 输入要刁钻——照抄 conftest 的癖好：batch 用质数 3、seq 用 7、维度用 32，专打抄形状的写法； PASS 之外的一切输出都算线索——assert_close 的失败信息会点名第一处不匹配的位置与量级， 它就是你的下一步路标。

求助梯度（四层，只升不跳）

卡住是 B 轨的常态——按层级求助，每层停留够久再升下一层：

层级动作允许看到什么
① 重读回对应模块的 A 轨小节再读一遍——任务说明书就写在那里全部讲解、图示与源码讲解（重读不扣分）
② 提示展开该任务的提示折叠块（在各模块页的挑战块内）一句话方向提示，不含代码
③ 签名打开 reborn 对应函数，只看签名与 docstring，不看函数体——看完关掉再写参数名、类型、默认值、返回形状
④ 规格跑该任务的对拍测试文件，读测试怎么使用这个组件——测试即行为规格输入构造方式与断言的不变量（仍不许抄实现）

四层用尽仍未通过：回 A 轨把整个模块重读一遍再战——那不叫失败，叫发现了一个读漏的盲区。

🏁D 终点定义

🏁
里程碑 D · 自己的模型说话
与 🏁A 同一验收口径，但实现是你自己的

用 B 轨八件套中的四件——M05（RMSNorm 与 RoPE）、M07（Attention）、 M08（FFN）、M09（组装）——拼出一个最小 CausalLM， 然后让它开口：

  • ① 四件套先各自过关：BT1 / BT3 / BT4 / BT5 的对拍脚本全部 PASS——地基不牢的终点站没有意义；
  • ② 官方权重 strict 互通：你的模型以 strict=True 加载 out/official/pretrain_768.pth——无缺失 key、无多余 key，参数量 63.91M（与 🏁A 的验收口径完全一致）；
  • ③ 贪心生成本课程的第一句话：temperature=0 逐 token 贪心解码，把你手写的模型生成的第一句话记下来——它就是你 B 轨的毕业证书；
  • ④ 口径声明：与 🏁A 的差别只有一个——实现是谁写的。验收一样硬：都是可判定的绿灯，不是"感觉会了"。

与 M22 毕业实验的关系

走完 B 轨的人，毕业实验（M22）相当于直接锁定"复现对比"题： 你的实现与 reborn 的对拍数据（哪里逐值一致、哪里有残差、什么边缘输入下分叉）就是现成的自变量与因变量， 不必再另找选题——按 M22 的四步模板（假设 / 设计 / 数据 / 结论）把"两套实现的差异及其来源"写成一份有数据支撑的报告即可。 对 A 轨同学这是一道要现攒数据的题，对 B 轨完成者它已经躺在你的对拍日志里。
