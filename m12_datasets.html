🛑 红线：loss mask 是"全系统最脆的耦合"

源码注释原话："这是全系统最脆的耦合（依赖模板恰好产出该格式），tests/test_data/test_loss_mask.py 用真实 tokenizer 逐 token 断言锁定"（loss_mask.py docstring 与 constants.py 注释双处声明）。 脆在哪：它靠模式匹配在渲染产物里找 "<|im_start|>assistant\n" 开头、"<|im_end|>\n" 收口的区间—— 模板哪怕改一个字符（M10 坑卡实测过：多一个空格，锚点序列就再也对不上），监督区间会静默变空，训练照跑、loss 照降， 只是模型什么都没学。所以红线是：改模板或改锚点常量前，先跑 test_loss_mask.py 的 7 个测试； 过了这关，数据还要重造（渲染产物全变）。本课的第一件事就是把这个"脆耦合"拆开看懂。

loss mask：只在 assistant 说话的地方算账

SFT（supervised fine-tuning，监督微调——用问答语料教预训练基座学会"以助手身份对话"，M02 对照表里 full_sft 那一行）的训练目标很朴素：给定对话前文，模型要学会续写 assistant 的回答。但一条渲染后的 样本里混着四种东西——用户的话、模板零件（<|im_start|> 之类）、assistant 的回答、凑批填充—— 其中只有第三种是"该学着重现的"：教模型背出"用户接下来会问什么"毫无意义，还会稀释梯度。

💡 概念卡：loss mask（损失掩码）

与 input_ids 等长的一张"着色表"：该学的位置亮色（label = 原 token id，照常算交叉熵），不该学的位置灰色（label = -100， 损失直接跳过）。-100 是 PyTorch 交叉熵的 ignore_index 约定（M09 讲过"这一格不算账"）——必须取词表外的值， 因为 0~6399 每个数都是合法 token id（0 号就是 <|endoftext|>，拿 0 当掩码等于"在每个填充位学习预测 pad"）。 M09 见过它的第一处来源（凑批填充位），本课补上第二处也是主要来源：非回答区间。

两个容易被忽略的细节，都体现在图上：锚点本身是灰的——<|im_start|>assistant\n 这 5 个 token 是"递话头"的模板件， 模型不需要"学会主动说这句话"；收尾的 <|im_end|>\n 是亮的——模型必须学会在该停的地方发出 eos（M03 ④站生成停止的靶子）， 不学它，模型就会刹不住车。think 块也在监督区内：样本带 reasoning_content 时（M10 见过渲染格式），"怎么想"和"怎么答"一起学。

从"着色表"到代码只有一步：先找区间（哪些 token 亮），再刷颜色（区间外填 -100）。这两步正是 loss_mask.py 的 81 行全部内容——找区间的 scan_response_spans（下一节填空主角）与刷颜色的两个孪生函数：

src/minimind_reborn/data/loss_mask.py · 刷颜色的两个孪生函数（全文）python
def build_labels(input_ids, spans, ignore_index: int = -100) -> list[int]:
    """区间内保留原 token id，区间外填 ignore_index。"""     # SFT 用：-100 哨兵
    labels = [ignore_index] * len(input_ids)                 # 先全灰
    for start, stop in spans:
        for j in range(start, stop):
            labels[j] = input_ids[j]                         # 区间内刷亮
    return labels

def build_mask(input_ids, spans) -> list[int]:
    """区间内 1，区间外 0（DPO 用）。"""                      # DPO 用：0/1 权重
    mask = [0] * len(input_ids)
    for start, stop in spans:
        for j in range(start, stop):
            mask[j] = 1
    return mask

为什么要两个版本？SFT 的损失是 CrossEntropyLoss(ignore_index=-100)（M09），认 -100 哨兵； DPO 的损失要拿每个 token 的对数概率加权求和（M17 详讲），需要的是 0/1 权重而不是哨兵——同一个"着色"语义，两种消费格式。 而锚点序列本身（prefix = [1, 1388, 570, 811, 234]、suffix = [2, 234]，M10 实测过）由 pattern_ids(tokenizer) 单处定义——encode 一次、全程复用，不许各处自己算。

SFTDataset 精读：一行 jsonl 的七步旅程

扫描器在手，现在把它装回完整流水线。SFTDataset 继承 M11 的 JsonlIndexedDataset （字节偏移索引基类：load_line(i) 一次 seek+read 取出第 i 行），自己只做"行 → 样本"的翻译。 取一个样本的完整代码只有这几行：

src/minimind_reborn/data/datasets.py · SFTDataset.encode（行级编码统一入口）python
def encode(self, index: int) -> dict[str, torch.Tensor]:
    """行级编码（IndexListView / __getitem__ 的统一入口）。"""
    sample = self.load_line(index)                      # ① O(1) 取行（M11 的字节偏移索引）
    conversations = pre_processing_chat(sample["conversations"], self.add_system_ratio)  # ② 增强A
    out = encode_sft_sample(                            # ③~⑦ 主流程抽成模块级函数
        self.tokenizer, self.prefix_ids, self.suffix_ids, conversations, self.max_length
    )
    return {
        "input_ids": torch.tensor(out["input_ids"], dtype=torch.long),
        "labels": torch.tensor(out["labels"], dtype=torch.long),
    }

两个运行时增强：每个 epoch 重新抽签

②与③里各藏一次概率抽签，都发生在每次取样本时（不是预处理一次定死）——同一个样本，每个 epoch（全数据过一遍） 见到的形态都不同。这就是"运行时增强"：不加一行数据，白拿训练分布的多样性：

src/minimind_reborn/data/datasets.py · 两个增强函数（全文）python
def pre_processing_chat(conversations, add_system_ratio: float = 0.2) -> list[dict]:
    """首条非 system 时按概率插入；工具调用数据完整保留不处理。"""
    if any(conv.get("tools") for conv in conversations):
        return conversations
    if conversations[0].get("role") != "system" and random.random() < add_system_ratio:
        return [{"role": "system", "content": random.choice(SYSTEM_PROMPTS)}] + conversations
    return conversations                                    # 增强A：10 条中英混合 system 池随机插

def post_processing_chat(prompt_content, empty_think_ratio=0.2, remove_empty_think=None):
    """按概率移除空思考标签（保留 20% 样例带空 think 格式，让模型两种都会）。

    remove_empty_think 显式给值时跳过随机——DPO 用它保证 chosen/rejected 配对公平。
    """
    if EMPTY_THINK in prompt_content:                       # "<think>\n\n</think>\n\n"
        if remove_empty_think is None:
            remove_empty_think = random.random() > empty_think_ratio   # 增强B：80% 移除
        if remove_empty_think:
            prompt_content = prompt_content.replace(EMPTY_THINK, "")
    return prompt_content

增强 A（system 注入，0.2）：语料大多没有 system 消息，但真实用户会设人设——按 20% 概率从 10 条 中英混合池里随机插一条。学到的不是某条人设，而是"见到 system 段要遵循"这件事本身。 增强 B（空 think 移除，0.8）：模板给每轮 assistant 都渲染空 think 块（M10 实验见过），80% 的样本把它删掉、 20% 保留——模型对"带空块"与"不带"两种格式都要会答，因为推理侧两种都会遇到（open_thinking 开关，M20）。 两个增强的影响可以直接量出来：语料第一条（6 个空 think 块）保留空块 549 token，移除后 513——差 36 = 6 块 × 6 token。

C1 轮次边界截断：二分丢整轮，保尾不保头

修复思路一句话：与其在 token 层面拦腰切，不如在轮次层面丢整轮。超窗时从最旧的"一问一答"成对丢弃（system 恒留）， 装得下为止；只剩最后一轮还超，就左截那轮 user 的内容（保尾部，可截到空）——assistant 回复永不在这里截。 "丢 k 对轮"的单调性天然适合二分（丢得越多越短）：

def __getitem__(self, index: int) -> dict[str, torch.Tensor]:
    pos = index % len(self._indices)
    item = self._base.encode(self._indices[pos])
    if not self._filter_zero_loss:
        return item                               # 直接索引不过滤（口径：过滤只在训练视图）
    probes = 0
    while not bool((item["labels"] != -100).any()):   # 全 -100 = 零损失样本
        self.remap_events += 1                     # 触发次数记入数据卡（D5 可观测）
        pos = (pos + 1) % len(self._indices)       # 确定性前向重映射：不是随机跳
        item = self._base.encode(self._indices[pos])
        probes += 1
        if probes >= len(self._indices):
            raise ValueError("视图内全部样本均为零损失（无任何完整 assistant 区间）")
    return item

两个讲究：确定性——同一视图同一位置恒定映射到同一目标，双卡 DDP（分布式数据并行，M15 详讲）的两个进程才会看到 一致的数据流，随机跳会导致两卡各喂各的；计数——重映射次数进 data_card()（数据卡：把数据的指纹、 剔除量、分布统计写进运行配置快照，供事后审计，存档 D5 项）。视图长度不变（len 恒 2，只是位置 0 实际吐出位置 1 的样本）， test_sft_dataset_filters_zero_loss_with_remap 把这条口径连同"直接索引不过滤"一起锁定。

PretrainDataset：没有 loss mask 的世界

src/minimind_reborn/data/datasets.py · PretrainDataset.encode（全文）python
def encode(self, index: int) -> dict[str, torch.Tensor]:
    sample = self.load_line(index)
    text = str(sample["text"])
    tokens = self.tokenizer(
        text, add_special_tokens=False, max_length=self.max_length - 2, truncation=True
    ).input_ids                                    # -2：给 bos/eos 留位（截断不吞哨兵）
    tokens = [self.tokenizer.bos_token_id] + tokens + [self.tokenizer.eos_token_id]
    input_ids = tokens + [self.tokenizer.pad_token_id] * (self.max_length - len(tokens))
    input_ids = torch.tensor(input_ids, dtype=torch.long)
    labels = input_ids.clone()
    labels[input_ids == self.tokenizer.pad_token_id] = -100   # 唯一的 -100：填充位
    return {"input_ids": input_ids, "labels": labels}

为什么它不需要区间扫描：预训练是纯语言建模——整篇文档处处都是"该学的正文"，每个位置的"下一词预测"都是 有效监督信号，没有"别人说的话"要排除。样本形态是 bos + 正文 + eos 三明治（bos/eos 的职责见 M10）， labels 与 input_ids 逐位相同，唯一的 -100 是填充位。真跑一条短文档（64 窗口）：

DPODataset：一对样本，共享一次抽签

DPO（direct preference optimization，直接偏好优化，M17 推导）的样本是"同一 prompt 的两个回答"： chosen（人更喜欢的）与 rejected（较差的）。数据集要为两边各造一份 token 序列与 0/1 mask（build_mask 那位孪生兄弟）， 关键在抽签的归属：

src/minimind_reborn/data/datasets.py · DPODataset.__getitem__（节选）python
def __getitem__(self, index: int) -> dict[str, torch.Tensor]:
    sample = self.load_line(index)
    remove_empty_think = random.random() > self.empty_think_ratio  # 每行抽一次签
    chosen_ids, chosen_mask = self._encode_side(sample["chosen"], remove_empty_think)
    rejected_ids, rejected_mask = self._encode_side(sample["rejected"], remove_empty_think)
    # 同一个签喂两边——配对公平：两序列的差异只剩"回答内容"一个变量
    return {
        "x_chosen": torch.tensor(chosen_ids[:-1]),      # x 去尾、y 去头：移位在数据集里就做完
        "y_chosen": torch.tensor(chosen_ids[1:]),
        "mask_chosen": torch.tensor(chosen_mask[1:]),
        "x_rejected": torch.tensor(rejected_ids[:-1]),
        "y_rejected": torch.tensor(rejected_ids[1:]),
        "mask_rejected": torch.tensor(rejected_mask[1:]),
    }

配对公平是本类的灵魂：DPO 损失比较的是两条序列的对数概率差——若 chosen 恰好抽到"带空 think"、 rejected 抽到"不带"，两边的格式差异（36 token 的模板件）就会混进偏好信号，模型可能学到"带 think 的回答更好"这种假规律。 把同一行的一次抽签同时喂给两边，格式变量被钉死，剩下的差异才可归因为"内容好坏"。真跑验证：

⚠️ 坑卡：为什么必须逐 token 匹配——字符下标不是 token 下标
  • 症状：自己写数据管线时最顺手的做法是 text.find("<|im_start|>assistant\n") 拿字符下标当区间边界， 或者肉眼数 token（"锚点 3 个 token：im_start、assistant、换行"）。产物往往看起来能跑： loss 正常下降、生成正常——直到发现监督区间整体平移了几十个 token，模型一直在学错位的段落。
  • token ≠ 字符，两把尺子不可互译。真跑语料第一条：第一个 assistant 回答的起点，字符下标是 68、token 下标是 25——68 个字符只折合 25 个 token（中文 2 字 1 token、'assistant' 一个词 3 个 token，M10 实测）。 把 68 直接当 token 下标用，"区间起点"已经越过第一个回答的结尾（真实区间是 [25,50)）——切掉的监督 token 不是 18 个而是整段。 手数同理必错：'assistant' 在这把 6400 词表下是 ass·ist·ant 三瓣。另一个隐藏失败：字符串 find 找不到后缀返回 -1 后怎么处理？旧实现的兜底"监督到结尾"正是 C2 的 0.82 残段来源——残段语义在字符串层面根本没法定义。
  • 逐 token 模式匹配（scan_response_spans + pattern_ids 单处定义），外加测试锁定。作者实测过一个扎心细节： 在前 300 行真实数据上，"字符串 find + 重新分词前缀换算"的朴素实现与逐 token 扫描恰好零失配—— 不是因为它可靠，而是因为锚点恰是特殊 token（强制切分对齐）。"恰好对"意味着没有任何东西保证它对： 模板一改（哪怕只动一个空格）、或数据里混入锚点字面量，它就静默错位。脆的东西要用测试钉住，而不是赌它一直对。

检验一下

测验 1 · 掩码为什么用 -100，用 0 不行吗？

答案：不行。0 是合法 token id（词表 0 号就是 <|endoftext|>，M10 的 pad）——拿 0 当掩码，交叉熵会把它当成"该位置的正确答案"认真计算，等于在每个掩码位学习预测一个真实存在的 token。-100 是 PyTorch CrossEntropyLoss(ignore_index=-100) 的约定哨兵：词表只有 0~6399，-100 永远不可能与任何真实标签撞车，损失函数直接跳过。M09 说过的"这一格不算账"，兑现处正是本课的 build_labels。

答错回看：loss mask 概念卡。

测验 2 · C1 轮次截断为什么"保尾不保头"？丢 system 行不行？

答案：保尾：一条多轮会话里最完整的"接着聊"语境在末轮，丢末轮等于丢掉最新鲜的问答对；旧轮只承担上下文职责，且信息常被后文复述，丢得起。system 恒留（_fit_turns 先把 system 摘进 head 再丢轮）：人设指令对每一轮的约束都有效，丢了它，末轮回答可能"换了个人"。还有一层：这套"丢最旧轮、system 恒留、仍超则左截末轮 user 保尾部"与推理侧 ChatSession 滑动窗口同构——训练与推理用同一种截断口径，模型不会认生。

答错回看：C1 轮次边界截断。

测验 3 · DPO 为什么 chosen/rejected 必须共享同一次 remove_empty_think 抽签？

答案：DPO 损失比较的是两条序列的对数概率差（M17 推导）。若两边独立抽签，可能出现 chosen 带空 think、rejected 不带——36 token 的格式差异混进偏好信号，模型可能学出"带 think 的回答更好"的假规律。每行抽一次签、同一个布尔值喂两边（_encode_side(…, remove_empty_think)），格式变量被钉死，剩下的差异才可归因为内容好坏。实测 30 次抽样 30/30 同进退。这正是"控制变量"在数据管线里的形态。

答错回看：DPODataset：一对样本，共享一次抽签。

测验 4 · PretrainDataset 为什么不做区间扫描，SFT 为什么必须做？

答案：取决于样本里有没有"不该学的部分"。预训练是纯语言建模：整篇文档处处是有效监督信号（每个位置都有"下一词"要学），labels 与 input_ids 逐位相同，唯一要灰掉的是凑批填充位。SFT 样本里混着四种东西——用户的话、模板件、assistant 回答、填充——前两种和最后一种不该学（用户的话不是模型要重现的内容；模板件是"递话头"的固定协议），所以必须先用锚点扫描划出回答区间再着色。一句话：loss mask 的复杂度与"样本里不该学的内容占比"成正比。

答错回看：PretrainDataset：没有 loss mask 的世界 与 loss mask 概念。

提示 1 · 方向

两指针扫描：外层从头找 prefix 的落点，找到后从 prefix 尾部起向后找 suffix 的落点—— 找到则入区间并跳到 suffix 之后继续（防重叠匹配）；扫到头都没找到 suffix 就是残段，直接停。

提示 2 · 表达式级

匹配判定一行：seq[i : i + len(pattern)] == pattern（Python 切片越界自动截断，天然安全）； 区间入表：spans.append((i + len(prefix_ids), end + len(suffix_ids)))。

对拍：脚本模板见 B 轨总纲——合成小序列（含多轮、含截断残段）逐 case 对照 from minimind_reborn.data.loss_mask import find_response_spans。裁判测试 tests/test_data/test_loss_mask.py（先跑一遍看参考行为： uv run pytest tests/test_data/test_loss_mask.py -q——单轮/多轮/残段三组用例用真实 tokenizer 逐 token 断言，正是你要对齐的三种形态）。

本课词汇

loss mask 损失掩码
与 input_ids 等长的着色表：该学的位置 label=原 token id（进交叉熵），不该学的 label=-100（跳过）。SFT 只在 assistant 回答区间算损失；两个孪生产出 build_labels（-100 哨兵，SFT 用）与 build_mask（0/1 权重，DPO 用）。
监督区间 response span
[start, stop) 半开 token 区间：从前缀锚点（"<|im_start|>assistant\n"，5 token）之后起，到后缀锚点（"<|im_end|>\n"，2 token）含尾收口——模型要学的除回答正文外还包括 think 块与"何时闭嘴"的收尾。
残段 dangling
有前缀锚点开头、后缀锚点被截断丢失的半截回复。C2 修复后不计监督（只计数供诊断）；旧行为兜底划入损失区间，是"回答戛然而止、复读"的训练侧源头（基线 0.82 残段/受损样本，存档 docs/retrain_plan §3.1）。
零损失样本 zero-loss sample
截断后不含任何完整回复 → labels 全 -100 → 损失恒 0、零梯度，GPU 前向照算（"白训"）。C3 在训练视图取数路径上确定性前向重映射跳过，触发次数计入数据卡。
拦腰截断 / 轮次边界截断
旧新两种超窗策略：前者 ids[:max_length] 一刀切（切口落进回复中间，残段与零损失的温床）；后者 C1 的 _fit_turns——丢最旧整轮（system 恒留）→ 左截末轮 user 保尾部 → 单回复超窗才硬截兜底。
运行时增强 runtime augmentation
每次取样本时重新抽签的两处随机性：增强A 概率注入 system（0.2，10 条池）；增强B 概率移除空 think 块（保留 0.2）。不加数据白拿分布多样性；随机性由 seed_worker 治理（同 seed 同结果）。
配对公平 pairing fairness
DPO 每行抽一次 remove_empty_think 签、chosen/rejected 共用——把"格式"这个无关变量钉死，两序列的对数概率差才可归因为内容好坏（M17）。
manifest 旁车清单 sidecar manifest
构建期一次全量扫描（不做分词）产出的 .manifest.npz：每行的回复哈希（C4 去重键）、keep、is_eval（C5 分桶）、n_messages。哈希用 md5 不用内建 hash()（跨进程稳定），指纹 mtime+size 失效重算（M11 详讲）。
哈希分桶切分 hash-bucket split
训练/验证归属按整行规范化内容的稳定哈希取模决定，与文件顺序无关——治"有序文件尾切验证集分布偏移"（C5，基线多轮占比差约 21pp → 断言 ≤2pp）。
prompt-only 样本
RL 阶段（RLAIF/AgentRL）的数据形态：只渲染"该 assistant 说话了"的话头（add_generation_prompt=True），answer 留空——答案由 rollout 现场生成、奖励打分（M19）。
