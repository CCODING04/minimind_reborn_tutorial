FFN：SwiGLU 与 MoE

M07 的 attention 让词与词交换信息；本课拆 Block 的另一半——FFN，对每个词独立深加工。 两件事：SwiGLU 门控前馈（M04 埋的 intermediate_size=2432 伏笔在此兑现），以及 MoE 把一个 FFN 扩成一个四专家团队按 token 路由。这块补上，⑤站零件集齐，M09 就能组装整机。

SwiGLU：自己给自己调音量

直觉：两路线性，一路当门

经典 Transformer（2017 原版）的 FFN 是两层线性夹一个激活函数（activation function， 把线性变换"掰弯"的非线性函数，没有它 8 层线性层叠起来仍等价于一层）： $$ \mathrm{FFN}_{cls}(x) = W_{down}\,\sigma(W_{up}\,x) $$ SwiGLU 把它改成三路线性、两路相乘：gate 路过激活函数后，逐元素乘（$\odot$）到 up 路上，再投影回去： $$ \mathrm{SwiGLU}(x) = W_{down}\big(\mathrm{SiLU}(W_{gate}\,x) \odot (W_{up}\,x)\big), \qquad \mathrm{SiLU}(x) = x \cdot \mathrm{sigmoid}(x) $$ sigmoid 是把任意实数压进 $(0,1)$ 的 S 形函数——SiLU 的输出大体落在 $(−0.28, \infty)$，于是 gate 路出来的每个维度像一排音量旋钮：接近 0 把 up 路对应维度静音，大则放行。关键在"旋钮的位置由输入自己算出来"—— 自己给自己调音量，这就是门控（gating）。

💡 直觉：调音台，不是流水线

经典 FFN 是流水线：升维 → 过激活 → 降维，信号一路向前。SwiGLU 是调音台：同一输入接两路， gate 路 2432 个旋钮逐个决定 up 路每个通道的音量，混音后才降维输出。 哪些通道该开大，是 $W_{gate}$ 学出来的——相当于每个 token 自己决定"这 2432 个加工位我要用哪几个"。 论文 GLU Variants Improve Transformer（arXiv:2002.05202） 的实验结论：同参数量下 SwiGLU 一档全面小优于经典 FFN，LLaMA/Qwen/DeepSeek 系全线采用——也包括 reborn。

精读：14 行的 FeedForward

src/minimind_reborn/models/feedforward.py · FeedForward 类全文python
class FeedForward(nn.Module):
    """SwiGLU：down(act(gate(x)) · up(x))，全部无 bias（与官方/LLaMA 一致）。"""

    def __init__(self, config: MiniMindConfig, intermediate_size: int | None = None):
        super().__init__()
        intermediate_size = intermediate_size or config.intermediate_size
        self.gate_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)  # 门：768→2432
        self.down_proj = nn.Linear(intermediate_size, config.hidden_size, bias=False)  # 降维：2432→768
        self.up_proj = nn.Linear(config.hidden_size, intermediate_size, bias=False)    # 值：768→2432
        self.act_fn = ACT2FN[config.hidden_act]   # "silu" → SiLU（激活函数注册表查名取函数）

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))

四个读点。① forward 一行就是公式：act(gate(x)) * up(x) 是逐元素乘（ broadcasting 语义下 两个同形状张量对应位置相乘），再交给 down_proj；② 三个投影全部 bias=False—— 现代做法（LLaMA 起成为惯例）：FFN 前面有 RMSNorm（M05）管平移，偏置的作用被归一化吸收，去掉后每层省 2432×2+768=5632 个参数、计算更快，效果无损；reborn 还有一个硬理由——与官方权重逐键一致（state_dict 键与形状，M02 见过的保存格式）， M09 要拿官方 pretrain_768.pth 做 strict 互通，多个 bias 数组形状就对不上；③ ACT2FN 是 transformers 的激活函数注册表，配置里写名字（hidden_act="silu"）这里查表取函数——配置驱动，换激活不改代码； ④ 构造参数 intermediate_size 可覆盖——MoE 专家正是靠它用更窄的中间维（下文）。 shape 链路真跑核对：

为什么是三个矩阵：M04 括号里的 π 兑现

M04 讲派生参数时留过一个括号：intermediate_size 的官方公式是 ceil(hidden×π/64)×64（768 → 2432），并说"SwiGLU 比经典两矩阵多一个，参数量相当的量级是 8h/3"。现在兑现。参数量口径：经典 FFN 两矩阵 $2 \cdot h \cdot d$，SwiGLU 三矩阵 $3 \cdot h' \cdot d$ （$h$ 为中间维、$d$=768）。要 SwiGLU 不比经典贵，中间维该从经典的 $4d$ 缩到： $$ h' = \tfrac{2}{3} \times 4d = \tfrac{8d}{3} = \tfrac{8 \times 768}{3} = 2048 $$ 而官方经验值取 π：$768\pi \approx 2412.7 \Rightarrow$ 向上对齐 64 倍数 $\Rightarrow$ 2432， 比 8h/3 高 18.8%——略贵一点换 SwiGLU 的门控收益。这就是那个"π 经验公式"的来历： π 不是什么魔法数，是"8/3 再放宽一点"的工程取值，再取整到 64 的倍数吃满硬件对齐。

MoE：不是每次都要全脑运转

动机：把参数量和计算量解耦

dense FFN 有个死结：参数越多计算越贵——5.6M 参数每个 token 全都要乘一遍。MoE（Mixture of Experts， 混合专家）的解法：并排放 N 个独立的 FFN（"专家"），配一个轻量 router（路由器），每个 token 只挑 k 个专家加工。参数可以堆很多，每 token 的计算只花在被选中的专家上——这叫稀疏激活（sparse activation）。 直觉：医院分科——病人（token）只挂对应科室，不需要全院医生同时出诊。

💡 概念卡：稀疏激活 = 参数与计算分家

dense 模型的"大"要拿每 token 计算量付账；MoE 把两笔账拆开：总参数决定"装了多少知识"（显存）， 激活参数决定"每个 token 花多少算力"。reborn 的 4 专家 top-1：每层 FFN 参数 ×4，每 token 计算量不变。 本课末尾的参数账本会实测：全模型 63.91M → 198.42M（3.10 倍），每 token 激活 63.94M（几乎没变）。

开关与旋钮都在 models/config.py （M04 的 schema 域里同名同默认，所以 CLI 一句 --set model.use_moe=true 就能换结构）：

精读路由段：打分 → 选专家 → 定权重

src/minimind_reborn/models/feedforward.py · MOEFeedForward 路由段（forward 前半）python
def forward(self, x: torch.Tensor) -> torch.Tensor:  # (b, seq, hidden) → (b, seq, hidden)
    batch, seq_len, hidden_dim = x.shape
    x_flat = x.view(-1, hidden_dim)             # (b·seq, 768)：路由按"单个 token"进行，摊平
    scores = F.softmax(self.gate(x_flat), dim=-1)  # (b·seq, 4) 路由分数：和为 1 的概率
    topk_weight, topk_idx = torch.topk(scores, k=self.config.num_experts_per_tok, dim=-1, sorted=False)
    if self.config.norm_topk_prob:
        if self.config.num_experts_per_tok > 1:
            topk_weight = topk_weight / (topk_weight.sum(dim=-1, keepdim=True) + 1e-20)  # 重归一化
        else:
            # k=1 归一化是恒等，改用直通估计器把权重钉在 1.0 而梯度仍走 softmax
            top1 = torch.topk(F.softmax(self.gate(x_flat.detach()), dim=-1), k=1, dim=-1, sorted=False)[0]
            topk_weight = top1 - top1.detach() + 1.0

self.gate 是一个 768→4 的线性层（参数仅 3,072 个）——router 本体就这么小。三步： ① 打分：每个 token 得 4 个分数，softmax（M07 手算过的归一化：一组数变成和为 1 的概率）成"对每位专家的倾向"； ② 选专家：torch.topk（top-k：按值取前 k 名及其下标——一个离散选择，记住这点，直通估计器就为它而生） 默认 k=1，只留分最高的那位专家；③ 定权重：k>1 时把选中的 k 个权重重归一化（除以它们的和，只信"入围者内部的相对强弱"）， k=1 时除以自己是恒等——于是改走直通估计器分支。

top-1 直通估计器：让梯度绕过"选择"

最费解的一行来了：topk_weight = top1 - top1.detach() + 1.0。要懂它，先看清问题。 路由链里有一处天然断裂：torch.topk 是离散选择——"从 4 个分数里挑最大那个"。 假如 router 把分数微调 0.01 使专家 3 反超专家 0，输出会整个换成另一个人；但"选了谁"这件事本身 没有梯度（导数无处定义：输入的微小变化导致输出跳变，而不是平滑变化）。而 k=1 时重归一化又是恒等 （除以自己恒得 1）——若老老实实把权重算成 1.0，router 的 gate 将收不到任何梯度：损失怎么变都与打分无关， router 永远学不会"什么 token 该找什么专家"。两难：前向需要常数 1.0，反向需要梯度。

📐 严谨卡：直通估计器（straight-through estimator）拆到符号

detach() 返回同值但剪断计算图的副本（计算图：autograd 为反向传播记录的那张运算路径图， detached 副本对梯度"装死"——梯度流到它就停）。于是这一行的两个视角： $$ \text{前向：} \ w = \mathrm{top1} - \overbrace{\mathrm{top1}.\mathrm{detach}()}^{\text{数值=top1}} + 1 = 1.0 \qquad \text{反向：} \ \frac{\partial w}{\partial\, \mathrm{top1}} = 1 - 0 + 0 = 1 $$ 前向数值上权重恒等于 1.0（实测上表：全部等于 1.0? True）——专家输出不缩水；反向时梯度 $\partial L/\partial \mathrm{top1}$ 原样传回 softmax、再回 gate 权重（实测：gate.weight.grad 非零? True）—— router 学得会。一个表达式，前向一副面孔、反向另一副面孔。行内还有个细节：重算 top1 时喂的是 x_flat.detach()——这条捷径梯度只更新 gate 自己的权重，不再穿过输入回传主干，避免与专家路径的梯度重复计账。 为什么不干脆用 weight = top1（拿概率当权重）？梯度也有了——但前向语义变了：初始化时 top1≈0.25， 专家输出被整体压到 1/4；STE 保住"前向全强度、反向有梯度"两头。这是教科书级的工程妥协数学： 离散选择不可导，就在前向/反向各用一套近似，两头都不撒手。

专家执行段与"挂图"怪招

src/minimind_reborn/models/feedforward.py · 专家循环（forward 后半）python
y = torch.zeros_like(x_flat)
for i, expert in enumerate(self.experts):          # 逐专家认领自己的 token
    mask = topk_idx == i                           # (b·seq, k)：本专家分到哪些 token
    if mask.any():
        token_idx = mask.any(dim=-1).nonzero().flatten()
        weight = topk_weight[mask].view(-1, 1)     # 被选中处的路由权重
        y.index_add_(0, token_idx, (expert(x_flat[token_idx]) * weight).to(y.dtype))
        # index_add_：把每个专家的产出按 token 位置累加回 y（k>1 时一个 token 收多份）
    elif self.training:
        y[0, 0] += 0 * sum(p.sum() for p in expert.parameters())   # ← 未路由专家"挂图"

正常路径（mask.any() 为真）：抽出分到的 token，过专家、乘路由权重，累加回 y—— 每个专家只算自己的 token，这就是稀疏激活的落点。怪的是 elif self.training 那行： 本步一个 token 都没分到的专家，往输出上加一个乘以 0 的参数和。0 乘不改任何数值，为什么多此一举？

因为 DDP（DistributedDataParallel，分布式数据并行——多卡各持一份模型副本、各算各的 batch、 反向后同步梯度的训练方式；M15 详讲，本课只需要这一句）。DDP 的同步前提是每个参数都参与了前向、 反向时都有梯度可发。top-1 路由 + 4 专家，某个专家这步空手很常见（上节实测 load=[0.406, …, 0.125]， 0.125 意味着常有无票专家）——它的参数没进计算图，反向时无梯度可发，DDP 第二步直接报错。 y[0,0] += 0·Σp 用一次 0 乘在计算图上建立对这些参数的依赖：autograd 会为它们生成（全零的）梯度， reducer 视其为"已使用"。单进程就能复现这个报错与修复：

/tmp/m08_exp_ddp.py · 玩具 2 专家 MoE：无技巧 vs 挂图（gloo 后端，单进程 world=1）python
import os
import torch
import torch.distributed as dist
import torch.nn as nn
from torch.nn.parallel import DistributedDataParallel as DDP

os.environ.setdefault("MASTER_ADDR", "127.0.0.1")
os.environ.setdefault("MASTER_PORT", "29517")
dist.init_process_group("gloo", rank=0, world_size=1)   # CPU 也能起 DDP

class BiasedMoE(nn.Module):
    """路由结果全落专家 0（模拟偏心），专家 1 本步收不到 token。"""
    def __init__(self, d=16, hang=False):
        super().__init__()
        self.experts = nn.ModuleList([nn.Linear(d, d) for _ in range(2)])
        self.hang = hang
    def forward(self, x):                       # x: (T, d)
        y = self.experts[0](x)                  # 专家 1 本步未被路由到
        if self.hang:
            y[0, 0] += 0 * sum(p.sum() for p in self.experts[1].parameters())
        return y

for hang in (False, True):
    ddp = DDP(BiasedMoE(hang=hang))
    label = "无挂图技巧" if not hang else "y[0,0]+=0·Σp 挂图"
    try:
        for step in range(2):                   # 第 1 步能过，第 2 步撞上检查
            loss = ddp(torch.randn(8, 16)).pow(2).sum()
            loss.backward()
        print(f"{label}: 两步都通过")
    except RuntimeError as e:
        print(f"{label}: RuntimeError: {str(e).splitlines()[0]}")

负载均衡 aux loss：不许 router 偏心

router 有个自毁倾向：强者愈强。某专家初期略强 → 分到更多 token → 被训练得更充分 → 更强 → 分到更多……极端时 4 个专家坍缩成 1 个（上节"偏心 router"实测 load=[1.0, 0, 0, 0] 就是这个终态的样子）—— MoE 退化成 dense 还白付 3 份参数的显存。解法是给"偏心"上税：

src/minimind_reborn/models/feedforward.py · aux loss 段（forward 尾部）python
if self.training and self.config.router_aux_loss_coef > 0:
    # 负载均衡：路由频率 load 与平均分数 importance 的点积，越小越均衡
    load = F.one_hot(topk_idx, self.config.num_experts).float().mean(0)  # 实际分票频率
    self.aux_loss = (load * scores.mean(0)).sum() * self.config.num_experts * self.config.router_aux_loss_coef
else:
    self.aux_loss = scores.new_zeros(1).squeeze()   # 评估期恒 0

两个量：load=每位专家实际分到的 token 频率（one_hot 把选中下标变成 4 维指示向量再取均值； 不可导——它是"选择"的统计）；importance=每位专家的平均路由分数（scores.mean(0)，可导—— 梯度经它流回 gate）。乘积逐元素求和： $$ \mathrm{aux} = \Big(\sum_{i=1}^{N} \mathrm{load}_i \cdot \mathrm{importance}_i\Big) \times N \times \mathrm{coef} $$ 完全均匀时每项 $\frac{1}{N}\cdot\frac{1}{N}$，和为 $\frac{1}{N}$（最小）；全偏心时和为 1（最大）。 乘 N 把区间归一到 $[1, N]$，再乘系数缩放——取值范围天然是 $[\mathrm{coef},\ N\cdot\mathrm{coef}]$， 4 专家默认系数下就是 $[5\mathrm{e}{-4},\ 2\mathrm{e}{-3}]$。实测三点对上：均匀路由 0.000516、偏心路由 0.002000（恰好触顶 $4\times5\mathrm{e}{-4}$）、eval 恒 0.000000。评估期为什么置零？aux 是训练正则项—— 它与前向输出 y 完全无关，只影响 gate 的更新；eval 不更新参数，置零省计算且输出语义不变。 test_moe_aux_loss_positive 把这三点写成了断言。

这条损失怎么进训练？模型把各层加总（model.py:120-124 的 sum(layer.mlp.aux_loss ...)）挂在输出里， 8 个 workflow 的消费姿势一致，pretrain 版一行：

src/minimind_reborn/training/pretrain/workflow.py · compute_loss（第 17-19 行）python
def compute_loss(batch, m):
    out = m(batch["input_ids"], labels=batch["labels"])
    loss = out.loss + out.aux_loss  # aux 仅 MoE 非零；dense 恒 0，加法等价官方
    return loss, {...}

主损失 + 辅助损失的加法组合：dense 时 aux 恒 0（FeedForward 根本没有 aux_loss 属性这条路—— model.py 只对 MOEFeedForward 求和），MoE 时一个小系数的均衡税悄悄加进总损失。系数就是 $[\mathrm{coef}, N\cdot\mathrm{coef}]$ 里那个 coef——它的数量级为什么是 5e-4，坑卡见。

检验一下

测验 1 · SwiGLU 为什么是三个矩阵？多出来的那个在干什么？参数量怎么补回来？

答案：多出的是 gate 矩阵：它那一路过 SiLU 后输出大体在 $(−0.28,\infty)$，逐元素乘到 up 路——像由输入自己算出的一排音量旋钮，决定 2432 个加工位各开多大，这是"门控"。三个矩阵比经典两个多一份，参数量相当就要把中间维从 $4d$ 压到 $\frac{8d}{3}$（768 → 2048）；官方经验公式取 π·768≈2432，比 8h/3 再高 18.8%——M04 括号里的伏笔即此。

答错回看：直觉：两路线性，一路当门 与 为什么是三个矩阵。

测验 2 · top1 - top1.detach() + 1.0 的前向值是多少？反向呢？它解决什么问题？

答案：前向恒 1.0（detach 只剪图不改数，两项相消）；反向 $\partial w/\partial\mathrm{top1}=1$，梯度原样流回 softmax 与 gate。解决的是 topk 不可导：k=1 时"选了谁"是离散选择、重归一化又是恒等——老实写权重 1.0 则 router 收不到任何梯度、永远学不会路由。直通估计器让前向/反向各用一套近似：前向全强度、反向有梯度。

答错回看：top-1 直通估计器 的严谨卡与实测输出。

测验 3 · y[0,0] += 0·Σp 这行为什么存在？删掉它，单卡训练会坏吗？

答案：为 DDP 而生：分布式训练要求每个参数都参与前向，否则反向无梯度可发、同步报错（实测 RuntimeError: ... parameters that were not used in producing loss）；top-1 路由下某专家这步分不到 token 是常态，0 乘在计算图上建立依赖、生成全零梯度，让 reducer 视其为已使用。单卡（无 DDP）删掉它不坏——数值一分不变，只是上了多卡立刻翻车。它也只在 self.training 生效：eval 不建图。

答错回看：专家执行段与"挂图"怪招 的玩具 DDP 实验。

测验 4 · aux loss 由哪两个量相乘？取值范围是多少？评估期为什么是 0？

答案：load（每位专家实际分票频率，不可导）乘 importance（平均路由分数，可导——梯度经它流回 gate），求和后乘 N 乘 coef，范围 $[\mathrm{coef},\ N\cdot\mathrm{coef}]$（均匀最小、全偏心最大，默认 4 专家即 $[5\mathrm{e}{-4}, 2\mathrm{e}{-3}]$，实测 0.000516 → 0.002000）。评估期为 0：aux 是训练正则项，与前向输出无关，eval 不更新参数，置零省计算且不改输出——测试里两条断言锁定了这对行为。

答错回看：负载均衡 aux loss 的公式与实测。

本课词汇

FFN feed-forward network
前馈子层：对每个 token 位置独立做升维→非线性→降维，不跨位置混合（跨位置是 attention 的职责）。SwiGLU 形态下每层 5.6M 参数，占 Block 的 76%。
SwiGLU
三矩阵门控 FFN：down(SiLU(gate(x)) ⊙ up(x))。gate 路经激活后逐元素乘 up 路——"自己给自己调音量"；参数量与经典 FFN 相当时中间维取 8d/3，官方经验公式取 π·d 再对齐 64 倍数（768→2432）。LLaMA/Qwen/DeepSeek 系标配。
SiLU swish 激活
x·sigmoid(x)，非单调光滑激活函数；输出大体在 (−0.28, ∞)，负半轴小幅下潜——门控旋钮的"关"不必是零。
门控 gating
用一路可学习的信号逐元素乘另一路，控制其通/断/强弱；GLU 家族（SwiGLU/GeGLU/ReGLU）的区别只在门上的激活函数。
MoE mixture of experts
混合专家层：N 个并列 FFN + 轻量 router，每个 token 只激活 k 个专家。reborn：4 专家 top-1，总参数 ×4、每 token 激活不变。
router / top-k 路由
768→N 的线性层打分，softmax 归一，torch.topk 取前 k 名。topk 是离散选择、本身不可导——梯度问题的根源。
直通估计器 straight-through estimator
前向取离散/常数值、反向按连续近似传梯度的技巧；reborn 写作 top1 − top1.detach() + 1.0：前向恒 1.0，反向梯度照走 softmax 回 gate。
负载均衡 aux loss load balancing loss
(load·importance).sum() × N × coef：实际分票频率与平均路由分数的乘积和，均衡最小（1/N）、偏心最大（1）；防"强者愈强"的专家坍缩。Switch Transformer 提出。
稀疏激活 sparse activation
参数量与每 token 计算量解耦的性质：参数驻留显存但不逐 token 全算；用 forward hook 数"被调用的模块"可实测激活集合。
挂图技巧 DDP unused parameters
y[0,0] += 0·Σp：为未被路由的专家在计算图上建立 0 乘依赖，使其获得全零梯度、被 DDP 视为已使用——多卡同步的刚需（M15 详讲 DDP）。
