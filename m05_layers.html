RMSNorm：少一次统计的归一化

它到底归一化了什么

归一化（normalization）指按向量自身的统计量把它缩放、让幅度可控的一层操作——训练几十万步后 各层幅度会漂移，不压住后面的乘法越乘越炸。经典做法 LayerNorm（PyTorch 自带的 nn.LayerNorm， 2020 年前 Transformer 的标配）与 RMSNorm 对照： $$ \text{LayerNorm}(x) = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \cdot \gamma + \beta \qquad\quad \text{RMSNorm}(x) = \frac{x}{\sqrt{\tfrac{1}{d}\textstyle\sum_i x_i^2 + \epsilon}} \cdot \gamma $$ 差异就两处：不减均值（$\mu$ 整个消失），没有偏置 β。RMS 是 root mean square（均方根）， 向量的"典型幅度"。

💡 直觉：RMSNorm 只管"长度"，不管"原点"

除以 RMS 后，向量长度被拉到 $\sqrt{d}$（768 维 ≈ 27.7），方向一丝不变——而注意力真正关心的恰恰是方向 （打分靠内积，方向决定语义）。为什么敢把减均值砍掉？经验答案是：对 Transformer 效果几乎不掉 （RMSNorm 原始论文 arXiv:1910.07467 的核心实验）， 而均值偏移这类"整体平移"可以被下一层的线性变换自然吸收。省下一次均值统计、一次减法、一个偏置参数—— 768 维 × 17 处 × 每步前向，LLaMA、Qwen、DeepSeek 系全线换装。

精读：14 行的 RMSNorm

src/minimind_reborn/models/layers.py · RMSNorm 类全文python
class RMSNorm(nn.Module):
    """RMSNorm：fp32 归一化后回落输入精度。"""

    def __init__(self, dim: int, eps: float = 1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))  # 逐维缩放 γ，初始全 1（等于"先不缩"）

    def _norm(self, x: torch.Tensor) -> torch.Tensor:
        # x: (..., dim) —— 最后一维是 768；逐行（每个 token 位置）独立归一化
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return (self.weight * self._norm(x.float())).type_as(x)

三个读点。① weight 是这个层唯一的可学习参数（768 个数），这就是"无 β"的代码形态； ② eps（epsilon，数值稳定小量）防分母为零——函数默认 1e-5，但 64M 模型实际传的是 config.rms_norm_eps=1e-6（config.py:34，变式练习 2 专门拆它）； ③ forward 那一行的 .float() 与 .type_as，是下面整节的大知识点。

fp32 纪律：为什么先 .float() 再 type_as

先补背景：bf16（bfloat16，brain float 16）是 16 位浮点——8 位指数 + 7 位尾数。指数位宽与 fp32（32 位单精度浮点）相同，动态范围不缩水；但尾数只有 7 位显式（fp32 是 23 位）， 精度只剩约 $2^{-8} \approx 0.4\%$。训练配方 dtype: bf16（M04）与 GPU 推理都用它省一半显存与带宽。 问题在于：归一化是"用小数除小数"的精密活，mean(x²) 与 rsqrt 在 bf16 里逐级舍入， 误差直接乘进每个输出元素。reborn 的对策写在 forward 单行里：统计升 fp32 算， 算完 type_as 回落原精度——存储不变、带宽不涨，只有计算中间态升精度。 真跑对比（脚本与 _norm 相同，只换精度路径）：

/tmp/m05_exp_bf16.py · bf16 直算 vs fp32 纪律python
import torch
torch.manual_seed(0)
eps = 1e-5
def norm(x):                                    # 与 layers.py 的 _norm 相同
    return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + eps)

dev = "cuda" if torch.cuda.is_available() else "cpu"
h = (torch.randn(8192, 768) * 30).to(dev)       # 模拟训练后期的 hidden（std=30），(8192, 768)
x = h.bfloat16()                                # 全 bf16 模型里 RMSNorm 的真实输入
ref    = norm(h.double()).float()               # fp64（双精度）参考答案
direct = norm(x).float()                        # 无纪律：统计量在 bf16 里算
discip = norm(x.float()).bfloat16().float()     # reborn：升 fp32 算完回落
for name, out in [("bf16 直算", direct), ("fp32 纪律", discip)]:
    print(f"{dev} · {name}: max_abs={(out-ref).abs().max():.4f} rel={(out-ref).norm()/ref.norm()*100:.3f}%")
r64 = torch.rsqrt(h.double().pow(2).mean(-1, keepdim=True) + eps)
print("scale 因子误差: bf16 %.4f%%  fp32 %.4f%%" % (
    ((torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + eps).double() - r64).abs() / r64).max() * 100,
    ((torch.rsqrt(x.float().pow(2).mean(-1, keepdim=True) + eps).double() - r64).abs() / r64).max() * 100))

💡 概念卡：敏感算子精度纪律（fp32 纪律）

存储用低精度，敏感计算升 fp32，算完回落。"敏感"指做除法/开方/求和归约、输入可能是极小数的算子： 归一化、位置编码、attention 打分、对数概率。layers.py 模块注释的纪律原文： "norm、rotary 等半精度下易失稳的算子显式升 fp32 计算、算完 type_as 回落——写法固定在此处， 不依赖 autocast 内部行为"（autocast：PyTorch 混合精度上下文，自动决定哪些算子降 bf16）。 这是本课程三次相遇的第一个：M07 的 attention 打分（attention.py:113 的 .float()）、 M17 的 DPO 对数概率——同一思想，三处复用。

RoPE：用旋转角度编码位置

直觉先行：模型天然不知道词序

embedding（把 token id 变成向量的那张查找表，M09 组装时详讲）只认词本身，不认位置—— "我打他"和"他打我"送进去是同一袋向量。注意力打分又只看内积（dot product：两向量对应元素相乘再求和）。 没有位置信息，"我"和"他"谁在前，打分完全不知道。

RoPE（Rotary Position Embedding，旋转位置编码，arXiv:2104.09864） 的方案一句话：按 token 的位置把 q、k 向量旋转一个角度——位置每走一步多转一点； 旋转后的内积只依赖两位置的差。这里 q（query）和 k（key）是注意力里每个词自带的一对向量， 词与词的相关性打分就是 q·k——M07 的主角，本课只需要这一句。

直觉——表盘上的指针：把一对维度看成一个表盘上的指针，RoPE 就是"位置每 +1，指针多转固定角度"。两个词打分时， 先把各自的指针转到位再比对夹角——夹角只取决于两针各转了多少的"差"，与从几点开始转无关。 "我打他"里（我，他）距离 2 与"他打我"里（他，我）距离 −2 撞出两种不同夹角图案，词序就这样进了打分。 早期 GPT 的做法是把位置 id 变成向量加进 embedding（绝对位置编码）；RoPE 不加参数、 只在 attention 内部旋转，长文本外推也更从容（见 YaRN 折叠深读）。

精读 precompute_freqs_cis：把"位置×角度"提前算成表

旋转需要的 cos/sin 只依赖配置（维度、位置数、base），与输入无关——所以预计算成表，前向只查表 （M03 ⑤站见过的 self.freqs_cos[cache_start : cache_start+seq] 切片就是它）。核心骨架：

src/minimind_reborn/models/layers.py · precompute_freqs_cis（YaRN 分支见折叠深读）python
def precompute_freqs_cis(dim, end=32768, rope_base=1e6, rope_scaling=None):
    """预计算 RoPE 的 cos/sin 表，形状 (end, dim)，sin/cos 各重复一半以对齐 rotate_half。"""
    # dim//2 个步进角 θ_i = base^(-2i/dim)：i=0 → 1 弧度/步，i 越大转得越慢
    freqs = 1.0 / (rope_base ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
    ...                                    # ← rope_scaling 分支：YaRN 折叠深读
    t = torch.arange(end)                  # 位置 0..end-1
    angles = torch.outer(t, freqs).float() # (end, dim//2)：每个位置 × 每个步进角
    # cos/sin 各自重复一半拼成 (end, dim)：前半 = 后半，为对齐下面的 rotate_half
    freqs_cos = torch.cat([torch.cos(angles), torch.cos(angles)], dim=-1)  # (end, dim)
    freqs_sin = torch.cat([torch.sin(angles), torch.sin(angles)], dim=-1)  # (end, dim)
    return freqs_cos, freqs_sin

shape 链路第一步：freqs 是 (dim/2,) 的步进角，torch.outer(位置, 步进角) 摊成 (end, dim/2) 的角度矩阵，cos/sin 各重复一半后成为 (end, dim)。注意 dim 是 head_dim=96（旋转发生在每个注意力头内部，不是 768 整根向量），64M 模型即 48 个旋转对。 实测 dim=8 时的 4 个步进角：

第 0 对每步转 1 弧度（约 6 步一圈——快指针，编码近距离），最后一对每步 0.000032 弧度 （约 20 万步一圈——慢指针，编码远距离）。48 个指针以 rope_theta=1e6（config.py:35） 为底按几何级数排开转速，不同距离的词对撞出不同"夹角图案"。cos/sin 为什么重复一半？ 答案在下一个函数的 rotate_half 里。

这两张表住在模型里（model.py:64-73 用 register_buffer("freqs_cos", …, persistent=False) 注册）。 buffer 是"跟着模型走设备、但不参与训练"的张量；非持久（persistent=False）意味着不进 state_dict（torch.save 保存的参数字典，M02 加载权重时见过的那种）——因为它是派生数据，只依赖 config，加载时重算即可。64M 模型两张表各 (32768, 96) fp32、共 24.0 MiB，而 pretrain_768.pth 才 131.3 MiB——落盘则每个 checkpoint 白胖 18%。代价是：transformers ≥5.x 用 meta 设备（只建形状 不占内存的虚拟设备）初始化模型时会丢非持久 buffer，model.py:75-90 为此留了重建兜底—— M09 的猎场就从这里开挖。

[作者实测 · 2026-09-30] 表形状/dtype 与字节数由 precompute_freqs_cis(dim=96, end=32768, rope_base=1e6) 实跑核对；checkpoint 大小来自 os.path.getsize('out/pretrain_768.pth')。

精读 apply_rotary_pos_emb：rotate_half 的障眼法

src/minimind_reborn/models/layers.py · apply_rotary_pos_emb 全文python
def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim: int = 1):
    """对 q/k 施加 RoPE。
    q, k: (b, seq, heads, head_dim)；cos, sin: (seq, head_dim) → 在 head 维前 unsqueeze。"""

    def rotate_half(x):
        # (b, seq, heads, head_dim) 前后半交换符号拼接：(x1, x2) → (-x2, x1)
        return torch.cat((-x[..., x.shape[-1] // 2:], x[..., : x.shape[-1] // 2]), dim=-1)

    cos = cos.unsqueeze(unsqueeze_dim)  # (seq, head_dim) → (seq, 1, head_dim)：广播到所有头
    sin = sin.unsqueeze(unsqueeze_dim)
    q_embed = (q * cos) + (rotate_half(q) * sin)   # 2D 下即标准旋转 R(θ)·x
    k_embed = (k * cos) + (rotate_half(k) * sin)
    return q_embed.to(q.dtype), k_embed.to(k.dtype)

拿一对维度 $(x_1, x_2)$ 展开最后一行：q*cos + rotate_half(q)*sin = $(x_1\cos\theta - x_2\sin\theta,\ x_2\cos\theta + x_1\sin\theta)$——正是旋转矩阵 $R(\theta)$ 乘向量的逐元素写法，一次广播完成 48 对的旋转。这也回答了上节的问题：rotate_half 把后半维翻到前面， cos/sin 必须"前半=后半"才能逐元素对齐。顺带一句（不展开）：把每对 $(x_1, x_2)$ 看成复数 $x_1 + ix_2$，这套实数运算严格等价于乘以 $e^{i\theta}$——RoPE 论文的原视角就是复数旋转， 工程实现用实数避免复数内核。

shape 链路收尾：调用点在 attention.py:68，此时 q/k 是 (B, T, H, D)（batch、序列、头、head_dim）； cos/sin 是 (T, D)，unsqueeze(1) 成 (T, 1, D) 广播到每个头； 随后 attention.py:78 的 transpose(1, 2) 才把头维提到前面变成 (B, H, T, D) 去打分。 末尾的 .to(q.dtype)——又是一处精度回落，与 type_as 同一纪律。

实验：同一对词，换个起点，内积不变？

RoPE 的招牌性质值得亲手验证一次。同一对 q/k 向量，放在三个不同起点（位置差都是 4）， 旋转后的内积应当完全相等——用 reborn 的真实函数跑：

/tmp/m05_exp_rope.py · 相对位置不变性验证python
import torch
from minimind_reborn.models.layers import precompute_freqs_cis, apply_rotary_pos_emb

torch.manual_seed(0)
dim, end = 8, 64
cos, sin = precompute_freqs_cis(dim, end=end)            # cos/sin: (end, dim)
q, k = torch.randn(1, 1, 1, dim), torch.randn(1, 1, 1, dim)  # (b, seq, heads, head_dim)

def qk_at(m, n):
    """q 放在位置 m、k 放在位置 n，返回旋转后的内积"""
    qr, _ = apply_rotary_pos_emb(q, k, cos[m:m+1], sin[m:m+1])  # 只转 q 那一格
    _, kn = apply_rotary_pos_emb(k, k, cos[n:n+1], sin[n:n+1])  # 只转 k 那一格
    return (qr * kn).sum().item()

print("q·k（不旋转）= %.6f" % (q * k).sum().item())
for m, n in [(2, 6), (30, 34), (57, 61)]:
    print(f"q@{m:2d} k@{n:2d}（距离 {n-m}）: {qk_at(m, n):.6f}")

为什么"只依赖差"在数学上成立？推导折在下面——结论只有一行： $\langle R(m\theta)q,\ R(n\theta)k\rangle = q^\top R((n-m)\theta)\,k$，绝对位置 $m$、$n$ 各自消失。

📐 折叠深读：旋转为什么带来"只看距离"的内积（2D 手算，可跳过，不影响主线）

缩到最小：head_dim=2，只有一个旋转对、一个步进角 θ。二维旋转矩阵（逆时针转 α）与 RoPE 的用法（位置 m 的 q 转成 $R(m\theta)q$、位置 n 的 k 转成 $R(n\theta)k$）：

$$ R(\alpha) = \begin{pmatrix}\cos\alpha & -\sin\alpha \\ \sin\alpha & \cos\alpha\end{pmatrix} $$

推导只用旋转的两个恒等式：转置即反转 $R(a)^\top = R(-a)$，转角相加 $R(a)R(b) = R(a+b)$。于是：

$$ \langle R(m\theta)q,\ R(n\theta)k \rangle = q^\top \underbrace{R(m\theta)^\top R(n\theta)}_{R((n-m)\theta)}\, k $$

手算一遍（θ=30°，q=k=(1,0)，m=2、n=5）：

  • 老老实实转：$R(60°)q = (\cos 60°, \sin 60°) = (0.5,\ 0.866)$；$R(150°)k = (\cos 150°, \sin 150°) = (-0.866,\ 0.5)$； 内积 $= 0.5 \times (-0.866) + 0.866 \times 0.5 = -0.433 + 0.433 = 0$；
  • 走公式捷径：$q^\top R((n{-}m)\theta)k = (1,0)\cdot R(90°)(1,0) = \cos 90° = 0$ ✓ 两条路会合；
  • 平移检验：m、n 同时 +10（变成 12 与 15），$(n-m)\theta$ 仍是 90°，内积仍是 0——起点无关， 正是上面实验三行相等的原因。

[作者实测 · 2026-09-30] 此例已用脚本数值核对：直接转与公式捷径均输出 0.000000。

推广到 96 维：head_dim=96 拆成 48 个互不干扰的 2D 平面，第 i 个平面用步进角 $\theta_i = \text{base}^{-2i/96}$， 转速各不相同。总内积是 48 个"不同频率余弦"的加和：同一距离同一图案，不同距离不同图案—— 所以距离 4 → −1.706、距离 7 → +1.109（变式练习 1 的实测）不是单调衰减，是多频率振荡。

📐 折叠深读：YaRN——380 窗的模型，服务 2280 长的输入（可跳过，不影响主线）

64M 模型训练时的上下文窗口只有 380（config.py 注释原文："模型实际训练窗口"）， 但推理侧要覆盖 2048 档评测——位置 2048 的角度组合模型从没见过，打分会乱。在训练见过的范围之外 使用模型叫外推（extrapolation），位置编码外推质量骤降是经典痛点。 inference_rope_scaling=True（config.py:37）开启的 YaRN（arXiv:2309.00071） 用插值（interpolation：把没见过的长角度范围压进见过的范围）补救——把步进角按因子压小， 相当于把 2280 步的旋转总量"匀"回训练尺度。

关键在于不搞一刀切：高频对（快指针、管近距离）保持原样，低频对（慢指针、管远距离）压缩，中间线性过渡：

src/minimind_reborn/models/layers.py · YaRN 分支节选python
if end / orig_max > 1.0:              # 只有位置数超过训练窗才插值；end ≤ 380 原样返回
    # 由 beta 反解 ramp 的维度边界：inv_dim(b) = dim·ln(orig_max/(b·2π)) / (2·ln(base))
    low, high = max(math.floor(inv_dim(beta_fast)), 0), min(math.ceil(inv_dim(beta_slow)), dim // 2 - 1)
    ramp = torch.clamp((torch.arange(dim // 2).float() - low) / max(high - low, 0.001), 0, 1)
    freqs = freqs * (1 - ramp + ramp / factor)   # 插值公式一行：γ=0 原样，γ=1 压 factor 倍

插值公式即 $f'(i) = f(i)\cdot\big((1-\gamma_i) + \gamma_i/s\big)$，$\gamma_i$ 就是 ramp、s 是 factor=6 （目标窗 = 380×6 = 2280，覆盖评测 2048 档）。实测边界（dim=96、base=1e6）：orig_max=380 时 ramp 区间 [2, 15]——48 对里 0..1 不动、2..15 过渡、16..47 全插值。

常数曾是 2048 的 bug。config.py:9-10 注释记录了这段历史： "orig_max 必须等于模型实际训练窗口（380），否则插值按错误的'训练窗'外推、质量被系统性低估"； test_rope_scaling.py 的模块 docstring 更直白："曾硬编码 2048 导致插值参数失真（报告 §6.1）"。 实测两个后果：① ramp 边界错移——同参数下 2048 算出区间 [8, 21]（该插的没插够、 不该全插的被全插）；② 更致命的，end=2048 时 end/orig_max = 1.00， 不大于 1.0，插值分支整个不触发——评测窗恰好等于错误常数，等于裸奔外推。 修复：常数抽成 YARN_ORIGINAL_MAX_POSITION_EMBEDDINGS = 380 单一来源（config.py:11）+ 6 个测试锁定。

[作者实测 · 2026-09-30 · 2×RTX 4090 · torch 2.14.0+cu130] [2,15] 与 [8,21] 两组边界、end/orig_max 比值均由脚本按 inv_dim 公式实算；注释引文逐字来自 config.py:9-10 与 tests/test_models/test_rope_scaling.py:1-5。

坑卡：bf16 直接归一化，坏得很安静

⚠️ 坑卡：删掉那行 .float()，什么都不会发生——直到发生
  • 症状极其安静：全 bf16 模型里手写 RMSNorm 忘了升精度，不报错、不 NaN、loss 照常下降—— 输出悄悄偏移（实测见上节），17 个 RMSNorm 层层叠加，你只会觉得"这模型有点难训"。

  • 一行：(self.weight * self._norm(x.float())).type_as(x)——layers.py 模块注释立的规矩 "写法固定在此处，不依赖 autocast 内部行为"：行为从"碰巧"变"必然"，代价只是这个算子的 中间态多占一点 fp32 寄存器。

🏭 工业对照：为什么手写 98 行，而不是用现成的

RMSNorm 与 RoPE 是 LLaMA/Qwen/DeepSeek 系标配，现成实现到处有：PyTorch 2.4+ 内置 torch.nn.functional.rms_norm；HuggingFace transformers 把 RoPE 做成统一 utilities （含 YaRN 的 RoPEInitKwargs，全部模型共享一份实现与缓存）。reborn 仍手写：一为可读 （逐行看见 rotate_half 与插值公式），二为显式数值纪律（.float()/type_as 不藏在框架分支里）， 三为 6 个专属回归测试。工程判断：地基件值得亲手写一次，上层结构再谈复用。

检验一下

测验 1 · RMSNorm 比 LayerNorm 少算了什么？为什么敢少？

答案：少算均值 μ（不减均值），也去掉偏置 β——一次统计、一次减法、一组参数全省。敢少的原因：RMSNorm 论文的经验结论是效果几乎不掉；直觉上归一化的关键收益来自"压幅度、保方向"，整体平移可被下一层线性变换吸收。

答错回看：它到底归一化了什么 的公式对比与直觉卡。

测验 2 · RoPE 的"内积不变性"指什么？q@30 k@34 和 q@2 k@6 的内积谁大？

答案：旋转后的 q·k 只依赖两位置的差（$R(m\theta)^\top R(n\theta)=R((n-m)\theta)$，绝对位置消失）。两对距离都是 4，内积相等（实测同为 −1.706030）——同一对词换到文本任何位置，相对关系不变，打分就不变。

答错回看：内积不变性实验 + 直觉先行。

测验 3 · 归一化为什么要 .float() 再 type_as，而不是全程 bf16？为什么不干脆全模型 fp32？

答案：bf16 只有 7 位显式尾数（精度约 0.4%），归一化的统计链（平方→均值→rsqrt→乘回）在 bf16 里逐级舍入，实测 scale 因子误差 0.488%，fp32 路径 0.041%，差 12 倍。而"存储用 bf16、敏感计算升 fp32、算完回落"两头兼顾：显存与带宽省一半，数值安全不牺牲。全 fp32 当然更准，但训练/推理成本翻倍——纪律是性价比解。

答错回看：fp32 纪律 的实验与概念卡。

测验 4 · 预计算表里 cos/sin 为什么要各自重复一半（前半=后半）？

答案：为了对齐 rotate_half。施转算式是 q*cos + rotate_half(q)*sin，而 rotate_half 把后半维翻到前面——前半的 $x_1$ 要配 sin 的后半值，后半的 $x_2$ 配前半值，cos/sin 必须"前半=后半"才能在 (end, dim) 上逐元素广播对齐。这是实现层的配合约定，不是数学要求。

答错回看：rotate_half 的障眼法 与 precompute 精读 的注释。

写下预测：eps=0 时输出是全零、inf、还是 NaN？想一下 rsqrt(0) 等于什么，以及 $0 \times \infty$ 在浮点里规定成什么。

观察结果与解释（先动手再看）

作者实测（同环境）：

机制：全零行让 $\mathrm{mean}(x^2)=0$，rsqrt(0) = inf，再乘回全零的 $x$ 得 $0 \times \infty$——IEEE 754 浮点规定这个组合是 NaN，且 NaN 沿前向一路传染。 eps 的职责就是给分母兜底：有它时全零行干净地输出全零。全零 hidden 不是刁钻构造—— 深层残差网络瞬时接近零、异常输入都可能触发。"归一化分母永不为零"是数值安全的底线。

本课词汇

RMSNorm root mean square normalization
只除均方根、不减均值、无偏置的归一化层；唯一可学习参数是逐维缩放 γ。比 LayerNorm 少一次统计，LLaMA/Qwen 系标配。
bf16 bfloat16
16 位浮点：8 位指数（与 fp32 同宽，动态范围不缩水）+ 7 位显式尾数（精度约 0.4%）。训练与 GPU 推理用它省一半存储与带宽。
fp32 纪律 敏感算子精度纪律
存储用低精度、敏感计算（除法/开方/归约）显式升 fp32、算完 type_as 回落。layers.py 模块注释定为成文纪律；M07 打分、M17 DPO 复用。
RoPE rotary position embedding
旋转位置编码：按位置把 q/k 向量旋转递增角度，旋转后的内积只依赖位置差。不引入参数，发生在 attention 内部。
rotate_half
把最后一维前后两半交换符号拼接 (x₁,x₂)→(−x₂,x₁) 的实现技巧；与"cos/sin 各重复一半"配套，使 (q·cos)+(rotate_half(q)·sin) 等价于复数乘 e^{iθ}。
非持久 buffer persistent=False
register_buffer 注册的"跟着模型走但不参与训练"张量；persistent=False 使其不进 state_dict/checkpoint。RoPE 的 cos/sin 表（64M 模型两张共 24.0 MiB）只依赖 config，属派生数据，不落盘。
YaRN
RoPE 长度外推（在训练窗口之外使用模型）方案：高频维度保持、低频维度按 factor 插值（把没见过的范围压进见过的范围）、中间 ramp 过渡。reborn 训练窗 380、factor=6 → 目标窗 2280；orig_max 必须等于真实训练窗（曾有硬编码 2048 的 bug）。
eps epsilon
归一化分母里的数值稳定小量（模型用 1e-6）；防 mean(x²)=0 时 rsqrt 爆 inf——0×∞ 规定为 NaN，会沿前向传染。
