run_full.sh 精读：一条命令的全链路

M16 用接力赛讲过两棒的交接（init_from: pretrain 严格加载上一棒产物）。 tools/run_full.sh 把整场接力赛写成 20 行 shell—— 全文如下，一段一段看：

Reproduce/minimind_reborn/tools/run_full.sh · 全文 20 行bash
#!/bin/bash
# 全量训练链：数据下载校验 → pretrain → SFT → DPO（2×GPU DDP，resume 默认开）
# 用法：nohup bash tools/run_full.sh > /tmp/full_chain.log 2>&1 &
set -u
cd "$(dirname "$0")/.."
UV=${UV:-$HOME/.local/bin/uv}
NP=${NP:-2}
MARKER=/tmp/full_chain.log

echo "[chain] start $(date)" >> "$MARKER"
$UV run python tools/download_data.py --name pretrain_t2t >> "$MARKER" 2>&1 || { echo "[chain] 数据下载失败" >> "$MARKER"; exit 1; }
$UV run python tools/download_data.py --name sft_t2t    >> "$MARKER" 2>&1 || { echo "[chain] 数据下载失败" >> "$MARKER"; exit 1; }

$UV run torchrun --nproc-per-node "$NP" tools/train.py configs/pretrain_full.yaml > /tmp/full_pretrain.log 2>&1
echo "[chain] pretrain exit=$? $(date)" >> "$MARKER"
$UV run torchrun --nproc-per-node "$NP" tools/train.py configs/sft_full.yaml     > /tmp/full_sft.log 2>&1
echo "[chain] sft exit=$? $(date)" >> "$MARKER"
$UV run torchrun --nproc-per-node "$NP" tools/train.py configs/dpo_full.yaml     > /tmp/full_dpo.log 2>&1
echo "[chain] dpo exit=$? $(date)" >> "$MARKER"
echo "[chain] all done $(date)" >> "$MARKER"

四段各一句话。① 头部（4–8 行）：set -u 只防"引用未定义变量"直接死—— 注意不是 set -e（任何命令非零就停）；cd "$(dirname "$0")/.." 把工作目录钉在仓库根（从任何地方启动都能找到 configs/）；NP=${NP:-2} 是缺省 2 卡、 环境变量可覆盖（环境变量：进程级的配置开关，M04 的 CLI 覆盖是它的配置文件版）。② 数据段（11–12 行）： 两份语料各下载一次，|| exit 1 是全链唯一的 fail-fast（快速失败）——没有数据， 后面三棒全是白等，不如当场死。③ 三棒（14–19 行）：torchrun --nproc-per-node 就是 M15 的 DDP 启动器；每棒 stdout 重定向到各自的 /tmp/full_*.log， 而 MARKER 里只追加一行 exit=$?（上一命令的退出码）加时间戳—— 失败不停链，只记账。④ 为什么敢不停？因为下一棒自带守门人： init_from 走 M09 的 strict 加载，上一棒产物缺失或损坏会在下一棒启动前一秒炸出来， 日志里两行 exit=1 与报错对得上账。加上续训默认开启（M14：输出目录有 checkpoint 自动恢复）， 这条脚本天然支持"断了重跑接着来"。

💡 直觉：为什么要"一条命令"

全链 18 小时级（见下），不可能有人盯着。一条命令的价值是无人值守的原子性： nohup（no hang up：退出终端进程不死的挂后台方式）+ 各段独立日志 + resume 默认开， 深睡前敲一次、早上看 MARKER 的五行 exit=0。更深一层：这条脚本本身就是 系统是否真的"链"得起来的最终测试——三份 yaml 里的名字、路径、产物命名约定 （{名}_{hidden}.pth，M04 讲过）任何一处对不上，链当夜就断。M01 的 make smoke 三段链是它的分钟级缩影，本课下一节把缩影扩到八段。

🏭 工业对照：shell 链 vs 训练平台

工业界的"一条命令"长在训练平台里：DAG（有向无环图，节点按依赖自动排序的流水线描述）调度、 每节点独立重试、实验追踪（MLflow/W&B）、数据版本（DVC）。reborn 用 20 行 shell + 命名约定 + resume 达到同构的最小实现——形状相同，规模不同。你在本课程练的不是"用平台"， 而是平台替你做的那件事本身：把多阶段依赖写成可断点、可审计、可重跑的东西。

🎮 全量链路的真实刻度（无 GPU 走读档路线）：[存档 runs/pretrain_full/20260925_005504 · runs/sft_full/20260925_075941 · runs/dpo_full/20260925_191632 · 2×RTX 4090 DDP · bf16 · seed=42] 三段 run 档案的首尾时间戳相减：pretrain 7 小时 04 分 + SFT 11 小时 17 分 + DPO 4 分 18 秒 ≈ 18.5 小时；docs 的开工前估算口径为 20.5 小时（pretrain 8.1h + SFT 12.4h + DPO 5min， [存档 docs/pretrain_readiness.md:60]）。有意思的是 DPO 段只有 4 分钟——偏好数据只有 53MB、 单 epoch：对齐（alignment）阶段在工业界同样是三段里最便宜的一段，贵的是教它说话（pretrain） 和教它好好说话（SFT）。主线不追这个量级：八范式冒烟用同一形状的 tiny 配方，几分钟跑完全部八段。

但"全量测试"这件事本身，本课挖到一个新坑——毕业课的最后一次现场排雷：

⚠️ 坑卡：make test 五个失败——测试环境改写了被测系统
  • 症状：按 README 跑 make test，输出 5 failed, 80 passed； 失败的五个全是 metrics/observability 一族（test_unknown_metric_backend_raises、 test_dual_backend_jsonl_and_tensorboard、test_tensorboard_events_in_subdir_only、 test_metrics_steps_monotonic_and_unified、test_full_chain_train_save_resume_generate）。 而上一条终端里同参数的裸 pytest 是 85 全绿。
  • 原因：Makefile 的 test 目标给命令前置了 MINIMIND_REBORN_METRICS_DISABLED=1（README 说的"强制离线、禁云端上报"纪律）。 这个进程级开关会让 build_backends 把一切指标后端替换成 null（测试输出里那行 WARNING "全部指标后端替换为 null" 就是自白）。五个失败测试测的恰是后端本身—— 被测对象被测试环境改写了。"离线纪律"与"测后端"两条正当需求在这里真实冲突。
  • 解法：全量验收用不带环境变量的 uv run python -m pytest tests/ -m "not slow" -q （本课验收块如此）；想离线跑训练再补 MINIMIND_REBORN_METRICS_DISABLED=1。 make test 的 $(PYTEST_ARGS) 只能追加 pytest 参数、去不掉前置的环境变量—— 若要 make test 复绿，需把"离线"改为 pytest fixture 或 skipif 条件（改仓库属上游决策，课程只读）。

这个坑与本课主题严丝合缝：被测系统会读环境开关时，环境本身就是变量—— 单变量对照的控制清单里必须包含它。你在毕业实验里会再遇到这句话。

毕业实验：从弱项清单到一个结论

全课唯一的新概念，也是最后一件行李。研究迭代闭环：

💡 直觉：闭环的每一步都在防一件事

假设防"乱试"（先说清你相信什么、为什么）；单变量对照防"归因错误" （只动一个旋钮，其余全部冻结——自变量是你动的那个，因变量是你量的那个， 控制变量是冻住的一切，包括环境）；结论防"数据白产"（说清方向、幅度、边界—— 几个样本、什么权重、什么题目）。而"闭环"的意思是：结论几乎总会暴露新的弱项或设计缺陷， 于是回到起点再跑一圈。M21 已经示范过一圈（era1→era2 召回率 16.7%→50%）； 下面从 M21 的弱项清单里选四个可执行的选题，然后真做一个。

选题清单：四个可执行的假设

选题自变量因变量控制变量（冻结）预期
① 系统消息注入率SFT 的 add_system_ratio 0.2→0.5（M12 数据旋钮，默认 0.2）固定 8 题输出质量 + val loss数据/步数/lr/seed/权重结构注入更多 system 前缀会提升指令遵循的稳定性，但 val loss 略升（模板噪声多了）

③ YaRN 外推边界推理侧 YaRN 开/关（factor=6，M05 折叠卡）1536/2048 tok 的重复率与在题率权重、题目、贪心解码（每步取最高分 token 的确定性解码，M21 变式练过）——直接用 M21 存档YaRN 只救急不治本：1536 以上重复率仍崩（存档 0.842/0.980）

选②当示范的理由：零训练、单脚本、两分钟出数据，且直接接 M21 弱项清单的第三条 （"贪心复读循环 → 对比采样温度作为复读抑制剂"）。四步模板完整走一遍。

第一步 · 假设

同一权重、同一批题，把采样温度从 0.7 升到 0.85：回答的多样性会上升 （distinct-2 变大——复读变轻）。次级猜测：更高的温度可能让回答更长（更"敢说"）。 注意把猜测拆成"有把握的"（多样性，采样数学直接支持）与"没把握的"（长度，纯直觉）—— 实验设计时对两者都要安排测量。

第二步 · 设计（单变量 + 控制清单）

/tmp/m22_temp_ab3.py · 温度 A/B（终版，28 行）python
import torch
from minimind_reborn.configuration.schemas import GenerateConfig
from minimind_reborn.inference.engine import MiniMindLLM

PROMPTS = ["你有什么特长？", "为什么天空是蓝色的", "请用Python写一个计算斐波那契数列的函数",
           "推荐一些中国的美食"]  # 节选 4/8 题（页面版；实跑用 M21 eval_llm.py 全部 8 题）

def distinct2(text: str) -> float:
    """distinct-2：不重复 bigram 占比。复读越重值越低，全新搭配=1.0。"""
    chs = list(text)
    grams = [tuple(chs[i:i+2]) for i in range(len(chs)-1)]   # 相邻二字组
    return len(set(grams)) / len(grams) if grams else 1.0

llm = MiniMindLLM.build("full_sft")          # 控制变量①：两臂同一权重同一实例
for t in (0.7, 0.85):                        # 自变量：唯一的旋钮
    for seed in (42, 43, 44):                # 控制变量②：两臂共用同一组随机种子
        torch.manual_seed(seed)              # 固定随机数发生器起点：本臂重跑可复现
        gen = GenerateConfig(temperature=t, top_p=0.95, max_new_tokens=384)  # top_p：M02 的核采样旋钮，冻结
        lens, d2, stops = [], [], 0
        for p in PROMPTS:
            r = llm.generate_text([{"role": "user", "content": p}], gen)
            lens.append(r["generated_tokens"]); d2.append(distinct2(r["content"]))
            stops += r["finish_reason"] == "stop"
        print(f"T={t} seed={seed}: distinct2={sum(d2)/len(PROMPTS):.4f} "
              f"len={sum(lens)/len(PROMPTS):.1f} stop={stops}/{len(PROMPTS)}")

设计不是一次成的——第一版 max_new_tokens=256 就被数据打回来了：8 题里 15/16 跑满上限 （finish=length），长度这个因变量被测量天花板压死，根本分不出两臂。把上限提到 384 重跑， stop 开始出现（这是闭环的第一次转圈：数据暴露设计缺陷 → 改设计 → 重跑）。 第一版留下的有效读数只有一个：distinct-2 均值 0.582（T=0.7）vs 0.650（T=0.85），方向与预期一致。

第四步 · 结论（含边界）

结论一（有数据支撑的主结论）：同一权重同一题集，温度 0.7→0.85 让回答多样性稳定上升 （distinct-2 +0.050，且 42/43/44 三个 seed 逐对全升，不是单一幸运样本）——支持 M21 弱项清单 "采样温度可作复读抑制剂"的假设。结论二（猜错的部分，同样值钱）：回答反而更短、更常说完即停。 机制：温度把整个分布拉平，EOS（end of sequence，结束符——模型给出它即停止生成，M03 的 im_end） 与句读这类"低概率但合理"的 token 也被托举上来，序列更容易自然收尾；话痨的根源在权重—— M21 弱项清单第一列的"美食题 28 项列表跑满 256 tok"，不在温度。 边界：n=3 个 seed、单一权重、8 道题；distinct-2 量的是多样性不是质量—— "更发散"不等于"更好"：质量的判定需要裁判模型（LLM-as-judge：用更强的模型给输出打分）或人工， 而 M21 的三把尺都明说过自己"看不见对错"。 下一个假设已经写在桌上：repetition_penalty（M20 采样链的旋钮）与温度对复读的作用能否分离？

📐 为什么必须单变量

若同时改 temperature 与 top_p，两臂差异便无法归因——两个旋钮都在改分布形状， 观察到的任何变化都是混合效应。形式化地说：设观察差异 Δ = f(T 变化) + g(p 变化) + 噪声， 单变量设计让 g 严格为 0，Δ 才可归因；多变量同时动的"实验"只是两次改动， 不是一次对照。同理，种子与温度的顺序（先固定 seed 组再切温度臂）保证了噪声项在两臂间对称。 这条纪律对训练实验同样成立——选题④若同时改 rank 与 lr，得出的任何 loss 差异都没有主人。

测验 1 · 全链路为什么要一条命令？run_full.sh 为什么对数据下载 fail-fast，对三个训练段却只记 exit 码不停链？

答案：一条命令的价值是无人值守的原子性：全链 18 小时级，靠 nohup 挂后台、各段独立日志、resume 默认开启（断了重跑接着来），并且它本身就是"三份配置的命名与依赖真的咬合"的最终测试。数据下载 fail-fast 是因为没有数据后面全是白等，当场死最便宜；训练段不停链是因为下一棒自带守门人——init_from 走 strict 加载，上一棒产物有问题会在下一棒启动前一秒炸出来，MARKER 里的 exit= 行保留完整现场供对账。

答错回看：run_full.sh 精读 与 产物衔接表。

测验 2 · 单变量对照为什么必须？如果示范实验同时改 temperature 和 top_p，结论会发生什么？

答案：观察差异 Δ = f(改动甲) + g(改动乙) + 噪声；单变量设计让 g 严格为 0，Δ 才能归因给甲。若同时改温度与 top_p（两个都在改采样分布的形状），看到 distinct-2 上升你无法知道是温度的功劳还是 top_p 放宽的功劳——得到的是"两次改动"的混合效应，不是一次对照。同理，示范实验让两臂共用同一组 seed、同一权重实例、同一题集，就是为了让噪声项在两臂间对称。

答错回看：第二步 · 设计 与 直觉卡、📐 卡。

测验 3 · 开放题：85 个测试里，你印象最深的一个是哪个？为什么是它？

参考答案（任选其一，说得出"它锁住什么行为"即可）： ① test_rope_buffer_rebuild_after_meta_init——M09 猎场的回归锁：非持久 buffer 在 meta 初始化下责任真空，模型用"全零判据 + 重算重注册"自我兜底，测试保证这层兜底永远在； ② test_full_chain_train_save_resume_generate——M01 冒烟链的测试化身，一条测试锁住"训练→保存→续训→生成"整条链，是"绿灯担保什么"的最佳样本（也在 make test 坑卡里当过受害者）； ③ loss_mask 系列——M12 填空时你手写过它的核心逻辑，全系统最脆的一格有测试盯着。 共同点：好测试锁的是行为契约而不是实现细节——实现可以换，契约破了必须有人知道。

测验 4 · make test 的五个失败是怎么来的？这个坑和毕业实验的方法论有什么关系？

答案：Makefile 给 pytest 前置了 MINIMIND_REBORN_METRICS_DISABLED=1（离线纪律、禁云端上报），该开关把 build_backends 的所有指标后端替换成 null；五个失败测试测的恰是后端本身——被测对象被测试环境改写了，裸跑同参数 pytest 则 85 全绿。与方法论的关系：当被测系统会读取环境开关时，环境就是自变量/控制变量清单的一部分——"冻结其他一切"必须包括环境，否则你的对照实验在另一台机器上不可复现。

答错回看：坑卡：测试环境改写了被测系统。

毕业实验报告模板（照此四步填）text

② 设计：自变量 ___（唯一）；因变量 ___（怎么量：命令/指标名）

什么算"合格"？（先动手再看）

合格线与示范同规格：每个数字可溯源（命令可重跑、输出是原始的）、 结论有边界声明（n 多少、什么权重、什么范围成立）、至少一个反直觉或猜错的发现 （示范里是"升温反而更短"——猜错不是失败，是没有被数据骗着走）。两份存档做对照的选题③， 合格线是写清两份档的"控制变量"哪些真的相同（同权重？同题？同解码？）—— 读档分析也要过设计这一关。若你的结论与预期完全一致且毫无曲折， 大概率是因变量选得太迟钝（回忆示范第一版的长度天花板）——换更灵敏的尺再跑一圈，闭环本来就是圈的。

本课词汇

研究迭代闭环 research iteration loop
弱项清单 → 假设 → 单变量对照设计 → 数据 → 结论（含边界）→ 新弱项，回到起点再跑一圈。本课唯一新概念，也是全课程的方法论收束：评测的终点不是分数，是下一圈的假设（M21）。
单变量对照实验 controlled experiment
只动一个旋钮（自变量）、只量约定的指标（因变量）、冻结其余一切（控制变量——含随机种子与环境变量）的实验设计。多变量同时动得到的只是混合效应，无法归因。
自变量 / 因变量 / 控制变量 independent / dependent / controlled variables
对照实验三角色：动的那个、量的那个、冻住的一切。示范实验里分别是 temperature、distinct-2 等四指标、权重/top_p/max_new_tokens/题集/seed 组。
distinct-2
多样性的自动指标：文本中不重复相邻二字组（bigram）占全部 bigram 的比例，复读越重越低。便宜可全自动，但量的是"多样"不是"对错"（M21 三把尺里的第一把）。
天花板效应 ceiling effect
因变量被测量上限截断而失去区分力的现象：示范第一版 max_new_tokens=256 时 15/16 题跑满 finish=length，长度分不出两臂。对策是抬高上限重跑——设计缺陷由数据暴露，也是闭环的一圈。
随机种子 random seed
随机数发生器的起点：固定它，同一命令重跑得到同一序列（采样可复现）。示范实验每臂前 torch.manual_seed(seed)，两臂共用同一组 seed 让噪声对称；M21 弱项清单里"eval_llm 不设种子"就是它的缺席。
fail-fast 快速失败
越早暴露不可恢复的错误越便宜的纪律。run_full.sh 对数据下载用 || exit 1 当场死；训练段则交棒给下一棒的 strict 加载守门——两种失败策略各配一种依赖关系。
全链路脚本 run_full.sh
20 行 shell 串起 download→pretrain→SFT→DPO：nohup 无人值守、各段独立日志、MARKER 记 exit 码、resume 默认开断点重跑。工业界同构物是训练平台的 DAG 流水线。
