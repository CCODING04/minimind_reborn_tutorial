Attention：GQA、QK-Norm 与三条路径

M06 的 KV cache 让"每步只算新 token"成为可能，真正允许它这么干的是⑤站核心零件 attention： 只对历史列查询、挡住未来、无视 padding。这一课把它整个拆开——手算 Q/K/V 检索、GQA 砍半 KV cache （回收 M04 的整除伏笔）、QK-Norm 踩刹车，再精读同一语义下的三条执行路径并亲手证明等价。

Q/K/V：先把注意力当一次检索

注意力（attention）要解决的问题是：生成第 $t$ 个 token 时，前文 $t$ 个 token 各自该贡献多少。最直觉的模型是一次检索：

💡 概念卡：Q/K/V = 查询 / 索引 / 内容

把每个 token 想成图书馆里的一本书：K（Key，索引）是书脊标签，V（Value，内容）是正文， Q（Query，查询）是你想找的主题。当前 token 拿 Q 与每个位置的 K 比对得分数，经 softmax（把一组分数变成和为 1 的概率） 变成权重，再按权重把各位置的 V 加权求和——这就是它"读完全文后"的新表示： $$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$ 多头（multi-head）是同一件事做 8 遍：把 hidden 768 切成 8 份 head_dim=96（M04 的派生参数），各自独立检索再拼接—— 8 个头学会关注不同关系（指代、邻近、语法……）。

手算：4 个 token，一个头，数字真算

取「春 天 来 了」，1 个头，head_dim $d=4$，q/k/v 全部手写；V 特意用 one-hot（只有自己那位是 1）—— 加权求和的结果就直接等于权重本身。看「了」这一行（它能看到全部 4 个位置）：

📐 严谨卡：为什么要除以 $\sqrt{d}$？

两个各维独立、零均值、单位方差的随机向量点积，期望 0、方差恰为 $d$——维度越高打分越容易跑出 $\pm 3\sqrt{d}$。 $d=96$ 时不缩放打分动辄 $\pm 30$，softmax 里 $e^{30}\approx 10^{13}$，分布直接坍缩成 one-hot （训练早期等于随机挑一个 token 全信，梯度近乎为零）。除以 $\sqrt{d}$ 把方差拉回 1，让"softmax 真的在比较"—— 这与 QK-Norm 是同一条纪律的两个层次，后者连范数漂移一起管（见下文）。

进代码前固定记号——本课 shape 注释全程用 (B, H, T, D)（批 / 头数 / 序列长 / 头维度）。64M 配置下的主干变换：x (B, T, 768) → 投影 xq (B, T, 8, 96)、xk/xv (B, T, 4, 96) → 转置复制 (B, 8, T/total, 96) → 打分 scores (B, 8, T, total)（total = 历史列 + 新列，M06 的游标语义）。

GQA：8 个 Q 头共享 4 组 KV

上表里藏着一个不对称：Q 有 8 个头，K/V 却只有 4 组。这就是 GQA（Grouped-Query Attention， 分组查询注意力）：不是每个 Q 头配一套自己的 K/V，而是每 2 个 Q 头共用一组 KV。 为什么值得？回到 M06 的显存账——KV cache 缓存的是每个 token 的 K 和 V：

src/minimind_reborn/models/attention.py · __init__ 头数与投影（节选）python
self.num_kv_heads = config.num_key_value_heads        # 4：KV 组数
self.num_heads = config.num_attention_heads           # 8：Q 头数
self.n_rep = self.num_heads // self.num_kv_heads      # 8 // 4 = 2：每组 KV 服务 2 个 Q 头
self.head_dim = config.head_dim                       # 96（M04 派生：768 // 8）
self.q_proj = nn.Linear(config.hidden_size, self.num_heads * self.head_dim, bias=False)     # 768→768
self.k_proj = nn.Linear(config.hidden_size, self.num_kv_heads * self.head_dim, bias=False)  # 768→384
self.v_proj = nn.Linear(config.hidden_size, self.num_kv_heads * self.head_dim, bias=False)  # 768→384
self.q_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)   # QK-Norm 专用（下节）
self.k_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)

KV 头数减半，两头账单同时缩水：K/V 投影参数从 768×768 变 768×384（每层省约 59 万 ×2）；推理时 KV cache 每 token 只存 4 组—— M06 那本账的关键一行，本课把数字算实： 

   Q 头（8 个，各自独立计算）          KV 组（4 组，被共享）
     q0 ─────────────────► ◆ kv0 ◄───────────── q1      n_rep = 2：
     q2 ─────────────────► ◆ kv1 ◄───────────── q3        相邻两个 Q 头
     q4 ─────────────────► ◆ kv2 ◄───────────── q5        共享同一组 KV
     q6 ─────────────────► ◆ kv3 ◄───────────── q7

   repeat_kv(n_rep=2) 之后的 KV 列序：kv0 kv0 kv1 kv1 kv2 kv2 kv3 kv3 —— 8 列对齐 8 个 Q 头

共享是"相邻成对"：q0/q1 挂 kv0，q2/q3 挂 kv1，以此类推。扩张由一个 7 行的函数完成：

src/minimind_reborn/models/layers.py · repeat_kv 全文python
def repeat_kv(x: torch.Tensor, n_rep: int) -> torch.Tensor:
    """GQA：把 kv 头复制 n_rep 份对齐 q 头数。
    x: (b, seq, kv_heads, head_dim) → (b, seq, kv_heads·n_rep, head_dim)；n_rep=1 原样返回。
    """
    batch, seq_len, kv_heads, head_dim = x.shape
    if n_rep == 1:
        return x
    return (
        x[:, :, :, None, :]                                  # (b, seq, kv, 1, d) 先插一维
        .expand(batch, seq_len, kv_heads, n_rep, head_dim)   # 广播出 n_rep 份（零拷贝）
        .reshape(batch, seq_len, kv_heads * n_rep, head_dim) # 摊平成 4×2=8 个头
    )

expand 是零拷贝广播、reshape 才落盘——摊平不是"真复制 8 份"，成本很低。代价照付的地方在显存账：

结构kv_heads（n_rep）每 token KV cache2048 token32768 token（max_seq）
GQA（reborn 默认）4（n_rep=2）2×8层×4×96×2B = 12 KB24 MB384 MB
MHA（无共享）8（n_rep=1）24 KB48 MB768 MB

[作者实测 · 2026-09-30 · 2×RTX 4090 · torch 2.14.0+cu130] 公式 $2(K{+}V)\times 8\text{层}\times kv\text{头}\times 96\times 2\text{B(fp16)}$；并用 KVCache(8, 1, 32768, kv, 96, fp16) 真分配核对：k+v 合计 384 MB（kv=4）/ 768 MB（kv=8）。M06 讲过的预分配账，GQA 直接把基数砍半。

回收 M04 伏笔：整除约束为什么是硬的

M04 守门人那条 num_attention_heads % num_key_value_heads == 0（GQA 约束）此刻兑现：它硬在 repeat_kv 最后一行——reshape 目标头数是 kv_heads × n_rep，而 n_rep = num_heads // num_kv_heads 是整除截断。若 8 Q 头配 3 组 KV：n_rep = 8 // 3 = 2， reshape 得 6 个 KV 头 ≠ 8 个 Q 头——错误要拖到运行期第一次矩阵乘才爆：

k = repeat_kv(torch.randn(1, 5, 3, 96), 8 // 3)   # 3 组 KV，n_rep=8//3=2 → 只摊平出 6 头
print('repeat 后 kv 头数 =', k.shape[2])
q.transpose(1, 2) @ k.transpose(1, 2).transpose(-2, -1)"
repeat 后 kv 头数 = 6

[作者实测 · 2026-09-30] M04 变式 2 已在装配期见过守门人版本：ValueError: num_attention_heads(7) 必须被 num_key_value_heads(2) 整除（GQA 约束）。同一种错：M04 拦在训练开始前一秒，这里是没守门人时它在运行期的样子——深处、难懂、晚好几拍。"除不尽就没有分组方案"不是数学洁癖，是 reshape 对不上 shape。

🏭 工业对照：GQA 是 MHA 与 MQA 的折中

频谱两端：MHA（每 Q 头独享 KV，质量最好、cache 最贵）与 MQA（全部 Q 头共享 1 组 KV，最省但质量明显掉）。 GQA 取中间档：Llama 2 70B、Llama 3、Qwen 系均采用；reborn 8Q/4KV 与官方 minimind 同构——M09 官方权重 strict 互通 靠的就是形状逐键一致。KV 头数既是推理成本的旋钮，也是权重形状的一部分，定了就锁死。

QK-Norm：进 RoPE 之前先踩一脚刹车

__init__ 里那两行 q_norm / k_norm 是本课第二个新概念。QK-Norm：对 q、k 各做一次 RMSNorm（M05 读过的实现：fp32 归一化、type_as 回落），作用维度是 head_dim——每个头、每个位置各自归一，然后才进 RoPE：

src/minimind_reborn/models/attention.py · forward 前置段（节选）python
xq = self.q_proj(x).view(bsz, seq_len, self.num_heads, self.head_dim)      # (B, T, 8, 96)
xk = self.k_proj(x).view(bsz, seq_len, self.num_kv_heads, self.head_dim)   # (B, T, 4, 96)
xv = self.v_proj(x).view(bsz, seq_len, self.num_kv_heads, self.head_dim)   # (B, T, 4, 96)
xq, xk = self.q_norm(xq), self.k_norm(xk)     # QK-Norm：每个头内、head_dim 维踩刹车
cos, sin = position_embeddings
xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)   # RoPE（M05）：转的是"位置"，v 不转

为什么需要？打分 $s = q\cdot k / \sqrt{d}$，由柯西–施瓦茨不等式 $|q\cdot k| \le \|q\|\|k\|$——量级被 q、k 的范数直接放大。 训练中范数若不受控漂移，logits 爆炸、softmax 坍缩成 one-hot、注意力锁死在单点、梯度近乎消失。实测一笔账（head_dim=96，权重默认全 1）：

q/k 状态缩放后 logit 最大值后果
随机初始化（σ=1）3.86健康：softmax 还有分布形状
范数漂移（σ=3）34.29$e^{34}\approx 10^{15}$：softmax 完全饱和成 one-hot
RMSNorm 之后3.51无论输入范数多大，$\|q\|\|k\|=d$ 封顶 → logit $\le\sqrt{96}\approx 9.8$

[作者实测 · 2026-09-30 · 2×RTX 4090 · torch 2.14.0+cu130] 5000 对随机 q/k 的 $|q\cdot k|/\sqrt{96}$ 统计；RMSNorm 后每向量 RMS=1（$\|v\|=\sqrt{96}$），柯西–施瓦茨给出硬上界 96，缩放后 $\approx 9.8$。weight 是可学习逐维增益——模型仍能按需放大，但放大被参数显式控制，不再随范数漂移。

两个易错点：位置——norm 在 RoPE 之前，先把范数钉死、再旋转位置；放 RoPE 后，旋转/YaRN 缩放引入的范数变化会跟归一化打架。维度——是 head_dim（头内）而非 hidden_size：8 个头的分布各自稳，不做跨头平均。实现直接复用 layers.py 的 RMSNorm（M05 的"敏感算子纪律"原样生效：fp32 归一化、type_as 回落）。

🏭 工业对照：QK-Norm 已是现代标配

ViT-22B 论文（Dehghani 等，2023）把 q/k 归一化带进主流，Qwen3、Gemma 3 同款采用。小模型尤其需要： 数据少、训练短，范数漂移没有机会被海量数据磨平，一个不稳的头就能拖垮 loss 曲线——64M 的小模型选它是"小更要稳"的典型决策。

三条执行路径：一份语义，三台发动机

前置段算完 q/k/v，forward 下半场是本课主体：同一套注意力语义（GQA + QK-Norm + RoPE + 因果 + pad 抑制）有三个实现， 按序判定、择一执行——训练全段、推理带 cache、没有融合算子的老环境，各自的最优发动机不同：

"物化"（materialize）指真的把中间矩阵写进显存——③会把整个 $T\times total$ 打分矩阵摆上台面；①②的融合 kernel （GPU 上一次调用执行的计算单元，SDPA 内部自动在 flash / memory-efficient / math 后端里挑）分块在片上算完，从不完整落盘。 SDPA 指 torch.nn.functional.scaled_dot_product_attention（PyTorch 2.0 起内置）； sdpa_available() 用 hasattr 探测一次、全项目复用。

路径①：SDPA is_causal——训练全段

条件最苛刻（无 cache、无 pad），语义也最简单——因果下三角直接交给算子的 is_causal 开关：

src/minimind_reborn/models/attention.py · 路径①（节选）python
output = F.scaled_dot_product_attention(

路径②：SDPA + 显式 mask + cache——prefill / decode

带 cache 时不能用 is_causal：它假设 query 与 key 等长对齐，而 decode 步只有 1 个新 query、 却面对 total 个 key——causal 语义变成"历史列全部可见，因果限制只落在新块内部"。所以改喂显式 加性 mask（additive mask：加到打分上的矩阵，$-\infty$ 的位置 softmax 后权重为 0）：

src/minimind_reborn/models/attention.py · 路径② mask 构造（节选）python
total_len = cache_start + seq_len
neg_min = torch.finfo(xq.dtype).min                    # 精度下限（fp16/fp32 各自取，防下溢）
mask = torch.zeros(bsz, 1, seq_len, total_len, device=xq.device, dtype=xq.dtype)  # (B,1,T,total)
if seq_len > 1:                                        # decode 步 seq=1：新块只有 1 列，无块内因果
    causal = torch.zeros(seq_len, total_len, device=xq.device, dtype=xq.dtype)
    causal[:, cache_start:] = torch.full(              # 只在"新块列"上放因果墙：
        (seq_len, seq_len), neg_min, device=xq.device, dtype=xq.dtype
    ).triu(1)                                          # 上三角（含偏移1）= 屏蔽"块内未来"
    mask = mask + causal                               # 历史列全 0 = 全可见
if attention_mask is not None:                         # pad 列抑制（0 的列整列封死）
    mask = mask.masked_fill(attention_mask[:, None, None, :total_len] == 0, neg_min)
output = F.scaled_dot_product_attention(
    xq, xk_full, xv_full, dropout_p=self.dropout if self.training else 0.0, attn_mask=mask
)

三处讲究：triu(1)——上三角跳过对角线，第 $i$ 行屏蔽块内第 $i{+}2$ 列起的"未来"而保留自己；偏移写 1 不是 0， 就是源码注释里的 off-by-one（差一位）杀手位：写 0 连"自己看自己"都屏蔽，行内全 $-\infty$，softmax 出 NaN。 masked_fill 而非加法——pad 列用"覆盖"：若在已有因果墙的格子上再 + 一个下限值，fp16 下两下限相加会 下溢翻转成 $+\infty$，掩码变通道。形状 (B,1,T,total)——中间两个 1 广播到 8 头：pad 是序列级事实，不按头区分。

路径③：手动显式打分——fp32 数值基线

flash_attn=False 或无 SDPA 环境的回退路径，也是理解①②的"参考实现"——所有语义摊开在矩阵上，可打印、可手算 （开头的手算例子就是它的缩小版）：

src/minimind_reborn/models/attention.py · 路径③（节选）python
scores = (xq @ xk_full.transpose(-2, -1)).float() / math.sqrt(self.head_dim)  # (B,8,T,total) 升 fp32
if self.is_causal:
    # 与路径②同一论证：因果墙只作用于"当前步的新位置块"（最后 seq_len 列），历史列全可见
    scores[:, :, :, -seq_len:] += torch.full((seq_len, seq_len), float("-inf"), device=scores.device).triu(1)
if attention_mask is not None:
    scores += (1.0 - attention_mask.unsqueeze(1).unsqueeze(2).to(scores.dtype)) * -1e9  # pad 加性抑制
output = self.attn_dropout(F.softmax(scores, dim=-1).type_as(xq)) @ xv_full  # softmax 后回落精度

与②的两处对照：③ 的因果墙用切片 [:, :, :, -seq_len:] 落位（②用 causal[:, cache_start:]——同一个"最后 seq_len 列"，两种写法）； ③ 的 pad 抑制用加性 $-10^9$ 而非覆盖——fp32 打分不怕下溢。数值纪律是 M05 纪律的延伸：打分升 fp32、softmax 后 type_as 回落—— softmax 的指数与除法在半精度下最易失真，升精度算、算完回落。

⚠️ 坑卡：mask 忘了 pad 列——泄漏不在 prefill，在下一步
  • 右 padding 批次（M06 的 rollout / 批量对话）里喂了带 pad 的 input_ids 却没传 attention_mask：prefill 期"看起来没事"，若干步后输出渐渐跑偏，无任何报错。
  • prefill 期因果 mask 恰好挡住 pad 列（pad 在未来），有效位置毫发无损——这正是它阴险之处；但 pad 位置的 K/V 已写进 cache。decode 步一来，pad 列变成"过去"，因果墙不再挡——垃圾 K/V 从此混进每次加权求和。实测（tiny 模型）：丢 mask 后 pad 位 logits 漂移 max|Δ|=0.0425、首个 decode 步偏差 7e-4——随机权重下数字不大，但"逐位一致"的契约已破。
  • mask 跟着 input_ids 走：model(x, attention_mask=mask, past_key_values=cache)，pad 列在②被 masked_fill 封死、在③被 $-10^9$ 压平。回归锁定是 test_sdpa_prefill_path_matches_manual 的第三个断言（padding mask 下双路径 allclose）——mask 语义错了，等价性测试立刻红。
📐 严谨卡：fp16 下双路径分叉是预期，契约以 fp32 为准

模块 docstring 写明："fp16 双路径贪心分叉属预期浮点行为：数值验证以 fp32 为准"——①②的融合 kernel 与③的显式矩阵乘 浮点归约顺序不同，半精度末位差异会被自回归逐 token 放大，贪心 top1 可能分道扬镳，这不是 bug。作者实测 tiny 模型 fp16 ①vs③： 12 个种子 max|Δ| 均为 4.9e-4、top1 未分叉（2 层小模型太宽容）；fp32 下 max|Δ|≈9e-8（float32 舍入极限量级）、argmax 全等—— 所以一切等价性断言都跑在 fp32。

检验一下

测验 1 · GQA 省的到底是哪份账？Q 投影省不省？

答案：两份账都省：KV cache（随序列线性涨的推理显存）按 kv_heads 比例砍半——12 对 24 KB/token，32768 token 时 384 对 768MB；K/V 投影参数（768→384）也减半。但 Q 投影不省——8 个 Q 头一个不少（768→768），Q×K^T、softmax×V 的计算量主体也不省：GQA 只共享"存"，不共享"算"的查询侧。

答错回看：GQA：8 个 Q 头共享 4 组 KV 的 __init__ 代码与显存账表。

测验 2 · 8 个 Q 头配 3 组 KV，为什么守门人要在装配期拦，而不是让代码跑到哪算哪？

答案：因为 n_rep = 8 // 3 = 2 是整除截断，reshape 只能摊平出 3×2=6 个 KV 头，对不上 8 个 Q 头——错误必然发生，但发生点在运行期深处的矩阵乘（The size of tensor a (8) must match ... b (6)），又深又晚；守门人把它提前到训练开始前一秒，报错还自带 8 和 3 两个数字。整除不是数学洁癖，是 reshape 能否对齐 shape 的硬前提。

答错回看：回收 M04 伏笔：整除约束为什么是硬的 的终端复现。

测验 3 · QK-Norm 作用在哪个维度、为什么必须在 RoPE 之前？

答案：作用在 head_dim（每个头内、每个位置各自 RMSNorm），不是 hidden_size——8 个头的分布各自稳，不跨头平均。放 RoPE 之前，是因为它管范数（$q\cdot k\le\|q\|\|k\|$，范数不控则 logits 爆、softmax 饱和、梯度消失）：先把范数钉死在 $\sqrt{d}$，再让 RoPE 只改"方向"（位置）；放 RoPE 后，旋转/YaRN 缩放引入的范数变化会与归一化互相拆台。

答错回看：QK-Norm：进 RoPE 之前先踩一脚刹车 的量级对照表。

测验 4 · 三条路径各自的触发条件是什么？一台没有 SDPA 的老机器上，reborn 还能跑吗？

答案：① flash ✓ 且无 cache 且 mask 全 1（训练全段）；② flash ✓ 且带 cache 或有 padding（prefill/decode、rollout）；③ flash ✗——flash_attn=False 或 sdpa_available() 探测不到算子。老机器上 hasattr(F, "scaled_dot_product_attention") 为假 → self.flash=False → 一律走③：能跑，只是慢、长上下文显存高（物化 fp32 打分矩阵）。③不是死代码，是可移植性兜底 + 数值基线。

答错回看：三条执行路径 的分派代码与条件表。

观察结果与解释（先动手再看）

观察（作者实测）：kv_heads=4: k+v 合计 384 MB、kv_heads=8: k+v 合计 768 MB——翻倍。

机制：KV cache 字节随 kv_heads 线性增长（$2\times 8\text{层}\times kv\times 96\times 2$B），n_rep=1 只是共享系数归一， 存储没有免费午餐；但 repeat_kv 第一行 if n_rep == 1: return x 原样返回——连零拷贝扩张都省了， 省的是计算不是显存。K/V 投影参数同样翻倍（768×384→768×768，每层每矩阵多 29 万）。GQA 的交易本质：用"KV 头共享"换推理显存， 代价是表达能力略降；而 M09 官方权重 strict 互通要求形状逐键一致，所以 reborn 锁死 8Q/4KV。

🧪 变式 2 · 两边同时丢掉 padding mask，等价性测试还会绿吗？

坑卡说"mask 忘了 pad 列"很危险。做个思想实验再动手：②③同时不传 attention_mask，双路径还 allclose 吗？（tiny 配置，右 pad 批次）

写下预测：allclose 是 True 还是 False？如果还是 True，说明等价性测试能防住"丢 mask"这个错吗？

观察结果与解释（先动手再看）

观察（作者实测）：带 mask 时 ②vs③ allclose=True；两边同时丢 mask，②vs③ 仍然 allclose=True—— 但相对正确语义，pad 位置的 logits 已漂移 max|Δ|=0.0425。

机制：等价性断言比较的是两台发动机（②与③），不是发动机与正确语义——两边一起改错，它们依然"错得一致"，测试照绿。 所以 padding 场景的回归测试（test_sdpa_prefill_path_matches_manual 第三断言）必须把 mask 作为输入喂进去再比： mask 正确传到两条路径，才是被锁定的行为。通用教训：等价性测试锁"实现之间一致"，语义测试锁"实现与规格一致"—— 两个都要有，坑卡里"prefill 没事、decode 泄漏"那种错只有后者能抓。

✍️ 自写挑战 · B 轨 T3：从零手写 manual 注意力路径

任务书：从空白文件 my_impl/attention.py 开始，手写纯函数 manual_attention(xq, xk, xv, attention_mask=None) -> torch.Tensor（三个输入都已 reshape 到 (b, heads, seq, head_dim)、xk/xv 已含历史）。四步算式：QKT/√d → 因果 mask → softmax → ·V，数值纪律照抄 reborn 路径③（ src/minimind_reborn/models/attention.py 的 manual 分支）：打分升 fp32，softmax 后 .type_as(xq) 回落。GQA 的 kv 头对齐可直接引用 from minimind_reborn.models.layers import repeat_kv—— 本题考注意力本身，不考广播复制。

提示 1 · 方向

因果 mask 只落在"新位置块"：对无 cache 的全段输入，构造 (seq, seq) 的 triu(1) 上三角填 $-\infty$ 加到打分上——第 i 行只许看前 i+1 列； padding 用加性掩码 (1 - mask) * -1e9 广播到 head 维，别把因果的 $-\infty$ 与 pad 的 -1e9 记反。

提示 2 · 表达式级

核心一行：scores = (xq @ xk.transpose(-2, -1)).float() / math.sqrt(head_dim)； 出口一行：out = F.softmax(scores.masked_fill(causal_mask, float("-inf")), dim=-1).type_as(xq) @ xv。

本课词汇

多头注意力 MHA
把 hidden 切成 H 个 head_dim 份并行做注意力再拼接，每个头学一种关注关系；每 Q 头独享一套 KV（n_rep=1）。
Q / K / V Query / Key / Value
注意力三角色：Q=当前 token 的查询，K=各位置的被检索索引，V=真正被取走的内容；打分 $q\cdot k/\sqrt d$ 经 softmax 变权重，对 V 加权求和。
GQA Grouped-Query Attention
分组查询注意力：n_rep 个 Q 头共享一组 KV——KV cache 与 K/V 投影按 kv_heads 缩减，Q 侧不省；Llama 3/Qwen 系标准配置。
n_rep 与 repeat_kv
n_rep = num_heads // num_kv_heads；repeat_kv 把 (B,T,kv,d) 经 expand+reshape 摊平成 (B,T,kv×n_rep,d) 对齐 Q 头——整除约束的落点。
QK-Norm
对 q/k 各做 head_dim 维 RMSNorm 再进 RoPE；把 $\|q\|\|k\|$ 钉在 $d$、打分上界 $\sqrt d$，防范数漂移导致的 softmax 饱和与梯度消失。
SDPA scaled_dot_product_attention
PyTorch 2.0+ 的融合注意力算子，内部自动选 flash/mem-efficient/math 后端，不物化完整打分矩阵；is_causal 或显式 attn_mask 表达掩码。
因果 mask causal mask
第 $i$ 个位置只见前 $i{+}1$ 列的下三角掩码；实现为 triu(1) 的 $-\infty$ 上三角加到打分（加性 mask）上——对角线保留；路径②用 masked_fill 覆盖、路径③加 $-10^9$。
物化 materialize
把中间结果完整写进显存（如路径③的 (B,8,T,total) fp32 打分矩阵）；融合 kernel 分块在片上算、不落盘——显存差异的来源。
等价性断言 equivalence assertion
同权重下比较两条实现输出 allclose 的回归测试；锁"实现之间一致"，不锁"与正确语义一致"（见变式 2）。
