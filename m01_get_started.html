这门课怎么学

📐 先见三个词：pretrain · SFT · DPO

导语里那串箭头是这门课的主线三阶段，先用一句话混个脸熟，后面每篇都会亲手做： pretrain（预训练）＝喂海量文本，学会"文字接龙"——给定前文预测下一个词（M16）； SFT（Supervised Fine-Tuning，监督微调）＝喂问答对话，学会"按对话格式好好回答"（M16）； DPO（Direct Preference Optimization，直接偏好优化）＝喂"好答案 vs 坏答案"的对比，学会"挑更好的那种回答"（M17）。 现在只需记住：三个阶段是接力赛，后一棒吃前一棒的权重——冒烟日志里 DPO 段那句"起点：pretrain_64.pth"说的就是这件事。

这门课只有一个实现目标：Reproduce/minimind_reborn—— 一个 64M 参数中文小模型的工程化全流程训练项目。我们不为你准备"教学专用玩具代码"： 你在课里读的每一行，都在真实仓库里服役；你跑的每一条命令，都是这个项目日常工作流的一部分。

先认识实现目标：minimind_reborn

minimind_reborn 是开源项目 minimind 的工程化重构。64M 参数（hidden 768 × 8 层，词表 6400）， 覆盖八种训练范式与完整推理栈。它和官方版本的关键区别（也是本课程的看点）：

维度官方 minimindminimind_reborn（本课程主线）
配置每个脚本一套 argparse分域 dataclass + YAML 配方 + CLI 覆盖（M04 专讲）
训练范式pretrain/SFT/DPO/LoRA 等8 种：+ 蒸馏、GRPO、PPO、Agent-RL，全部有冒烟配方
测试无85 个（写作时实测）CPU 快速单元测试（验收锚点）
权重—与官方 state_dict 逐键兼容（官方权重可直接加载，M09 验证）
分布式torchrun DDPDDP + no_sync 梯度累积修复（M15 专讲，吞吐提升 31%）

[事实核对] 85 测试（2026-10-01 实测；课程早期记录为 49，随仓库长上下文工作扩容）· 8 冒烟配方 · 64M≈63.91M 参数 · 官方权重 strict 互通——均可在 Reproduce/minimind_reborn/README.md 与 tests/ 目录核对。

官方权重下载（可选但强烈建议）

上面目标对照表里有一条"权重：与官方 state_dict 逐键兼容"——它的意思是： 官方 minimind 训练好的权重可以直接加载进 reborn 模型（M09 🏁A 会用 strict=True 逐键验证这条声明）。 所以不必先训出 64M 模型就能对话、做实验：一条命令把官方的 pretrain 与 full_sft 两份 768 权重请到 out/official/（uv 环境在下一节安装——若还没装，先做下一节的 uv sync --extra dev 再回来执行）：

Shell · 在仓库根目录执行（下载约 138MB，CPU 即可，无需 GPU）bash
uv run huggingface-cli download jingyaogong/minimind-3-pytorch \
    pretrain_768.pth full_sft_768.pth --local-dir out/official/

四件事说在前面：工具哪来的——huggingface-cli 由核心依赖 transformers 自带的 huggingface_hub 提供，uv sync 后即有，无需额外 extras； 文件多大——full_sft_768.pth 约 138MB（fp16）[核对 · HF jingyaogong/minimind-3-pytorch 页面 · 2026-10-06；与 M09 变式"tied 模型 state_dict 逐值求和 68.83M × 2 字节 ≈ 138MB"对账一致]； 国内网络——可先设镜像端点再下载：set HF_ENDPOINT=https://hf-mirror.com（Windows cmd）/ export HF_ENDPOINT=https://hf-mirror.com（bash）； 不想用 hf 工具——直链 curl 亦可（full_sft 示例，pretrain 同理换文件名）： curl -L -o out/official/full_sft_768.pth https://huggingface.co/jingyaogong/minimind-3-pytorch/resolve/main/full_sft_768.pth。

下载完成后文件落位 out/official/pretrain_768.pth 与 out/official/full_sft_768.pth， 后续 M02（对话）、M06（KV cache 对照实验）、M09（🏁A strict 互通）、M20（推理栈）直接使用； 加载推理 CPU 即可，无需 GPU。

没有下载权重也能走完全课程主线（tiny 配方 CPU 可跑），但 M02 的对话体验与 🏁A 里程碑需要它们。

环境准备：uv 与锁定环境

reborn 用 uv 管理依赖—— uv.lock 锁定全部版本，任何人任何时候装出的环境逐位一致。这是可复现性的第一块地基。

Shell · 在仓库任意父目录执行bash

数据就位

训练数据不进 git 仓库，reborn 用一个环境变量告诉代码"数据根目录在哪"： MINIMIND_REBORN_DATA_ROOT（未设置时默认 ~/Code/WorkSpace/minimind-reproduce/dataset， 见 src/minimind_reborn/envs.py）。两种就位方式任选：

方式 A：已有数据目录 → 指过去（加进 ~/.bashrc 持久化）bash
export MINIMIND_REBORN_DATA_ROOT=/path/to/dataset

# 方式 B：从 ModelScope 下载（国内直连）
uv run python tools/download_data.py --name pretrain_t2t_mini
uv run python tools/download_data.py --name sft_t2t_mini
uv run python tools/download_data.py --name dpo_mini
⚠️ 坑卡：数据没就位就开跑？
  • 训练启动时抛出 FileNotFoundError，末行提到一个你从没创建过的路径。
  • MINIMIND_REBORN_DATA_ROOT 未设置或指向的目录里没有该数据集文件。
  • 照报错做即可——reborn 的报错是"三要素"式的（作者实测，值得停下来欣赏）：
FileNotFoundError: 数据集文件不存在：/tmp/nonexistent_data/pretrain_t2t_mini.jsonl
（注册名 'pretrain_t2t_mini'）。请检查 MINIMIND_REBORN_DATA_ROOT
或运行 tools/download_data.py --name pretrain_t2t_mini 从 modelscope 下载

缺什么（文件路径）、叫什么（注册名）、怎么办（两种解法）——一句废话没有。M11 讲数据注册表时你会看到这条消息是怎么生成的。

第一个绿灯：make smoke

万事俱备。现在跑整个课程的第一条核心命令——tiny 模型全链路冒烟： 一个 64 维 2 层的迷你模型（0.53M 参数），把 pretrain→SFT→DPO 三阶段各跑几步，11 秒内验证整条管线无断点。

💡 概念卡：冒烟测试（smoke test）

一句话：用最小的代价验证"整条链路能通"，而不是"每一步都做对"。 词源是电子工程——新电路板第一次通电，先看冒不冒烟，再谈性能。 在 ML 工程里，冒烟 = tiny 模型 + 少量步数 + 全流程串联：数据加载、前向、反向、保存、续训每一环都碰到一下。 它跑得快（秒级），所以你敢在每次改动后都跑一遍——这正是 reborn 把它做成 make smoke 的原因。

逐行读懂这份日志

训练日志是这门课的"第二语言"。拿 pretrain 段的几行做精读：

🏭 工业对照：make smoke 之外

"改完代码跑一遍冒烟"在工业界是提交前的标准动作（常挂进 CI 的 pre-merge job）。 reborn 的 Makefile 把它固化成一条命令，等价于 CI 里跑 pytest -m "not slow" + 冒烟链路。你在本课程里会重复执行它几十次——每次大改动后， 11 秒换一个"管线没断"的确认，极其划算。

📐 概念卡：配方（recipe）

一句话：一个 YAML 文件 = 一个可复现实验，文件名即实验名。 configs/smoke/smoke_pretrain.yaml 只有 8 行——它只写与默认值不同的部分 （tiny 模型尺寸、6 步预算、数据集名），其余超参全部来自代码里的分域默认值。 三条铁律：配方只含差异、CLI --set 可临时覆盖、未知 key 直接报错。 M04 会带你通读整个配置系统——这是 reborn 与官方版本差异最大的一层。

检验一下

测验 1 · pretrain 的初始 loss 为什么是 8.77 左右？

刚初始化的模型对 6400 个词表中"下一个 token 是谁"一无所知。如果它把概率均匀撒给每个词，交叉熵应该是多少？动笔算算，再对照日志。

答案：均匀分布的交叉熵 = ln(6400) ≈ 8.7636，与日志的 8.7871 几乎重合（差值来自随机初始化的不完全均匀）。

机制：交叉熵 $-\sum p_i \log q_i$ 在 $q_i = 1/V$ 时等于 $\log V$。所以"初始 loss ≈ ln(词表大小)"是语言模型的通用体检指标——M09 组装模型后你会用它验证"组装没装错"。

答错回看：逐行读懂这份日志 中 loss 一行。

测验 2 · DPO 段的 loss 为什么从 0.6931 开始？

提示：DPO 起点是刚加载的 pretrain_64.pth，它对"哪个回答更好"还没有任何偏好。0.6931 = ?

答案：0.6931 = ln(2)。DPO 的损失含 $-\log\sigma(\cdot)$ 项；策略（正在被训练的模型）与参考模型（冻结作对照的它自己，M17 详讲）此刻完全相同（还没训练），$\sigma(0)=0.5$，损失恰为 $-\log 0.5 = \ln 2$。

机制："和参考模型一样" = 对 chosen/rejected 五五开 = 猜硬币。M17 推 DPO 公式时这个数字会再次出现，它是所有偏好训练的"零点"。

答错回看：make smoke 的 DPO 段日志 + 实现目标 一节的范式表。

测验 3 · 冒烟测试能证明"模型训练正确"吗？

答案：不能，它只证明链路无断点。tiny 模型 6 步训练的 loss 变化没有任何统计意义。正确性由 85 个单元测试（写作时实测）（形状、不变量、等价性）与验收实验保障，那是后面每个模块的"验收块"在做的事。两种手段互补：冒烟抓"断了"，测试抓"错了"。

答错回看：这门课怎么学 三环节表 + 概念卡：冒烟测试。

变式练习

🧪 变式 · 重跑一次冒烟，会发生什么？

刚才 make smoke 已经在 out/ 留下了 pretrain_64.pth 等产物。 现在不做任何清理，单独重跑 pretrain 冒烟： 

$ uv run python tools/train.py configs/smoke/smoke_pretrain.yaml

写下你的预测：会从头重训 6 步吗？日志会和第一次有何不同？然后执行，重点找两类行：含"恢复/续训"字样的和 step 计数。

观察结果与解释（先动手再看）

作者实测（同环境）：第二次运行没有从零训练——日志出现 RNG 状态已恢复（位精确续训） 与 续训恢复清单：epoch=… step=… optimizer=[…]， step 计数从上次的 6 继续走而不是回到 1。

机制：reborn 的训练器 resume-by-default——只要 checkpoints/ 里有上次的状态 （不只权重，还有优化器、调度器进度、随机数状态），就默认接续。想真从头训练？删掉对应 checkpoint 或 --set train.resume=false。

这是工程化项目与"脚本玩具"的分水岭之一：训练中断（机器宕机、kill -9）后能无损接续。 M14 会拆开那个"六件套 checkpoint"看每一件的作用，还会复现一次 kill -9 续训实验。

🧪 变式 · 用 --set 把步数改成 4
$ uv run python tools/train.py configs/smoke/smoke_pretrain.yaml --set train.max_steps=4

基于上一题的发现预测：这条命令会打印几行 loss 日志？为什么？执行验证。

观察结果与解释（先动手再看）

作者实测：一行 loss 都没有——因为上次已到 step 6，超过 max_steps=4，训练循环直接跳过并只做保存 （达到 max_steps=4 截断，optimizer_steps=0）。 这正是"配方只含差异、状态存在 checkpoint"两个设计叠加出的行为： 配方说你最多走 4 步，而你已经走过了，于是一步都不再走。 想看到 4 步从头训练，需要 --set train.max_steps=4 train.resume=false（或清掉 checkpoint）。

本课词汇

冒烟测试 smoke test
tiny 模型 + 少量步数跑通全链路的快速验证，抓"断了"不抓"错了"。
配方 recipe
一个 YAML 文件 = 一个可复现实验；只写与默认值的差异，文件名即实验名。
绿灯验收
以具体命令输出（测试通过、日志行）为完成标准，而非"读懂了"。
环境指纹 env fingerprint
把 torch/CUDA/seed 等影响可复现性的版本信息写入日志的一条 JSON。
tiny 模型
缩小版模型配置（64 维 2 层，0.53M 参数），供测试与冒烟使用，CPU 可跑。
resume-by-default
检测到 checkpoint（六件套状态）时默认断点续训的行为约定。
MFU model FLOPs utilization
模型算力利用率：实际吞吐折算的 FLOPs ÷ 硬件峰值，M13 详讲。
