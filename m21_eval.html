评测的三把尺

"模型变好了吗"是训练侧最常问也最容易答错的问题。M13 说过 train loss 只能和同口径的自己比， M16 也只是拿它读曲线——要跨模型、跨阶段比较，需要专门的评测指标（本课第一个新概念： 把模型能力压缩成一个可比较的数字的方法）。reborn 的工具箱里躺着三把尺，先把它们摆开：

尺子怎么量量得到量不到（诚实边界）
① 自动指标
困惑度 / 重复率		 对一批固定文本算损失换困惑度；对生成文本数重复片段 "下一个词猜得准不准"（困惑度）、"是否复读"（重复率）——便宜、可全自动、跨模型可比 答案对不对：猜词很准的模型可以满嘴流畅的错话（幻觉，M02 见过），两把指标都看不见
② 固定题集
eval_llm 的 8 题		 同一组问题、同一种子与采样参数，逐题生成并肉眼对照 答题结构、知识性、代码能力、格式——输出可直接阅读比较 题目是"可见"的（可被针对性优化/背题）；8 题样本小，只能定性不能打分
③ 专项套件
多轮 / 长上下文		 构造有唯一正确答案的剧本（召回关键词、长度阶梯、越界输入） 跨轮记忆、长度塌缩点、边界行为——单轮评测的盲区 覆盖面窄：套件外的能力（工具调用、推理链）一概不测

三把尺互补而非互替——下面逐把上手。先把①的换算补齐：困惑度（perplexity，PPL）M16 用 e^loss 换算过一次（$ \mathrm{PPL} = e^{\mathcal{L}} $，"平均在多少个候选词里犹豫"），本课把它升级成 跨模型比较的正式指标：同一批评测文本上算 token 平均交叉熵再取指数，谁低谁的语言建模更准。 ①里的第二位是 n-gram 重复率：把生成文本切成 n 个连续字符的小片（n-gram），数重复的占比——

tools/eval_compare.py · ngram_rep_rate（字符级 3-gram）python
def ngram_rep_rate(text: str, n: int = 3) -> float:
    """字符级 n-gram 重复率：1 - 去重后/总数（0=无重复，1=完全循环）。"""
    cleaned = text.replace(" ", "").replace("\n", "")   # 先去掉空白：排版不算内容重复
    if len(cleaned) < n + 1:
        return 0.0
    grams = [cleaned[i : i + n] for i in range(len(cleaned) - n + 1)]  # 滑窗切 3 字符片
    return 1 - len(set(grams)) / len(grams)             # 去重后占比 ↓ = 重复 ↑

通顺的中文 3-gram 重复率通常在 0.1~0.2（常用词组天然重复），0.4 以上基本是复读循环，1.0 是 完全卡死。它自动、廉价、可量化——本课后面所有"复读了吗"的判断都用它。

📐 严谨：为什么三把尺都替代不了"人看输出"

工业界的完整评测分三层：自动指标（PPL、重复率）→ 客观基准（lm-evaluation-harness 上的 ceval / arc 等选择题集，有唯一答案可自动判分）→ 人工/模型裁判（LLM-as-judge 给开放式回答打分）。 官方 minimind-3 发布时用了第二层（[存档 重构报告 §9.4 · 项目仓库 docs/index.html]：ceval 24.89 / arc 28.49）； reborn 没有接入 harness，本课的三把尺都在第一、三层之间——每个数字都要记得它是哪把尺量出来的， 越界解读（拿 PPL 排名"谁更聪明"）是评测最常见的翻车姿势。

[作者实测 · 2026-10-01 · RTX 4090 · torch 2.14.0+cu130 · T=0.85 · top_p=0.95] 全程 15.2 秒。两个必须交代的实情：①当时 GPU 正被一场并行长训占着（利用率 99%），吞吐绝对值偏低， 专用卡会明显更高——吞吐数字离开负载环境没有意义；②out/full_sft_768.pth 正是那场长训 （runs/sft_full_mt/20261001_010937，多轮增强语料 sft_t2t_mt、训练窗 1536）的中途快照（2026-10-01 10:59 保存，epoch 1 进行到 277k/421k 步）——被测对象是移动靶。旧存档报告里的 full_sft 数字对应更早的 era1 权重（已归档 out/archive/era1/），两者不可混比。诚实标注时间戳，是评测的第一课。

输出本身已经是一张弱项速写：斐波那契题完整正确（代码可运行、示例输出也对）；"天空蓝" 框架对细节错；光合作用题后半段术语崩坏（小模型的典型幻觉：格式完美、内容虚构）；美食题 28 项 编号列表出现成对重复且跑满 256 token（finish=length：被长度上限掐停而不是自己说了 EOS，M20 的停止三重之二）。这些观察先记账，第 6 节会变成假设清单。

⚠️ 坑卡：不固定种子，"分数"会漂——同一命令跑两遍，重复率差 25%
  • 想拿 3-gram 重复率当回归指标，于是把今天和昨天的两次 eval_llm.py 输出各算一个数对比， "从 0.168 恶化到 0.210"——但模型一个字没改。作者实测同一命令背靠背跑两遍（同权重同参数）：
    同一命令第 N 次3-gram 重复率平均长度stop / length平均吞吐
    第 1 遍0.168326 字3 / 5153.8 tok/s
    第 2 遍0.210371 字1 / 7178.8 tok/s
  • eval_llm.py 走 M20 的采样生成（temperature 0.85：每步按概率抽样），且全程没有 torch.manual_seed——题目固定了，采样路径没固定。所有派生数字（重复率、长度、 吞吐）因此都是随机变量的单次抽样：差距小的"改进"完全会被这层噪声淹没。
  • 三选一：固定种子（对齐 eval_multiturn.py 的做法——它每轮生成前 torch.manual_seed(SEED)，SEED=42 写死，所以存档数字可复现）；贪心解码 （temperature=0，M20 讲过贪心每步取最大概率、输出确定，代价是更易复读，见本课变式练习）； 多样本取均值（官方 eval_compare 的做法：3 个 seed × 9-10 个 prompt 再平均）。拿单次 采样输出当分数用，是评测里最隐蔽的一个坑。 [作者实测 · 2026-10-01 · 同环境 · 同权重同参数背靠背两跑] 重复率由 3-gram 脚本对两次输出分别计算；第 2 遍 Q2 的答案与第 1 遍从第一句起就不同 （"天空是蓝色的原因是由于光的散射" vs "天空之所以呈现出蓝色……"）——采样路径不同，肉眼可见。

多轮与长上下文：读档四套件

第三把尺由 tools/eval_multiturn.py 扛着，四个套件各有明确靶子—— 多轮记忆与长上下文是单轮评测的盲区，也是 M02 对话实验里你多半已经隐约感到的短板：

套件测什么怎么判分
A 跨轮记忆首轮注入信息（姓名/数字/暗号/书名），后续轮追问召回召回关键词命中率（4 剧本 × 共 12 个关键词，客观可数）
B 长度压力构造 256→2048 token 的合成多轮历史后提问在题与否 + 3-gram 重复率 + 生成长度（敷衍短句 = 变相跑题）
C 长程稳定单会话连续 12 轮固定问题链前 3 轮 vs 末 3 轮重复率漂移、角色漂移（越说越像用户口吻）
D 边界行为超 32768 token 的越界 prompt（守卫缺口验证）报错类型：预期是清晰的守卫错误，实际是裸形状异常

官方对照：同题集、strict 载入、控制变量

本课的高潮：和官方 minimind 面对面。本课第二个新概念：对照实验——比较两个对象时， 用控制变量法把"不关心的差异"全部冻结，只留要研究的那一个。官方对照 （tools/compare_official.py + tools/eval_compare.py）的冻结清单：

冻结项怎么冻为什么必须冻
题目同一组 PROMPTS 写死在脚本里不同题目难度不同，分数不可比
随机性贪心解码 / 固定 seed 多次取中位上一节坑卡的教训
结构官方 .pth 以 strict=True 载入我们的模型见下方测验 3——松加载会静默丢键，比的就不是同一个东西了

🏭 工业对照：拿模型去考"别人出的卷子"

与官方对照是"自命题卷"；工业界更常引用的是公共基准（lm-evaluation-harness 的 ceval/arc、 MMLU、HumanEval……）——题目别人出、答案自动判，天然免疫"自己出题自己考"的偏置。代价是 小模型在这些卷子上常常接近乱猜水平（官方 minimind-3 的 ceval 24.89，四选一乱猜也有 25）， 区分度低。所以实践是分层用：训练期用便宜的自动指标做回归，里程碑用固定题集 + 专项套件做定性， 发布前上公共基准对外报数——本课三把尺的顺序，就是这条流水线的缩影。

⚠️ 坑卡：验证集的 iid 假设——M16 那个 1.96，一部分是尺子歪了
  • M16 读档时 sft_full 的 val 钉在 1.96 不动，当时解读为"过拟合信号"。后来数据画像发现这把尺本身 有问题：SFT 验证集是从文件尾部切的，而数据文件按类别有序——前段 100% 单轮、 尾段多轮占 39.4%，验证集的多轮占比是训练集的 2 倍多。

  • 修复五（C5，M12 提过）：按内容哈希分桶切分（与文件顺序无关），构建期断言验证集与训练集的 多轮占比差 ≤2 个百分点，违反即报错。教训：指标异常时，先审尺子再信读数—— 对照实验的"冻结清单"里，评测集的分布也是必须冻的一项。

检验一下

测验 1 · PPL 和 loss 是什么关系？ours full_sft 的 CE 是 1.592，PPL 是多少、什么含义？

答案：$ \mathrm{PPL} = e^{\mathcal{L}} $（M16 的换算）：把 token 平均交叉熵折算成"每个位置平均在多少个候选词里犹豫"的等效词数。1.592 → e^1.592 ≈ 4.91：模型每个位置大约在 5 个词里犹豫（对照乱猜 = 词表 6400，即 loss 8.76）。跨模型比较必须同评测语料同口径——换语料 PPL 的含义就变了（见坑卡二）。

答错回看：评测的三把尺 与 质量横评表。

测验 2 · 题目写死在脚本里了，为什么"固定题集"还要固定种子？

答案：固定的是"输入"，没固定的是"采样路径"——temperature>0 时每步按概率抽样，不设 torch.manual_seed 的话每次运行走不同路径，所有派生数字（重复率、长度、吞吐）都是随机变量的单次抽样。实测同一命令两遍：重复率 0.168 vs 0.210（差 25%）、stop 3/8 vs 1/8。固定种子（eval_multiturn 的 SEED=42）、贪心解码或多样本平均，三招任选其一，否则小改进会被这层噪声淹没。

答错回看：坑卡：分数漂移。

测验 3 · 官方对照为什么必须 strict=True 载入？松一点会怎样？

答案：对照实验要冻结"结构"这个变量：strict=True 要求 checkpoint 的键集合与模型完全相等（M09 的语义），是"两边比的是同一个数学对象"的机器证明。若松加载（strict=False），不匹配的键会被静默跳过——比如某层没载上、保持随机初始化，模型照样能生成，你却在拿"半随机初始化的模型"和官方比，结论整体作废还不报错。跑得动 ≠ 载对了，这是最危险的无声失败。

答错回看：官方对照：同题集、strict 载入、控制变量。

测验 4 · ours pretrain 的 CE（2.18）比 official（2.35）低，能宣布"我们的 pretrain 更强"吗？

答案：不能。评测语料是 mini 语料的 val 切片——我们恰好在 mini 语料上训练，分布匹配天然占便宜；官方在 full 10GB 语料训练，对 mini 切片反而不匹配。这是混杂因素（没冻住的外来变量）：换到 full 语料评测结论会反转。SFT 段官方领先（1.43 vs 1.59）才是数据量差距的真实兑现。判读对照表前先问：除了要研究的变量，还有什么没冻住？

答错回看：质量横评 的两个反直觉读数。

变式练习

🧪 变式 · temperature 0.1 vs 0.9：哪个重复率更低？

只动一个旋钮：--temperature（top_p 0.95、题集、权重全不动），各跑一遍 eval_llm.py，用 3-gram 重复率算分——把 尺子一节的 ngram_rep_rate 包一个小驱动（/tmp/m21_rep_rate.py：正则抠出每题 🧠: 到 [N tok 之间的回答，逐题算重复率再平均，顺带数 stop/length）。

写下预测：低温 0.1（更"稳"）和高温 0.9（更"放飞"），哪个的平均重复率更低？先押一边再动手：

$ uv run python tools/eval_llm.py --weight full_sft --temperature 0.1 > /tmp/t01.txt
$ uv run python tools/eval_llm.py --weight full_sft --temperature 0.9 > /tmp/t09.txt
$ python3 /tmp/m21_rep_rate.py /tmp/t01.txt /tmp/t09.txt
/tmp/t01.txt: 答案 8 | 平均3gram重复率 0.257 | 平均长度 376 字 | stop 0 / length 8
/tmp/t09.txt: 答案 8 | 平均3gram重复率 0.197 | 平均长度 363 字 | stop 1 / length 7
观察结果与解释（先动手再看）

反直觉：低温 0.1 的重复率（0.257）反而全场最高——比 T=0.9（0.197）和默认 0.85 （0.168/0.210）都高，且 8 题全部跑满 256 token 上限（stop 0/8，永远等不到自己说 EOS）。

机制：temperature → 0 时采样退化为贪心——每步取概率最大的那个词。而复读是 自强化的：一旦生成过"麻婆豆腐"，它再次出现的条件概率被上下文抬高，贪心永远顺着 最大概率走，等于永远顺着复读轨道走；适度的随机性（高温）反而能把序列"踢"出轨道。 小模型的概率分布尖，这个效应比大模型猛得多。这也是官方横评固定用 T=0.8、而双实现 一致性检验必须用贪心的原因：贪心可复现（同权重同输出，fp32 逐位相同）但易复读， 采样多样但不可复现——可复现性与生成质量是两把不同的尺，别混用。顺带一提： 想同时要"可复现 + 不复读"，工业界的答案是固定种子 + 采样 + repetition_penalty （M20 采样链里的现成旋钮），而不是压温度。

本课词汇

评测指标 evaluation metric
把模型能力压缩成可比较数字的方法。三把尺：自动指标（PPL/重复率，便宜可全自动但看不见对错）、固定题集（输出可肉眼对照但样本小、题目可见）、专项套件（覆盖多轮/长上下文盲区但面窄）。每个数字都要记得它是哪把尺量出来的。
困惑度 perplexity, PPL
token 平均交叉熵的指数换算 $e^{\mathcal{L}}$（见 M16），本课升级为跨模型比较指标：同一批评测文本上谁低谁的语言建模更准。ours full_sft 1.592 → 4.91；前提是同语料同口径，否则不可比。
n-gram 重复率 n-gram repetition rate
生成文本切成 n 连续字符片后重复占比（1 − 去重数/总数）：0 无重复，1 完全复读。通顺中文约 0.1~0.2，≥0.4 基本复读循环。eval_compare/eval_multiturn 的量化"复读"都用它。
固定题集评测 fixed prompt set eval
写死一组题目、同种子同参数逐题生成对照（eval_llm 的 8 题）。输出直接可读、可跨版本对比；但题目"可见"可被针对性优化，且样本小只能定性——必须配固定种子/贪心，否则分数漂移（实测同命令两遍重复率差 25%）。
对照实验 controlled experiment
比较两个对象时冻结全部不关心的变量（题目/种子/结构/精度/评测集分布），只留要研究的一个。官方对照的冻结清单四行；没冻住的外来变量叫混杂因素（如评测语料偏向我方训练分布），会让结论反转。
混杂因素 confounder
对照实验中未被冻结、同时影响结果的外来变量。例：质量横评的评测集取自 mini 语料，我方在其上训练天然占优——pretrain"反超"0.17 CE 是分布效应而非代码优势。判读对照表先问：还有什么没冻住？
贪心解码 greedy decoding
temperature=0 的采样特例：每步取概率最大的词，输出确定可复现。用途是等价性/一致性检验（fp32 下双实现逐位一致 100%）；代价是复读自强化——小模型贪心路径最易进循环（T=0.1 重复率全场最高）。
严格加载 strict load
checkpoint 键集合与模型完全相等才放行的载入方式（见 M09）。官方对照用它冻结"结构"变量；松加载会静默跳过不匹配键，让比较对象悄悄变成另一个模型——对照结论作废且无报错。
HF 格式导出 HF export
convert_model.py to-qwen：.pth → Qwen3 结构的 safetensors+config+tokenizer 目录。导出即进入 HF 生态（transformers/vLLM/ollama 可加载）——训练栈自有、交付格式行业标准。merge-lora 子命令则把 M18 的适配器合并回基模。
