总装：从零件到整机

五课零件在整机里的位置——M03 ⑤站画过图纸，现在每块砖都换成了你读过、跑过的类名： 

MiniMindForCausalLM（model.py:127）—— 本课组装的整机
│
├─ model: MiniMindModel（骨干，model.py:52）
│   ├─ embed_tokens   词 → 向量（M05 见过的那张查找表）
│   ├─ layers × 8     MiniMindBlock（本课）
│   │   ├─ input_layernorm         【M05】RMSNorm
│   │   ├─ self_attn               【M07】GQA + QK-Norm + RoPE + KV cache【M06】
│   │   ├─ post_attention_layernorm【M05】RMSNorm
│   │   └─ mlp                     【M08】SwiGLU（或 MoE）
│   ├─ norm          出口第 17 个 RMSNorm【M05】
│   └─ freqs_cos/sin RoPE 预计算表（非持久 buffer）【M05】
└─ lm_head          768 → 6400 的词汇预测头（与 embed_tokens 共享权重，本课）

整机只有 174 行（models/model.py）， 三个类各管一段：MiniMindBlock 管一层的变化，MiniMindModel 管骨干（把 8 层串起来、 持有 RoPE 表），MiniMindForCausalLM 管头与损失（把 768 维隐状态变成 6400 个词的打分）。 骨干 vs 头为什么拆开？因为头是"任务"：换成一个分类头就是句向量模型，骨干原封不动。

Block：pre-norm 残差的最终形态

M03 ⑤站见过图纸、M05 精读过其中的 norm，现在看全貌——整个 Block 的 forward 只有两行加法：

src/minimind_reborn/models/model.py · MiniMindBlock.forward 全文python
hidden_states = hidden_states + self.self_attn(      # x + attn(ln1(x))
    self.input_layernorm(hidden_states),              # 先归一化，再进注意力
    position_embeddings,                              # (cos, sin)：RoPE 表切片，【M05】
    cache=cache, layer_idx=self.layer_id,             # KV cache 逐层写入，【M06】
    cache_start=cache_start,
    attention_mask=attention_mask,
)
hidden_states = hidden_states + self.mlp(            # x1 + mlp(ln2(x1))
    self.post_attention_layernorm(hidden_states)
)
return hidden_states                                  # (B, T, C)：一路加到底的残差流

两次加法的左边都是未经加工的 x 本身——这条从输入直通输出的通道叫残差流（residual stream）。 把 8 层展开看，残差流是一条主干道，每个子层只是往主干道上"追加"自己的贡献： 

主干道（残差流）—— 任何一层看到的 x = 输入 + 此前所有子层贡献之和

x ──┬──────────────────────────────┐
    └─► ln1 ─► Attention ──────► (+)    x₁ = x + attn(ln1(x))
x₁ ─┬─────────────────────────────┐
    └─► ln2 ─► FFN(SwiGLU) ────► (+)    x₂ = x₁ + mlp(ln2(x₁))     × 8 层
                                         └─ 每个子层输出加回主干道，norm 只作用于支路
📐 为什么先 norm（pre-norm）而不是后 norm（post-norm）

初代 Transformer（post-norm）把 norm 放在加法之后：x = norm(x + attn(x))—— 主干道每过一层就被重新缩放一次，8 层叠起来，靠近输入的梯度被反复改写，深了就训不稳（这正是原始论文需要 学习率预热（warmup）的原因之一）。pre-norm 把 norm 挪进支路：主干道是恒等映射，梯度沿加法原样回流 （$\partial(x + f(x))/\partial x = I + f'$ 里的那个 $I$），层数加深不再放大数值动荡。 GPT-2 起至今 LLaMA/Qwen 系全线 pre-norm。代价是表示有效宽度略受影响——工程上换来训练稳定性，值。

ForCausalLM：头与两个新概念

src/minimind_reborn/models/model.py · __init__ 骨架python
class MiniMindForCausalLM(PreTrainedModel):
    config_class = MiniMindConfig
    _tied_weights_keys = {"lm_head.weight": "model.embed_tokens.weight"}  # 告诉 HF：这两个键共享

    def __init__(self, config: MiniMindConfig | None = None):
        config = config or MiniMindConfig()
        super().__init__(config)                       # 继承 HF：from_pretrained/config 管理免费获得
        self.model = MiniMindModel(config)             # 骨干
        self.lm_head = nn.Linear(config.hidden_size, config.vocab_size, bias=False)  # 768 → 6400
        if config.tie_word_embeddings:
            self.model.embed_tokens.weight = self.lm_head.weight      # ← 一行完成 weight tying
        self.post_init()

先补两个词。logits（对数几率）：模型对词表每个候选词输出的未归一化打分——M02 调温度时你摸过它； lm_head（language modeling head，词汇预测头）是产出 logits 的线性层：768 维隐状态 × 权重矩阵 → 6400 个打分，无 bias（与全模型线性层一致——RMSNorm 去偏置的同一哲学）。

Weight tying（权重绑定）是本课第一个新概念，只花了一行代码：

💡 直觉：一张表，正着查、反着用

embed_tokens.weight 的形状是 (6400, 768)——第 i 行就是"词 i 长什么样"的向量； lm_head.weight 的形状也是 (6400, 768)——隐状态与第 j 行做内积，就是在问 "这个隐状态跟词 j 像不像"。一个把词变向量，一个拿向量比词，参考的却是同一张"词—向量"对照表—— 既然语义相同，何必存两份？绑定后两块内存是同一个张量（is 判定为真），省下 6400 × 768 = 4,915,200（4.92M）参数——对 64M 的模型是 7.7% 的家当。

绑定带来三个工程细节，都值得记：① named_parameters() 对共享参数去重—— lm_head.weight 根本不出现在参数清单里（实测 90 项），parameters() 求和自动不重复计账； ② state_dict() 却两个键都保留（实测 91 项）——保存/加载按模块路径走，两键指向同一块内存； ③ 类属性 _tied_weights_keys 是给 transformers 生态的声明："保存为 HF 格式时这两个键别存两份"。 官方 checkpoint 同样带 lm_head.weight 键——所以 strict 载入能逐键对上。

🏭 工业对照：小模型 tie，大模型 untie

官方 minimind 与 reborn 默认 tie_word_embeddings=True；工业界 GPT-2 与 Gemma 系全线 tying， Qwen2/Qwen2.5 只在小尺寸档（0.5B/1.5B）tying、7B 起解绑，LLaMA 系与 Mistral-7B 则一贯解绑。 分界线就是省量占比：大模型词表大（15 万+），embedding 动辄上亿参数，但总参数几百亿—— 绑定省不到 2%（LLaMA-2 7B 约 1.8%），而"输入查找表"和"输出打分器"分开学出的表征确实更强； 小模型参数寸土寸金，绑定的正则效应（同一张表逼着学一致表征）反而更划算。 tie_word_embeddings 字段（config.py:36）就是这条工程权衡的开关。

移位交叉熵：用第 t 位预测第 t+1 位

语言模型的训练目标一句话：看前文，猜下一个词。代码在 forward 里只有六行， 但"移位"（shift）这个动作是本课第二个新概念：

src/minimind_reborn/models/model.py · forward 的损失段python
logits = self.lm_head(hidden_states[:, slice_indices, :])   # (B, T, 6400)：每个位置一套打分
loss = None
if labels is not None:
    # 移位：位置 i 的 logits 预测位置 i+1 的 token；-100 忽略（padding 与非回答区间）
    shift_logits = logits[..., :-1, :].contiguous()          # 去掉最后一位 (B, T-1, 6400)
    shift_labels = labels[..., 1:].contiguous()              # 去掉第一位 (B, T-1)
    loss = F.cross_entropy(
        shift_logits.view(-1, shift_logits.size(-1)),        # 摊平 (B·(T-1), 6400)
        shift_labels.view(-1),                               # 摊平 (B·(T-1),)
        ignore_index=-100,                                   # 标签 -100 的位置不进损失
    )

拿一句话走一遍（T=5；<s> 是 BOS 序列起始符，M02 对话模板里的开场 token）。 模型对每个位置都输出一套 6400 维打分——位置 0 看到的只有 <s>， 它的打分该把"北"顶上去；位置 3 看到"<s> 北 京 城"，它的打分该把"的"顶上去： 

位置 t:      0      1      2      3      4
input_ids:  <s>    北     京     城     的
labels:     <s>    北     京     城     的      ← 训练时 labels 就是 input_ids 本身

logits[t] 谁该得高分？ —— 位置 t 的答案是 labels[t+1]（下一个词）：
             0 号打分 ↔ labels[1] = "北"
             1 号打分 ↔ labels[2] = "京"
             2 号打分 ↔ labels[3] = "城"
             3 号打分 ↔ labels[4] = "的"
             4 号打分 ↔ labels[5] = ？（越界，丢弃）

移位 = logits[..., :-1] 对齐 labels[..., 1:]：各留 T-1 个有效配对位

两个零碎但要紧的点。为什么不直接 logits 对 labels？那样位置 0 的打分会拿 labels[0]="<s>" 当目标——模型学到的是"复读当前词"而不是"预测下一词"，训练看起来也收敛，生成的模型只会照抄输入， 错位一个下标，全盘皆错。.contiguous() 是什么？切片后的张量在内存里不连续， view（按形状重新解读内存，不搬数据）要求连续存储，contiguous() 物理搬一次； 用 reshape 可以省掉这两个词，但显式 contiguous 让"这里发生过一次拷贝"可见。

交叉熵（M01 定义：衡量"模型给正确答案的概率"有多低）在均匀乱猜时等于 $\log V$—— 这是 M01 测验 1 埋下的钩子，本课亲手回收：

$$ \mathcal{L} = -\frac{1}{|M|}\sum_{t \in M}\log \frac{\exp(z_{t,\,y_{t+1}})}{\sum_{j=1}^{V}\exp(z_{t,\,j})} \qquad \text{初始化时 } z \approx 0 \Rightarrow \mathcal{L}_0 \approx \log V = \log 6400 \approx 8.7641 $$

M01 测验 1 承诺过"M09 组装模型后用它验证组装没装错"——当场兑现。组装一台 tiny 版 （词表仍是默认 6400），喂随机 token 看 loss 落在哪：

[作者实测 · 2026-09-30 · 2×RTX 4090 · torch 2.14.0+cu130] 8.8141 与理论值 8.7641 差 0.05——随机初始化让 logits 带着微小的随机起伏，并非完全均匀 （M01 日志的 8.7871 同理）。若你的初始 loss 离 8.76 有 0.5 以上的距离， 先怀疑词表大小被改过或损失算错位置——这台"体温计"对错位极其敏感。

ignore_index=-100 是数据层的约定俗成：一个 batch 里短句要补齐（padding，M02 ③站见过）到同一长度， 补出来的位置不携带"下一个词"的语义，数据管道把它们的 label 置成 -100（datasets.py:338 一行： labels[input_ids == pad_token_id] = -100），交叉熵跳过这些位置——M01 冒烟日志里那个 loss=8.7871 的 batch 同样含 pad 位。这句约定的另一端（SFT 里"只对回答区间算损失"的 loss_mask） M12 详讲；本课只需记住：-100 = "这一格不算账"。

forward 签名里还有个 logits_to_keep: int = 0：大于 0 时只对最后 N 个位置过 lm_head—— 生成时一步只需要最后一个位置的打分，全序列 × 6400 的矩阵乘法可以省掉大半。它是给 transformers 生态 （HF 的 generate 流程会传这个参数）留的兼容开关；reborn 自己的生成内核（M03 ⑥站）走全量 logits 再切 [:, -1, :]（generator.py:78），两条路都通。 MoE 的 aux_loss（M08 的负载均衡辅助损失）也在这里收口：骨干把各层 mlp.aux_loss 求和带回（model.py:120-123），dense 模型恒为 0——test_forward_shapes_and_loss 断言的正是这一条。

/tmp/m09_ledger.py · 逐键分组参数账本python
import re
from collections import OrderedDict
from minimind_reborn.models.config import MiniMindConfig
from minimind_reborn.models.model import MiniMindForCausalLM

model = MiniMindForCausalLM(MiniMindConfig())   # 64M 默认结构：768 宽 × 8 层
groups: "OrderedDict[str, list]" = OrderedDict()
for name, p in model.named_parameters():
    key = name.removeprefix("model.")                 # model.layers.0.… → layers.0.…
    key = re.sub(r"layers\.\d+", "layers.N", key)     # 8 层逐层归并到同一行
    groups.setdefault(key, [0, 0])
    groups[key][0] += p.numel()                       # 该行总参数
    groups[key][1] += 1                               # 出现的 key 数

total = sum(v[0] for v in groups.values())
for k, (n, c) in groups.items():
    tag = "" if c == 1 else f"  ← ×{c} 层"
    print(f"{k:44s}{n:>12,}{tag}")
print(f"{'合计':44s}{total:>12,}   = {total/1e6:.2f}M")
print("lm_head.weight 单独计账了吗：", "lm_head.weight" in groups)

权重三语义：save / strict / finetune

模型有了、账算清了，下一个问题是权重怎么落地、怎么回来。 models/weights.py 全文 89 行，模块 docstring 立了四条不变量，其中三条定义了三个语义不同的入口：

save_inference_weights：fp16 CPU 原子写

src/minimind_reborn/models/weights.py · save_inference_weightspython
def save_inference_weights(model: nn.Module, path: str | Path, dtype: torch.dtype = torch.float16) -> Path:
    """保存推理权重（fp16 CPU，原子写）。调用方负责 rank0 门控。"""
    raw = unwrap_model(model)     # 剥掉 DDP / torch.compile 壳（分布式/编译加速的包装都不留进文件）
    state_dict = {k: v.detach().to(dtype=dtype, device="cpu") for k, v in raw.state_dict().items()}
    return atomic_save(state_dict, path)

三个动词各有含义。.to(fp16, cpu)：训练可能跑在 bf16 + 多卡上，但落盘统一 fp16（M05 讲过的半精度， 尾数 10 位，比 bf16 精一倍、动态范围小——推理权重取其精确）；统一 CPU 是让文件与机器无关 （GPU 序列化文件到无卡机器上直接炸——docstring 不变量第一条）。原子写（atomic write）：先写 path.tmp 再一步改名——写到一半被 kill -9（强杀进程）不会留下半个坏文件顶替好文件 （M14 用 kill -9 实验专门验证）。rank0 门控：多卡训练只有 0 号进程写文件，其余进程不碰—— "调用方负责"即这层判断在训练器里（M15）。

def load_finetune_weights(model: nn.Module, path: str | Path) -> None:
    """微调加载：非严格 + 缺失/形状不匹配逐 key warning（training §4 反'静默吞键'）。"""
    state_dict = torch.load(path, map_location="cpu", weights_only=True)
    model_state = model.state_dict()
    shape_mismatch = [k for k, v in state_dict.items() if k in model_state and model_state[k].shape != v.shape]
    filtered = {k: v for k, v in state_dict.items() if k not in shape_mismatch}  # 形状不对的先剔除
    missing, unexpected = model.load_state_dict(filtered, strict=False)          # 再非严格载入
    _warn_key_diff(missing, unexpected, shape_mismatch)

def _warn_key_diff(missing, unexpected, shape_mismatch):
    if missing:        logger.warning("权重加载缺失 %d 个 key（保持初始化值）：%s", len(missing), missing[:8])
    if unexpected:     logger.warning("权重加载多余 %d 个 key（已忽略）：%s", len(unexpected), unexpected[:8])
    if shape_mismatch: logger.warning("权重加载形状不匹配 %d 个 key（已忽略）：%s", len(shape_mismatch), shape_mismatch[:8])

🔍 bug 猎场：RoPE buffer 在 meta 初始化中丢失

M05 结尾埋的雷今天挖：非持久 buffer（register_buffer(..., persistent=False)—— 跟着模型走设备、不参与训练、不进 checkpoint 的派生数据）在正常构造下毫无问题—— __init__ 里预计算、forward 里切片。问题出在模型不是"正常构造"出来的那些路上。

⚠️ 坑卡：transformers ≥5 的 meta 初始化，会把 RoPE 表变成空壳
  • meta 设备（M05 见过：只登记形状、不分配内存的虚拟设备）是 transformers 5.x 初始化模型的新姿势： 先在 meta 上把 8 层骨架搭起来（零内存开销），再把 checkpoint 里的参数逐个灌进去。 灌参数时参数有人管、持久 buffer 有人管（从 checkpoint 恢复），唯独 persistent=False 的 buffer 没人管—— 它不在 checkpoint 里，物化路径也不会替你重算。症状：形状还在，值是全零（或未初始化内存）； 模型能跑、不报错，位置编码却已蒸发。
  • 责任真空：非持久 buffer 的契约是"派生数据、加载时重算即可"，但"加载时重算"这一步 没有任何机制保证发生——load_state_dict 只覆盖参数与持久 buffer。作者实测复现责任真空 （脚本见下）：孪生模型建在 meta 上物化、灌入好模型的全部参数，唯独 RoPE 表回不来—— 四次运行 logits 最大偏差 0.28 / NaN / 0.14 / 0.22，坏法每次不一样（内存里是什么垃圾就用什么），坏本身每次都发生。
  • reborn 的 workaround 在 model.py:75-90：每次 forward 先花一次 torch.all(self.freqs_cos == 0) 探测（全零判据——官方踩坑时物化路径留下的正是全零），命中就重算重注册。注释原文： "这是官方踩坑后的 workaround（原版同款判断），单测 test_models 锁定该行为。"

检验一下

测验 1 · 移位为什么要 logits[..., :-1] 对 labels[..., 1:]？不移位会怎样？

答案：位置 t 的 logits 是"看完前 t+1 个词后对下一个词的打分"，它的正确目标是 labels[t+1]——所以打分去掉最后一位（它要预测的 t+1 不存在）、标签去掉第一位（没人预测 BOS），各留 T-1 个配对。不移位则位置 t 拿 labels[t] 当目标——模型学成"复读当前词"，训练照样收敛，生成的模型只会照抄输入；错位一个下标，全盘皆错。

答错回看：移位交叉熵 的 T=5 逐位图解。

测验 2 · weight tying 省了多少参数？为什么这两个矩阵天然可以共享？

答案：省 6400 × 768 = 4,915,200（4.92M，占 63.91M 的 7.7%）。直觉：embed 是"词 → 向量"的查找表（第 i 行 = 词 i 的向量），lm_head 是"隐状态 × 每个词的向量 → 打分"——两者参考的是同一张"词—向量"对照表，一个正着查、一个反着用，语义相同即可共享同一块 (6400, 768) 张量（绑定后 is 判定为真）。

答错回看：ForCausalLM 精读 的直觉卡与三个工程细节。

测验 3 · 同一个缺 key 的权重文件，strict 和 finetune 两种加载分别发生什么？"静默吞键是最危险的成功"防的是谁？

答案：strict 直接 RuntimeError: 权重加载失败（严格模式）：1 个缺失 key / 0 个多余 key，启动前一秒死掉；finetune 不炸，缺失的 key 保持随机初始化继续训练，但必须逐 key 打 warning（"缺失 1 个 key（保持初始化值）"）。"静默吞键"防的是第三种状态——加载既"成功"又无声，随机初始化的部件混在训练里，loss 也降只是降不好，几小时后才从曲线倒查。reborn 用测试（caplog 断言警告必现）锁死"不许装哑"。

答错回看：strict 的两种死法 与 非严格但不许装哑。

测验 4 · pre-norm 为什么把 RMSNorm 放在支路而不是主干道？这换来什么、付出什么？

答案：主干道保持恒等映射（x 原样参与加法），梯度经 $\partial(x+f(x))/\partial x = I + f'$ 中的 $I$ 直通浅层，8 层叠加不再逐层改写梯度尺度——深模型好训（post-norm 需要学习率预热来压同一问题）。付出：残差流的幅度会随层数缓慢增长（没有 norm 压它），好在出口还有第 17 个 RMSNorm 收尾，且现代实现普遍接受这一点。

答错回看：Block 精读 的残差流图与推导卡。

✍️ 自写挑战 · B 轨 T5：手写移位交叉熵

任务书：从空白文件 my_impl/loss.py 开始，手写纯函数 shifted_cross_entropy(logits, labels, ignore_index=-100) -> torch.Tensor—— logits: (b, T, vocab)，labels: (b, T)。行为约束：移位用 logits[..., :-1, :] 对 labels[..., 1:]（位置 t 的打分预测 t+1 的 token）， 展平成 (b·(T-1), vocab) 与 (b·(T-1),) 后交给 F.cross_entropy(..., ignore_index=-100)——被标 -100 的位置（padding、非回答区间）不进分母。 参照 src/minimind_reborn/models/model.py 的 MiniMindForCausalLM.forward 里 labels 非 None 的分支。 注意：这是本课参数账本之外的纯函数任务——不要模型、不要权重，一份 logits 一份 labels 就能开工， 八个挑战里门槛最低、收益最高（🏁D 拼装时它原样可用）。

提示 1 · 方向

移位的本质是"各去一位再配对"：logits 去掉最后一位（位置 T-1 的目标不存在），labels 去掉第一位 （BOS 没人预测它）——两边各剩 T-1 个，按位对齐就是训练对。

提示 2 · 表达式级

核心三行：sl = logits[..., :-1, :].contiguous(); tl = labels[..., 1:].contiguous()； return F.cross_entropy(sl.view(-1, sl.size(-1)), tl.view(-1), ignore_index=ignore_index)。

对拍：脚本模板见 B 轨总纲——取 tiny 模型一次前向的 logits 与含 -100 的 labels，你的返回值 vs model(x, labels=labels).loss，allclose 必须成立； 再构造 labels 全 -100 的批次确认抛错/为 nan 的边界行为与 reborn 一致。裁判测试 tests/test_models/test_model.py::test_forward_shapes_and_loss（先跑一遍看参考行为： uv run pytest tests/test_models/test_model.py -q——它锁定的正是"带 labels 的前向产出有限 loss"）。

本课词汇

weight tying 权重绑定
词嵌入矩阵与词汇预测头共享同一块 (vocab, hidden) 张量：一个正着查（词→向量）、一个反着用（向量×词打分）。64M 模型省 4.92M（7.7%）；named_parameters() 去重、state_dict() 保留双键。
移位交叉熵 shifted cross-entropy
语言模型损失：位置 t 的 logits 对 labels[t+1] 求交叉熵——logits[..., :-1] 对 labels[..., 1:]，各留 T-1 个配对。不移位则学成"复读当前词"。
ignore_index
交叉熵的免算标记（约定 -100）：padding 位与非监督区间的 label 置 -100，损失跳过。数据侧在 datasets.py 落笔（M12 的 loss_mask 详讲）；"这一格不算账"。
残差流 residual stream
Block 间直通的主干道：每个子层只往上面追加贡献（x += f(norm(x))），主干道是恒等映射，梯度直通浅层——pre-norm 训练稳定性的来源（M03 图纸的正式名字）。
strict 加载 严格加载
模型键集与文件键集必须完全相等，多一个少一个都 RuntimeError；形状不匹配则由 PyTorch 的 size mismatch 更早拦下。自建模型与官方权重互通的最硬证据。
finetune 语义 非严格加载
允许结构差异（缺失保持初始化、多余忽略、形状不匹配剔除），但逐 key warning——"静默吞键是最危险的『成功』"（weights.py docstring 原话）；警告必现有 caplog 测试锁定。
原子写 atomic save
先写临时文件再一次改名，进程中途被杀不会留下半个坏文件顶替好文件；save_inference_weights 的落盘纪律（M14 用 kill -9 实验验证）。
meta 设备 meta device
只登记形状不分配内存的虚拟设备；transformers ≥5 用它搭骨架再灌参数——参数与持久 buffer 有人恢复，非持久 buffer（RoPE 表）责任真空，reborn 以"全零判据 + 重算重注册"兜底。
