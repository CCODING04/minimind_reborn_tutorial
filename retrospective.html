制作复盘：这套教程是怎么做出来的

本课程站用 10 天、22 个提交从空仓库走到 23 模块 + 4 附录 + 103 个源码查看页。 本页复盘全程遇到的问题 → 解决方案，以及最终质量背后做对了什么—— 目的是把这套做法沉淀成可复用的制作方法（见本页第 7 节 SOP）。

受众：想复用这套方法做课的人 · 不限 用法：方法论参考，可跳读 姊妹篇：仓库内 ANALYSIS.md / DESIGN.md / RETROSPECTIVE.md

一、一页总结

结果：机械 QA（check_course + interact_check 54 项）0 错误，上游 93 个单元测试全绿， 五档视口无横向溢出，完全离线自足（无外部资源依赖）。

💡 四条核心结论

① 内容质量不是"审"出来的，是结构保证的——开工前三条工程原则（单一事实源 + 生成式导航 / 机械 QA 覆盖正文引用 / 写作即实测）把参照教程尸检出的 8 类过程缺陷在结构上堵死； ② 修复历史呈收敛形态——前 48 小时集中消灭内容层错误，此后全部是排版、导航、渲染层的长尾清理， 人工通读验收的反馈同样集中在排版层；③ 最危险的内容错误（三处教了不存在的 API 参数）不是人眼发现的， 是跨仓库同步时的机械对拍发现的；④ 最大的维护负担是烘焙 HTML + 手动资源版本链 （13 次全站 bump），复用本法时应改为构建期注入。

三、方法论链条：开工前做对了什么

分工链是 ANALYSIS（尸检参照物）→ DESIGN（宪法）→ 写手规范 → QA 工具链（兜底）→ 一次性成文。 前三环都发生在第一个提交之前——全项目最重要的一条经验：把决策成本前置，把执行交给流水线。

3.1 先尸检，后动笔（ANALYSIS.md）

动笔前先对参照教程（Part7_minimind，21 模块 HTML 课程）做了一次逐证据检查， 产出"8 项优势全继承 + 8 项缺点逐条对策"。8 项对策的方向：

参照教程的缺点新课程对策
声称产物与实际不符（权重丢、日志在）只引用实际存在的产物；QA 对正文提到的路径做存在性检查
规划文档漂移（模块数自相矛盾）模块清单单一事实源 = course.js 的 COURSE 数组，导航全部生成
机器特定路径（读者不可复现）一律仓库相对路径 + 环境指纹标注
单页模板不一致（另一代模板残留）共享 CSS 承载全部样式；QA 检查内联 style 属性
正文文本引用路径失效（非链接，查不到）QA 扫描正文路径形引用并核对存在性
测试承诺与交付落差不虚构承诺，直接绑定上游真实 93 测试 + 8 冒烟配方
仓库卫生（杂散文件、node_modules）目录最小结构约定
已知渲染问题记录了但不修样式层预防 + QA 含移动端宽度检查项
📐 元教训（最值钱的一段）

参照教程的缺点几乎都不是写作能力问题，而是多轮 agent 生成之间的过程问题—— 状态不同步、模板换代未全量重刷、QA 只覆盖链接不覆盖正文。 对应的工程解法只有三条，全部写进了新课程工作流： 单一事实源 + 生成式导航；机械 QA 覆盖到正文引用；写作即实测（页面上每个命令作者真实跑过）。

3.2 宪法先行（DESIGN.md）

DESIGN.md 把"这门课长什么样"一次性定死：7 篇 23 模块结构表（每模块映射上游关键资产与 bug 猎场索引）、 每模块固定骨架（模块头 → 学完你能 → 正文 → 测验 → 变式 → 验收 → 词汇 → 导航）、 11 类教学元素体系（直觉卡/严谨卡/坑卡/红线/工业对照/折叠测验/变式练习/填空/验收块/里程碑/概念图， 每类定用量规则）、代码与数字规范、写作 SOP 五步、9 项自查清单、QA 契约。 关键设计：模块清单以 COURSE 数组为准，本文表格冲突时服从数组——文档自己不争事实源地位， 从制度上消灭规划漂移。

3.3 写手规范：把风格决策做成"逐字模板"

给 AI 写手的规范（tools/agent_brief_common.md）不写抽象原则，直接给逐字照抄的页面骨架模板 + 10 条硬规则（零内联样式、代码块结构、终端块手写、仓库链接原始形式、HTML 转义、shape 注释、 标题带 id、数字溯源、长度区间）+ 连贯性纪律（术语首现必须 A=当场解释或 B=显式桥接，零裸用； 新概念 ≤2 个/模块；开头承接结尾预告）。违反硬规则的，QA 直接拦。 效果：23 个模块由多轮会话生成，但没有一个模块出现模板漂移。

五、问题分类学：八类问题与解法模式

#类别怎么发现的解法模式 / 一般化教训
1事实一致性跨仓库同步对拍、系统性 QA 审查清单式机械修复 + 实测复核。最危险的是"教程教的 API 不存在"——人眼审不出，必须与真实代码机械对拍
2资源供应链"读者从零走一遍"视角审查补第 0 步、参数补全、路径环境变量化。自己机器上永远复现不了读者的问题；从零验收要独立做
3上游代码漂移上游提交监控成建制同步（口径+叙事+行号+数字），改"已修复"叙事而非删素材
4响应式/布局回归五档视口矩阵断点实测修正 + 视口进 QA。布局回归是设计系统改版的固定伴生物，改版必须带视口回归
5滚动与锚点人工通读 + 交互矩阵定位锚与滚动容器分离、状态存储化。绝对定位元素不能挂在滚动容器内部——DOM 结构即 bug
6渲染缺陷人工通读修根因 + 全量重生成。生成器修了别忘了旧产物——烘焙页要跟生成器版本对齐
7CSS token 错名双皮肤对比时暴露token 名对齐共享 CSS。CSS 变量拼错不报错；新皮肤先用最小用例验证每个 token
8工具/流程事故事后 diff 发现git 恢复零损失；后续批量改文件只用纯 sed + 对账。批量脚本要有"可回滚 + 事后对账"双保险
💡 分布规律

类别 1–3（内容层）全部发生在前 48 小时；类别 4–8（呈现层）散布全程。 内容层的收敛速度是 QA 管线效果的直接度量——人工通读（至 M08）后剩余反馈集中在排版层， 内容层未再发现硬伤。

六、最终做对了什么（八条）

  1. 先尸检再动笔。 对参照教程的 8 项缺点逐条立对策。成本一天，收益是整类问题（文档漂移、路径失效、模板不一致）从制度上不存在。
  2. 风格决策一次性做完，执行交给流水线。 DESIGN 定元素体系、写手规范给逐字模板、panelize 自动包卡片、语法高亮由 JS 运行时完成——写手只产出结构与文字，23 个模块多轮生成零模板漂移。
  3. 单一事实源 + 生成式导航。 COURSE/APPENDIX 数组是唯一清单，导航全部运行时生成。全项目导航类 bug 只有一次（漏注册），且修一处即全站生效。
  4. 机械 QA 覆盖到正文引用。 三处"教了不存在参数"级别的硬伤由对拍发现而非审读发现；行锚校验让 227 处深链"可达"变成可验证属性。
  5. 写作即实测 + 数字溯源。 页面每条命令真实跑过、每个数字带溯源标注。一致性修复里没有一个是"凭空捏造的数字"——最多是口径漂移。
  6. 一次性成文 + 分批质检。 先修工具、再修内容、再修视觉——修工具优先于修内容，供应链优先于排版，每批修复都建立在可信地基上。
  7. 缺口驱动增补。 M00、B 轨、PyTorch 指南、两份词汇表——全部是被读者旅程的真实缺口逼出来的，每个都有正文首现桥接，没有一个是"规划出来的完税结构"。
  8. 提交纪律 + git 兜底。 几乎每个提交以"QA: 0 错误 + 浏览器实测"收尾；两次脚本截断事故因 git 而零损失；危险操作前建备份分支。

八、可复用 SOP：下次做新教程的八步

前置条件：已选定一个真实、带测试、持续维护的上游代码仓库作为教学对象。

  1. 尸检参照物（1 天）：找一套同类优秀教程，逐证据列优势（继承）与缺点（对策），产出分析文档。重点提炼"过程性缺点"——它们才对应工程解法。
  2. 写宪法（1 天）：定结构表（模块 ↔ 上游资产映射）、固定骨架、教学元素体系（每类定用量规则）、代码与数字规范、QA 契约。声明单一事实源，文档自己不争。
  3. 写写手规范：逐字骨架模板 + 硬规则清单（QA 可拦的）+ 连贯性纪律（术语首现 A/B、新概念限额、开头承接结尾预告）。
  4. 工具链先行：静态检查（断链/锚点/nav 一致性/正文路径/禁内联样式）、动态检查（交互/五档视口）、codeview 生成器、部署 CI。工具本身先过"参数化与可移植"关（本项目 B0 的教训）。
  5. 先跑通再成文，一次性集中成文：页面上每条命令真实执行、输出留档；按骨架批量产出全部模块。
  6. 分批质检：顺序 = 工具 → 内容一致性 → 资源供应链 → 视觉。每批修复后 QA 归零再进下一批。
  7. 缺口驱动增补：以"读者从零走一遍"的视角找缺口（受众入口、理论前置、词汇表、自写轨道），每个增补在正文首现处建桥接，并注册进导航事实源（别忘注册）。
  8. 长尾清零 + 规则固化：排版/锚点/渲染类长尾逐个清；每修一类就把校验规则固化进 QA；批量改文件 = 纯 sed + 对账 + git 兜底。
🛑 三条不可妥协的底线

单一事实源 + 生成式导航；机械 QA 覆盖正文；写作即实测。 丢了任何一条，就会退化成参照教程的样子——文档自相矛盾、路径失效、数字凭空。
