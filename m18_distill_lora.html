蒸馏与 LoRA：小成本改造

M17 的 DPO 给模型装上了"品味"——在两个回答里挑更好的那个。但到 M17 为止， 每次训练都在动全部 63.91M 参数。本课学两个"省钱术"：蒸馏不抄答案、抄老师的完整概率分布； LoRA 冻结基座、只训 0.6% 的旁路参数。M02 埋的"自称 Qwen"伏笔，也在这课兑现。

蒸馏：抄答案，不如抄老师的思路

硬标签 vs 软标签：暗知识

回忆 M16 的 SFT：每个位置的监督信号是 labels 里那个 token 的编号，训练时被交叉熵 （M01 见过的"预测分布 vs 真实分布"的账）当成 one-hot 目标——6400 维向量里只有正确答案是 1， 其余 6399 个全是 0。这叫硬标签。软标签则是另一个模型对同一位置给出的完整概率分布： 正确答案也许 0.6，但"语义近似的错误答案"各分到一点概率。

💡 直觉：一道选择题的两种讲评

硬标签是"答案是 C"——你只知道对错。软标签是"C 60%，B 25%，D 10%，A 5%"—— 你额外知道了 B 比 D 更像正确答案。这些"错误答案之间的相似度结构"叫暗知识（dark knowledge， Hinton 的术语）：硬标签里它全部被压成 0，软标签里它整份保留。同一个训练样本， 软标签的信息量稠密得多——每个位置都带着 6400 个非零（或接近零）的分数，而不是 1 个编号。

现在兑现 M02 的伏笔。M02 你见过模型一本正经地自称"Qwen / 通义千问"，当时的解释是： SFT 语料本身就是拿 Qwen 当老师生成的——用大模型的回答训练小模型，这件事有个正式名字，就是 知识蒸馏（knowledge distillation）：拿一个强模型当教师（teacher），训练一个小学生（student）。 注意 M02 那条链其实只蒸馏了一半：Qwen 的回答被采样成了文本，分布结构（哪些错误答案也像样）丢了， 留下来的仍是硬标签。本课的 distill 范式把这一步做完整——学生的分布直接对齐教师的分布。 也就是说：你从 M02 起就一直在用蒸馏的产物，现在才第一次亲手做蒸馏。

数学：KL 散度与温度

"两个分布差多远"需要一个度量——KL 散度（Kullback–Leibler divergence）： $$ \mathrm{KL}(p \,\|\, q) = \sum_i p_i \log\frac{p_i}{q_i} \;\geq\; 0 $$ 读作"拿 q 当编码器去表示 p，平均每个符号要多付多少比特"。它不对称（$\mathrm{KL}(p\|q) \neq \mathrm{KL}(q\|p)$）， 两个分布完全相等时为 0。reborn 的蒸馏损失（α 混合，CE 是对硬标签的交叉熵）： $$ \mathcal{L} = \alpha \cdot \mathrm{CE}_{\text{硬}} + (1-\alpha)\cdot T^2 \cdot \mathrm{KL}\Big(\underbrace{\mathrm{softmax}(z_t / T)}_{\text{教师分布}}\;\Big\|\;\underbrace{\mathrm{softmax}(z_s / T)}_{\text{学生分布}}\Big) $$ 其中 $z_t, z_s$ 是教师/学生在同一位置的 logits（M03 起一直在用的"词表原始得分"，每词一个数）。 温度 $T$ 你在 M02 调过采样温度时已经见过同一公式：logits 除以 $T$ 再 softmax。M02 用它"读"生成分布的平陡； 这里在训练侧用同一招软化教学分布：$T$ 越大，softmax 越平，正确答案与"近似答案"的差距被压小、 相对结构被放大——暗知识从背景里浮出来，变得可学。

📐 严谨卡：KL 项为什么乘 $T^2$——梯度尺度补偿

温度不是免费软化。设 $p=\mathrm{softmax}(z_s/T)$、教师分布 $q$ 固定，对 $z_{s,i}$ 求导（softmax 的 Jacobian 自带一个 $1/T$）：$ \dfrac{\partial\, \mathrm{KL}(q\|p)}{\partial z_{s,i}} = \dfrac{1}{T}(p_i - q_i) $。 大 $T$ 时 $p, q$ 都被摊平，逐项差 $(p_i-q_i)$ 本身又缩小约 $1/T$——两个 $1/T$ 相乘， 软标签项的梯度被压成 $1/T^2$：不补偿的话，$T{=}1.5$ 时 KL 的"嗓门"只有名义的 44%， 温度越高蒸馏越失声。乘 $T^2$ 恰好补回，让软、硬两项对梯度的贡献与 $T$ 无关地保持 $\alpha$ 配比。 这是 Distilling the Knowledge in a Neural Network（Hinton et al., arXiv:1503.02531）的原始设定。 推导可跳过，记住结论：$T^2$ 不是超参，是温度带进来的尺度修正。

还有一个读源码前必须拆穿的陷阱：PyTorch 的 F.kl_div(input, target) 参数序容易记反—— 它算的是 $\mathrm{KL}(\text{target} \| \text{input})$。沿用上方严谨卡的记号（$p$=学生、$q$=教师）： reborn 写的是 F.kl_div(student_log_probs, teacher_probs)，即 input $=\log p$（学生）、target $=q$（教师），算出来是 $\sum_i q_i(\log q_i - \log p_i)=\mathrm{KL}(q\|p)=\mathrm{KL}(\text{教师} \| \text{学生})$。 这个方向正是 Hinton 的选择：最小化它时，学生必须覆盖教师的每个概率高峰，不许漏。 （loss.py 的 docstring 曾把这个方向写反成"KL(student‖teacher)"，2026-10-06 已修正——commit 40829a9，以代码为准的纪律没变，但现在代码与注释也一致了。）

精读：20 行损失 + 76 行 workflow

全部数学落在一个 20 行的函数文件里，先看全文：

src/minimind_reborn/training/distill/loss.py · 全文 20 行python
def distillation_loss(
    student_logits: torch.Tensor, teacher_logits: torch.Tensor, temperature: float = 1.0
) -> torch.Tensor:
    """softmax(T) 软化：KL(teacher‖student) × T²，batchmean 归约。

    F.kl_div(input, target) 实算 KL(target‖input)——此处 input=学生 log_softmax、
    target=教师 softmax，即 KL(教师‖学生)（前向 KL，与官方蒸馏语义一致）。
    """
    with torch.no_grad():
        teacher_probs = F.softmax(teacher_logits / temperature, dim=-1).detach()
    student_log_probs = F.log_softmax(student_logits / temperature, dim=-1)
    return (temperature**2) * F.kl_div(student_log_probs, teacher_probs, reduction="batchmean")

四个读点：① 教师进 no_grad——不建计算图（autograd 的反向记录，M08 的 detach 同款语义）， 教师只出题不学习；② 学生用 log_softmax（比先 softmax 再取 log 数值稳定，直接配 kl_div 的 input 口味）； ③ reduction="batchmean"——对所有 answer token 取平均，得到"每个回答 token 的平均 KL"； ④ $\times T^2$ 按位置补梯度尺度（上文严谨卡）。方向：teacher_probs 在 target 位——$\mathrm{KL}(\text{教师}\|\text{学生})$。

src/minimind_reborn/training/distill/workflow.py · compute_loss（45–62 行）python
def compute_loss(batch, m):
    labels = batch["labels"]
    out = m(batch["input_ids"], labels=labels)
    mask = (labels[..., 1:] != -100).float().view(-1)     # M12 的 loss mask 回收：-100 = 非回答区
    shift_labels = labels[..., 1:].contiguous().view(-1)  # 移位对齐：位置 t 预测 t+1（M09）
    logits = out.logits[..., :-1, :].contiguous()         # (B, T-1, V) 学生的移位 logits
    ce = torch.nn.functional.cross_entropy(
        logits.view(-1, logits.size(-1)), shift_labels, ignore_index=-100, reduction="none"
    )
    ce_mean = (ce * mask).sum() / (mask.sum() + 1e-8)     # 只对回答 token 平均
    with torch.no_grad():
        t_logits = teacher(batch["input_ids"]).logits[..., :-1, :][..., :vocab_student].contiguous()
        # 教师读同一段 input_ids，同样移位；词表超过学生时切片对齐
    flat_s = logits.view(-1, logits.size(-1))[mask == 1]  # (N_ans, V) 只挑回答行
    flat_t = t_logits.view(-1, t_logits.size(-1))[mask == 1]
    kl = distillation_loss(flat_s, flat_t, temperature=dc.temperature)
    loss = (dc.alpha * ce_mean + (1 - dc.alpha) * kl) + out.aux_loss  # aux 仅 MoE 非零（M08）
    return loss, {"train/ce": ce_mean.item(), "train/kl": kl.item(), "train/aux_loss": float(out.aux_loss)}

三个设计值得念出声。① 账本口径与 SFT 完全一致：M12 的 loss mask（labels 里非回答区是 -100） 在这里被复用了两次——CE 的 ignore_index 与 KL 的行选择（mask == 1）， 蒸馏也只教回答段：prompt 段人人都会读，不值得付学费。② 教师读的是 input_ids，不是答案： 它要给出的正是"面对这个问题你怎么想"的分布。③ 分项日志：返回的字典里 CE 与 KL 分开记账 （写进 metrics.jsonl），等下的实测靠它拆开看两项各自的动向。收尾看 64M 主配方：

🏭 工业对照：蒸馏是小模型产业的底座

Hinton 2015 论文里最有攻击力的一句话：软目标让蒸馏不需要标注数据——α 取 0， 教师对任意输入的分布就是全部教材。工业界因此形成"大模型产出、小模型继承"的流水线： DistilBERT 把 BERT 压到 60% 参数保 97% 效果；DistilWhisper、TinyLlama 皆是此路； DeepSeek-R1 的"蒸馏小模型"（拿 R1 产出的推理数据 SFT 小模型）就是你 M02 那条链的当代版本。 国内语境里"XX 小模型是 YY 大模型蒸馏的"是常规披露，不是贬义。

LoRA：只训 0.6% 的参数

直觉：微调的增量是低秩的

换一个省钱角度。全参 SFT/DPO 的账（M13/M16）：动 63.91M 参数，且 AdamW 优化器（M13）要给 每个可训练参数再背两份状态（动量与二阶矩），显存约 3 倍于参数本体。 LoRA（Low-Rank Adaptation，低秩适配）的出发点是一个经验观察：微调前后权重的变化量 $\Delta W$ 是低秩的（low-rank）——它只沿着少数几个方向改动，不需要一个满秩的 768×768 修正矩阵。 于是干脆不学 $\Delta W$ 本身，学它的低秩分解： $$ W' = W + \Delta W \approx W + B\cdot A, \qquad B \in \mathbb{R}^{768\times r},\; A \in \mathbb{R}^{r\times 768},\; r = 16 $$ 秩（rank）$r$ = 旁路里保留的独立方向数。一个 768×768 的投影有 589,824 个权重； LoRA 旁路只要 $16\times768 + 768\times16 = 24{,}576$ 个——4.2%，且 W 冻结不背优化器状态。

[作者实测 · 2026-10-01 · RTX 4090 · torch 2.14.0+cu130] 单矩阵账 24,576 / 589,824 = 4.2% 为算术；全模型口径的实测（只挂方阵，0.615%）见 实测一——两个比例不同，因为挂载点只有 16 个方形投影，不是全部权重矩阵。

💡 直觉：改书不重排印，贴批注条

全参微调是重排一版书；LoRA 是原版冻结、在页边贴批注条——书（基座）不变，新的意思全在批注（B·A）里。 换个任务就换一套批注，书还是那本书：这正是"一个基座 + 一抽屉适配器"的多任务形态。 批注条要有多少信息？r=16 说的是"这次修改只涉及 16 个独立方向"。

精读 lora.py：B(A(x))、A 高斯 B 零、方阵注入

src/minimind_reborn/models/lora.py · LoRA 类（22–34 行）python
class LoRA(nn.Module):
    """低秩旁路：B(A(x))，A 高斯初始化、B 零初始化。"""

    def __init__(self, in_features: int, out_features: int, rank: int):
        super().__init__()
        self.rank = rank
        self.A = nn.Linear(in_features, rank, bias=False)    # 768 → 16：降到 r 维"批注空间"
        self.B = nn.Linear(rank, out_features, bias=False)   # 16 → 768：升回原维
        self.A.weight.data.normal_(mean=0.0, std=0.02)       # A：小方差高斯，非零
        self.B.weight.data.zero_()                           # B：全零 → 初始 ΔW = B·A = 0

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.B(self.A(x))

初始化是 LoRA 最讲究的两行。$\Delta W = B\cdot A$——B 全零则 $\Delta W$ 全零， 训练起点与原基座逐位等价：LoRA 是"外挂"上去的，绝不允许第一步就破坏基座已学会的东西 （M16 的灾难性遗忘）。那 A 为什么不能也置零、图个对称？因为梯度会死锁： $\partial L/\partial B \propto A$、$\partial L/\partial A \propto B$——两个都为零， 两个梯度永远为零，旁路永远学不动。A 非零保证第一步 B 先收到梯度动起来，随后 A 也有梯度可收。 "B 零保起点、A 非零保流动性"，一对儿各管一头。

旁路怎么挂到模型上？apply_lora(model, rank) 扫描所有 Linear，只挂方阵（in==out）：

src/minimind_reborn/models/lora.py · apply_lora（37–52 行）python
def apply_lora(model: Any, rank: int = 16) -> None:
    """对方阵 Linear（in==out）注入 LoRA 并接管 forward。

    只挂方阵投影：默认 GQA 拓扑下 q/o_proj 是 768→768 方阵、可注入；k/v_proj 是
    768→384 非方阵、不注入——注意力四投影实际只有 q/o 两侧有旁路。
    """
    for module in model.modules():
        if isinstance(module, nn.Linear) and module.in_features == module.out_features:
            lora = LoRA(module.in_features, module.out_features, rank=rank).to(model.device)
            module.lora = lora  # 挂为子模块：参数自动进 state_dict、被 DDP 管理
            original_forward = module.forward

            def forward_with_lora(x, layer1=original_forward, layer2=lora):
                return layer1(x) + layer2(x)   # 输出 = 原投影 + 旁路：W·x + B(A(x))

            module.forward = forward_with_lora  # monkey-patch：替换该实例的 forward

这里的手法叫 monkey-patch（运行时替换对象的方法）：不改 attention.py 一行源码， 把命中条件的 Linear 的 forward 换成"原计算 + 旁路"。原 forward 用默认参数存进闭包 （layer1=original_forward）而不是外层变量——避免循环变量晚绑定把所有层指到同一个 forward。 哪些矩阵恰好是方阵？q_proj 输出维 = 头数 × head_dim = 8×96 = 768 = 输入维（M07 的形状约定）， o_proj 把拼接后的 768 投回 768——这两个天然方形。而 GQA 下 k/v_proj 是 768→384（KV 头只有 4 个）， 非方阵，挂不上；FFN 三个投影（768→2432 / 2432→768，M08）也不是方阵。实测挂载点（下一节）只有 q_proj 与 o_proj × 8 层 = 16 个——方阵判据是唯一事实。 一段勘误史（2026-10-06 已修正）：这个 docstring 原来写的是"即 q/k/v/o_proj 等"——举例按"无 GQA" 口径写，在默认 GQA 拓扑下并不成立（k/v 挂不上），恰好被本课实测抓个正着；修复周期改为如实写明 "q/o 可注入、k/v 非方阵不注入"（commit 40829a9）。读源码时，举例要拿判据复核——这一条保住了。

实测三：merge——推理时零额外延迟

旁路再小也是额外的矩阵乘。推理部署不想背它？merge_lora 把旁路算进主权重再存盘：

src/minimind_reborn/models/lora.py · merge_lora（76–88 行）python
def merge_lora(model: Any, lora_path: str | Path, save_path: str | Path) -> Path:
    """把 LoRA 合并进基模权重（W' = W + B·A）并保存为基模结构。"""
    load_lora(model, lora_path)
    merged: dict[str, torch.Tensor] = {}
    for name, module in model.named_modules():
        lora = getattr(module, "lora", None)
        if isinstance(module, nn.Linear) and lora is not None:
            delta = (lora.B.weight.data @ lora.A.weight.data).cpu().half()  # (768,16)@(16,768) → ΔW
            merged[f"{name}.weight"] = (module.weight.data.clone().cpu().half() + delta).half()
    base = {k: v.cpu().half() for k, v in model.state_dict().items() if ".lora." not in k}
    base.update(merged)     # 用 W' 覆盖同名键，剔除所有 .lora. 键
    return atomic_save(base, save_path)

数学上 $W'x = (W + B A)x = Wx + B(A(x))$——两种算法恒等。合并后存出的文件没有任何 .lora. 键：它就是一份普通基座权重，推理引擎根本不知道 LoRA 存在过，零额外延迟。 恒等性实测（把 B 随机化模拟"训过的适配器"，同输入比对三条路线的输出 logits）：

坑卡：静默失败的两张面孔

⚠️ 坑卡：merge 前忘了 apply_lora——不报错，存出来的还是基座
  • 症状安静得可怕：新建一个干净基座模型，直接 merge_lora(model, "lora.pth", "merged.pth")， 函数正常返回、文件正常落盘；加载 merged.pth 后行为与基座一模一样。作者实测： 合并版与"真值"输出 max|Δ|=1.0558——适配器根本没进去。
  • load_lora 只对 hasattr(module, "lora") 的挂点装权重——干净基座一个挂点都没有， 整个循环空转；后面的合并字典也是空的，base 原样写出。没有任何一步报错： 每个"没找到东西"的分支都被静默跳过了。
  • 合并前先 apply_lora(model, rank=…) 再 merge_lora（rank 必须与训练时一致， 形状对不上才会报错）；并且永远用一行输出验证——合并版与"基座+适配器"同输入比对 max|Δ| 应在 1e-3 量级（本课实测 0.0027），差到个位数就是没合上。
⚠️ 坑卡：双重 apply_lora——旧适配器被冻进闭包，训练照常、保存丢失
  • 对同一个模型调用两次 apply_lora（比如"保险起见再注入一次"）：不报错、loss 正常降。 但 state_dict 里只剩第二套（B=0 的新适配器），第一套训练成果存不下来； 而它仍通过闭包参与前向——输出却和注入前一模一样（实测第二次注入后 max|Δ|=0.000000）。
  • 第二次注入把 module.lora 指向新对象（旧参数脱离注册、不再被优化器和保存钩子看见）， 但新 forward_with_lora 捕获的 original_forward 是已被 patch 过的旧 forward—— 旧旁路被永久冻结在闭包里：不训练、不保存、却一直参与计算。
  • 一个模型只 apply 一次；注入前自查 any(hasattr(m, "lora") for m in model.modules())。 相关红线：lora.py 模块 docstring 明示 monkey-patch 与 torch.compile 不兼容 （官方已知）。作者实测 torch 2.14 上小模型能跑通编译与反传，但 dynamo 对被 patch 的 forward 报 graph break、编译优化承诺失效——所以 reborn 的 train.compile 默认 False， LoRA 配方也从不开它。想提速请用 bf16（M13 的 AMP），别对 LoRA 开 compile。

检验一下

测验 1 · 软标签比硬标签多了什么信息？为什么同一批数据软标签"更稠密"？

答案：多的是暗知识——错误答案之间的相对结构与相似度排序。硬标签 one-hot 里 6399 个错误答案全是 0（"差得远"和"差一点"被压成同一种 0）；软标签给每个位置一个完整分布，"B 比 D 更像对的"这类信息整份保留。每个位置的监督信号从 1 个编号变成 6400 个带权重的分数，所以说更稠密。M02 的 SFT 语料是 Qwen 蒸馏后采样成文本的——暗知识在采样时被丢掉，只剩硬标签；distill 范式把分布直接对齐，才算把蒸馏做完整。

答错回看：硬标签 vs 软标签：暗知识。

测验 2 · KL 项为什么要乘 T²？不乘会发生什么？

答案：梯度尺度补偿。温度把 logits 除以 T：softmax 的 Jacobian 自带一个 1/T，而大 T 下教师/学生分布都被摊平、逐项差又缩小约 1/T——两个 1/T 相乘，软标签项的梯度只剩 1/T²。不补偿时 T=1.5 下 KL 的"嗓门"只有名义的 44%，α=0.5 名义配比实际失效：温度越高蒸馏越失声。乘 T² 恰好补回，使软硬两项对梯度的贡献与 T 无关地维持 α 配比。这是 Hinton 2015 论文的原始设定，不是可调超参。

答错回看：数学：KL 散度与温度 的严谨卡。

测验 3 · LoRA 的 B 为什么零初始化？A 为什么不能也是零？GQA 下哪些投影挂不上？

答案：ΔW = B·A，B 全零 ⇒ ΔW 全零 ⇒ 训练起点与基座逐位等价——外挂的第一原则是不破坏基座已会的东西。A 若也为零则梯度死锁：∂L/∂B ∝ A、∂L/∂A ∝ B，两个都为零则两个梯度恒为零，旁路永远学不动。A 非零保证第一步 B 先动，随后 A 也有梯度。挂载判据是"方形 Linear（in==out）"：q_proj（8×96=768→768）与 o_proj（768→768）中选；GQA（M07）下 k/v_proj 是 768→384 非方阵、FFN 三投影也不是方形——实测挂载点恰为 q/o × 8 层 = 16 个。docstring 原按"无 GQA"口径举例 q/k/v/o，2026-10-06 已修正为如实写明 q/o 可注入、k/v 非方阵不注入。

答错回看：精读 lora.py。

测验 4 · LoRA 为什么推理零额外延迟？merge 前后输出差多少量级、差在哪？

答案：merge 把 W'=W+B·A 写回主权重：数学恒等 (W+BA)x = Wx + B(A(x))，合并后模型结构与基座完全相同（state_dict 里没有任何 .lora. 键），推理引擎只做一个普通矩阵乘——旁路"从未存在过"。实测残差 max|Δ|≈0.0027，是 fp16 舍入级：适配器存档 .half() 与合并加法都在半精度里做。顺带：merge 后再 apply_lora 是在合并版上开新适配器（新 B=0，输出与合并版逐位一致）——正确的叠层姿势。

答错回看：实测三：merge。

    n = sum(p.numel() for nm, p in m.named_parameters() if 'lora' in nm)
    print(f'rank={r:>2}: LoRA {n:,} | 占 64M 基座 {100*n/63_912_192:.3f}%')"
rank= 4: LoRA 98,304 | 占 64M 基座 0.154%
rank=64: LoRA 1,572,864 | 占 64M 基座 2.461%
观察结果与解释（先动手再看）

机制：每个挂点参数 = A 的 r×768 + B 的 768×r = 2·r·768，线性于 r—— rank=4 是 16 的 1/4（98,304 = 393,216÷4），rank=64 是 4 倍（1,572,864）。 门槛：rank=4 的 0.154% 更省，rank=64 的 2.461% 已失守 1%——但注意"失守"只是丢了招牌说法， 换来的是旁路能表达的独立方向从 4 个涨到 64 个：任务与基座差异越大（如换语言/换领域）， 需要的秩越高；风格类小改动 rank=4~8 往往就够。极限情形 r=768 时 B·A 是 768×768 的满秩乘积， LoRA 在表达能力上逼近全参微调（仍是不同的参数化：冻结 W、只优化低秩因子，优化器状态依旧省）。 这就是 rank 的真实语义：你愿意给"这次修改"几个自由方向。

本课词汇

知识蒸馏 knowledge distillation
用教师模型的输出训练学生模型。软标签版直接对齐教师的完整概率分布（KL 项），保留暗知识；M02 的 SFT 语料（Qwen 生成）是其"采样成文本"的硬标签版。α=0 时不需要标注数据。
软标签 / 硬标签 soft / hard label
硬标签 = one-hot 编号（只有一个 1）；软标签 = 完整概率分布。软标签多出的信息是错误答案之间的相对结构，每个位置的监督信号从 1 个数变成整个词表的 6400 个。
暗知识 dark knowledge
Hinton 术语：教师分布里"哪些错误答案也像样、彼此差多少"的结构。硬标签把它压成 0；温度软化把它放大到可学习的量级。
KL 散度 Kullback–Leibler divergence
KL(p‖q)=Σ p·log(p/q)≥0，两个分布相等时为 0；不对称。PyTorch 的 F.kl_div(input=log Q, target=P) 算的是 KL(P‖Q)——reborn 实际优化 KL(教师‖学生)，学生须覆盖教师每个高峰。
温度（蒸馏语境）temperature
与 M02 采样温度同一公式（logits/T 再 softmax），训练侧用来软化教学分布：T 大分布更平、类间结构暴露更多。配套 T² 系数补偿梯度尺度，见本课严谨卡。
LoRA low-rank adaptation
冻结基座，给方形 Linear 挂旁路 B(A(x))，ΔW≈B·A 低秩分解。reborn 只挂 in==out 的投影（GQA 下 q/o_proj，16 个挂点）；rank=16 时 393,216 参数 = 0.615%。merge 可写回主权重，推理零额外延迟。
秩 rank
旁路保留的独立方向数 r。参数量随 r 线性（每挂点 2·r·768）；r 越大能学的改动越复杂，r=hidden 时逼近全参的表达能力。"这次修改需要几个自由方向"的预算旋钮。
适配器 adapter
插在基座上、可单独保存分发的小型可训练模块。LoRA 适配器经 save_weights_fn 钩子单独落盘（12 KB 级），配一句基座名即可复现；一基座多适配器是多任务标准形态。
monkey-patch
运行时替换对象方法：apply_lora 把命中方阵判据的 Linear 的 forward 换成"原计算+旁路"，不改源码一行。代价：与 torch.compile 不兼容（官方已知），LoRA 配方保持 compile 关闭。
merge 权重合并
W'=W+B·A 写回主权重并剔除所有 .lora. 键：输出与"基座+旁路"恒等（fp16 舍入级，实测 max|Δ|≈0.003），推理结构与基座完全相同。坑：merge 前没 apply_lora 会静默存出纯基座。
